# 친구에게 단어장 보내기 — 스펙

목업(화면 전부): https://claude.ai/code/artifact/c1520dea-6bb5-44f6-947d-3d89a8b36a85

내 단어장을 **한 사람에게 주소로 건네는** 길을 만든다. 지금 «공유»는 모두에게 게시하는 것 하나뿐이라,
스터디원·친구·학생에게 단어장을 주는 방법이 없다.

---

## 1. 왜 (실측, 2026-09-11 프로덕션)

| 항목 | 값 |
|---|---|
| 공유 단어장 탭에 올라온 것 | **2개** (같은 사람 1명, 마지막 2026-07-26) |
| 그 2건 | 제목이 개인 메모(`소하윤하`, `소하윤하01`), 설명 없음 |
| 공급 후보 | 로그인 계정 148 · 단어장 보유 95명 · 10단어 넘는 단어장 **280개(71명)** |
| 단어장 크기 | 단어가 든 것 320개 · 500 초과 27개(8.4%) · 1,000 초과 6개(1.9%) · **2,000 초과 0개** · 최대 **1,730** |
| DB | 총 167MB / 무료 한도 500MB · `cloud_words` 56,170행(37MB) · 단어 1행 평균 **449바이트** |

71명이 쓸 만한 단어장을 갖고 있는데 게시는 1명뿐이다. 148명 규모에서 «공개 게시판»은 원리적으로 돌지
않는다(Memrise는 8년 운영한 커뮤니티 코스를 2024-03-31 앱에서 제거했다). 반면 **한 사람에게 주는 길은
규모와 무관하게 성립**하고, 주소가 앱 밖에서 돌면 그게 곧 유입이다.

경쟁 앱은 대부분 이 길을 갖고 있다 — 원보카(공개 라이브러리 + 친구·팀·선생님 비공개 공유), Quizlet·Knowt
(공개로 바꾸면 링크 공유), Brainscape(클래스 초대 링크). Anki만 «파일(.apkg)»이고, 그래서 «내가 공유한 덱을
어떻게 지우나»가 포럼에 반복된다.

**범위 밖:** 공유 단어장 탭 자체를 어떻게 할지(승격·통합·방치)는 이 문서에서 다루지 않는다.

## 2. 정해진 것

1. **메뉴에서 둘을 가른다.** «📤 친구에게 보내기»(신설)와 «🌏 공유 단어장에 올리기»(지금 «단어장 공유하기»의
   이름을 바로잡은 것). 결과가 다르면 항목도 달라야 한다 — 수명까지 다르다.
2. **보낼 것을 매번 한 번 보여주고, 그다음 OS 공유 창.** 받는 사람이 보게 될 카드를 그대로 띄우고, 고칠 수 있는
   것은 **이름 하나**다. [보내기]를 누르면 CSV 내보내기가 이미 쓰는 네이티브 공유 시트가 열린다.
   «첫 공유 때만 묻기»는 하지 않는다 — 이번엔 왜 안 묻는지 알 수 없고, 공유는 서버에 사본이 올라가는
   되돌리기 어려운 동작이라 매번 한 번은 보이는 편이 맞다.
3. **30일 뒤 스스로 끝난다.** 담으면 주소는 쓸모없어지니 «전송»으로 다룬다. 공유 단어장에 올린 것은 «게시»라
   만료가 없다.
4. **보낸 내용은 그대로 굳는다.** 갱신 버튼도, 담아 간 사람에게 가는 알림도 없다. 다시 보내면 새 주소가 나온다.
5. **앱에 상태를 남기지 않는다.** 배지도, 상태 줄도, «주소 다시 복사»도 없다. 메뉴는 보냈든 안 보냈든 똑같고,
   또 보내려면 «친구에게 보내기»를 다시 누르면 **그때 내용으로 새 주소**가 나간다. 각 주소는 자기 30일을 산다.
   보낸 기록은 카톡 대화에 남는다 — 앱이 들고 있을 이유가 없다.
   (배지 자리는 하나뿐이고 이미 학습 중·AI 생성·담아온 것 셋이 쓴다 — `components/ListCard.tsx:61`)
6. **열림·담김 수는 서버에만 쌓고 화면에 띄우지 않는다.** 한 사람에게 보내면 0 아니면 1이라 볼 것이 없고,
   보이면 «왜 안 담았지»가 생긴다. 우리가 판정할 근거로만 쓴다.
7. **거두는 길은 두지 않는다.** «지금 끝내기» 버튼도, 단어장 삭제와의 연동도 없다 — 끝내는 일은 30일이 한다.
   잘못 보냈을 때 드러나는 건 단어장 제목·보내는 이름·단어뿐이라 피해가 작고, 풀 길은 사람 사이에 있다
   (메시지를 지우거나 «잘못 보냈어요» 한마디). 계정을 지우면 공유본도 함께 지워진다(`creator_id` → `auth.users` cascade).
   *(2026-09-11: 처음엔 «단어장 삭제 = 급히 거두는 길»로 정했다가 이 이유로 거뒀다 — §5.6·§6.3.)*
8. **받는 사람은 로그인 없이 담는다.** 담기는 로컬 SQLite에 들어가는 일이라 계정이 필요 없다.
9. **한 번에 2,000단어까지.** 실측 최대가 1,730이라 **지금 있는 단어장 전부가 한 번에** 나가고, 나눠 보내기 화면이
   아예 없다. 나눠 보내면 주소가 둘이 되어 받는 쪽이 두 번 담고 단어장이 쪼개진다 — 빠뜨림을 막으려던 선택이
   받는 쪽에서 빠뜨림을 만든다. 2,000을 넘는 경우가 생기면 «앞 2,000단어만 보내기»로 받는다.
10. **보내는 이름은 그 시트에서 고친다.** 기본값은 프로필 닉네임이지만, 고친 값은 **«보내는 이름»으로 따로
   기억한다** — `profileSettings.nickname`은 **홈 화면 인사말에도 쓰이므로**(`app/(tabs)/index.tsx:96`)
   공유에서 고친 이름이 홈 인사말을 바꾸면 놀라움이 된다.
11. **뜻 언어가 다르면 알리고 맡긴다.** 막지 않는다.
12. **웹 미리보기는 앞 10단어** + «외 N단어».
13. **주소는 UUID 그대로.** 짧은 코드는 발급 테이블이 따로 붙으므로 하지 않는다.
14. **«링크»라는 말은 화면에서 쓰지 않는다.** 주소를 실제로 보여주는 자리에만 등장한다.

## 3. 사용자 흐름

```
 ①  내 단어장 «⋯» → 📤 친구에게 보내기
        ▼
 ②  «받는 사람에게 이렇게 보여요» — 카드 미리보기 + 보내는 이름 [수정] + [보내기]
        ▼
 ③  서버에 사본 저장 → OS 공유 창
        메시지: 아보카도 «토익 빈출 300» 단어장
                300단어 · 10월 11일까지 열 수 있어요
                https://eunjbaek12.github.io/NewSokSok/d/?id=<uuid>
        ▼
 ④  받는 사람이 주소를 누른다
        앱 있음 → 담기 화면 (로그인 안 물음)
        앱 없음 → 웹 미리보기(앞 10단어) → [앱에서 담기] / [설치하기]
        ▼
 ⑤  담기 = 복사. 그 뒤로 원본과 무관.
        이미 담았으면 «8월 12일에 이미 담았어요» + [내 단어장 열기] / [그래도 새로 담기]
        뜻 언어가 다르면 «이 단어장의 뜻은 한국어예요» + [그래도 담기]
        ▼
 ⑥  30일 뒤 자동 종료. 주소를 누르면 «단어장을 열 수 없어요».
        보낸 쪽은 할 일이 없다 — 애초에 메뉴가 변한 적이 없다.
```

## 4. 데이터 모델

### 4.1 서버 (`curated_themes`)

| 컬럼 | 형 | 설명 |
|---|---|---|
| `visibility` | `text` | `'public'`(공유 단어장 목록) \| `'link'`(주소로만). 기본 `'public'` — 기존 2건은 그대로 |
| `expires_at` | `bigint` NULL | epoch ms. `'link'`은 생성 시각 + 30일, `'public'`은 `null` |
| `source_list_id` | `text` NULL | 이 공유물이 나온 내 단어장 id. 한 단어장에서 여러 번 보냈으면 그만큼 붙는다. **측정용으로만 남긴다** — 삭제 연동(§5.6)은 하지 않기로 했다 |
| `open_count` | `int` default 0 | 주소가 열린 횟수(웹+앱). **화면에는 띄우지 않는다** |
| `save_count` | `int` default 0 | 담긴 횟수. 같이 서버 전용 |

> `created_at`/`updated_at`이 이미 bigint epoch ms다. `expires_at`도 같은 규약으로 맞춘다.
>
> **`curated_words.position int`도 넣었다**(구현 중 실측으로 발견). 서버에는 단어 순서가 아예 없었다 — 한 배치
> insert라 `created_at`이 전 행 동일하다(100단어 덱의 distinct = 1). 지금까지는 PostgREST의 물리적 순서에 기대 왔고,
> 청크 insert(§6)를 넣는 순간 경계에서 뒤섞인다.
>
> **열림·담김 수가 `updated_at`을 움직이지 않는다.** 그 트리거 함수(`set_updated_at_ms`)는 동기화 5개 테이블
> 공용이라 손대지 않고, `curated_themes`에만 `set_updated_at_ms_skip_counters()`를 따로 걸었다 — §2-4의
> «그대로 굳는다»가 시각에도 적용된다.

### 4.2 서버 (신설 `share_events`) — 만료 후에도 남는 요약

만료 행을 지우면 **열림·담김 수가 함께 사라져 누적 측정이 불가능해진다.** 지우기 전에 요약 한 줄만 남긴다.
**단어 내용은 남기지 않는다.**

```
share_events(id uuid, creator_id uuid, word_count int, visibility text,
             created_at bigint, ended_at bigint, open_count int, save_count int)
```

### 4.3 로컬 (`lists`, SQLite 마이그레이션 +1)

| 컬럼 | 설명 |
|---|---|
| `sourceThemeId` | 이 사본이 어느 공유물에서 왔는지. 제목 접두사 매칭을 대체한다 |
| `savedAt` | 담은 시각. «8월 12일에 이미 담았어요» |

두 값은 **비어 있을 수 있다**(이전에 담은 단어장). 값이 없으면 날짜 없이 «이미 담았어요»로 표시한다.

🔴 **두 값은 로컬 전용이라 동기화 pull의 `INSERT OR REPLACE INTO lists`가 지운다**(REPLACE는 행을 통째로
갈아끼운다 — 굴절형 원형이 별표 한 번에 사라진 `b92e763`과 같은 부류). pull은 옛 행에서 서브쿼리로 되읽어
보존한다. `__tests__/sync-pull-list-columns.test.ts`가 lists 스키마 전체를 pull 컬럼 목록과 맞대 본다.

## 5. 서버 작업

### 5.1 인덱스 — 가장 먼저

`curated_words`의 인덱스는 PK(`id`) 하나뿐이다. 용량 트리거가 행마다 `count(*) where theme_id = …`를 돌리므로
**매 행 삽입이 전체 스캔**이다. 지금은 125행이라 티가 안 나지만 2,000행을 넣으면 count를 2,000번 하고, 테이블이
커질수록 제곱으로 는다.

```sql
create index if not exists curated_words_theme_id_idx on public.curated_words(theme_id);
```

### 5.2 상한 2,000

`check_curation_word_count()`의 `>= 500`을 `>= 2000`으로. 앱의 `MAX_WORDS_PER_CURATION`도 함께(§6).

### 5.3 SELECT 정책 교체 — **이게 없으면 A안이 성립하지 않는다**

지금 `themes_select_all`의 조건은 `qual = true`다. 익명 키만 있으면 전 테이블을 읽는다. 그래서 컬럼만 추가하면
① 친구에게 보낸 단어장이 **목록째 덤프**되고(주소가 UUID인 것과 무관), ② **구버전 앱이 `select *`로 다 긁어**
공유 단어장 탭에 띄운다(스토어 앱은 업데이트가 늦다 — 쿼터 정책 때 값을 치렀다).

```sql
drop policy if exists "themes_select_all" on public.curated_themes;
create policy "themes_select_public" on public.curated_themes for select
  using (visibility = 'public' or creator_id = auth.uid());
-- curated_words 도 부모 기준으로 같게 좁힌다(words_select_all 교체)
```

### 5.4 주소로만 여는 RPC

목록 조회로는 못 보고, **id를 아는 사람만** 열 수 있게 한다.

```sql
create or replace function public.get_shared_deck(p_id text)
returns jsonb language plpgsql security definer set search_path = public as $$
  -- visibility 무관, 단 expires_at 이 지났으면 null
  -- 반환: 테마 메타 + 단어 배열, open_count += 1
$$;
```

- 익명(게스트) 호출 허용. 게스트도 `signInAnonymously`로 `authenticated` 역할을 갖는다.
- 미리보기용은 앞 10단어만 돌려주는 인자(`p_preview boolean`)를 둔다 — 웹 랜딩이 500단어를 통째로 받지 않게.
- 담을 때 `save_count += 1`은 별도 RPC(`bump_share_save`).

### 5.5 만료 정리

1. 조회에서 거른다(§5.4).
2. 주기적으로 지운다(pg_cron 또는 Edge cron, 하루 1회). **지우기 전에 `share_events`에 요약을 남긴다.**
3. 50개 한도(`check_user_curation_count`)를 셀 때 **만료된 것은 빼야 한다.** 안 그러면 몇 달 뒤 «더 공유할 수
   없어요»에 막히는데 정작 살아 있는 공유는 하나도 없는 상태가 된다.

### 5.6 ~~단어장 삭제 → 공유본 동반 삭제~~ — 안 함 (2026-09-11)

처음엔 «급히 거두는 유일한 길»로 계획했다. 하지 않기로 한 이유는 §2-7 — 잘못 보내도 드러나는 게 단어장뿐이고,
30일이면 스스로 닫히며, 풀 길은 사람 사이에 있다. 이게 빠지면 삭제 확인 문구(§6.3)도 띄울 말이 없어 함께 빠진다.

> 따라서 **단어장을 지워도 보낸 사본은 만료까지 남는다.** 공유 단어장에 «올린» 것(만료 없음)은 공유 탭에서
> 작성자가 직접 지울 수 있다(`deleteCloudCuration`).

| `docs/` (GitHub Pages) | 랜딩 `docs/d/index.html`(주소는 `/d/?id=<uuid>` — 정적 호스팅은 `/d/<uuid>` 같은 임의 경로를 200으로 못 받는다) — 제목·단어 수·앞 10단어·[앱에서 담기]/[설치하기]. 공개 키(publishable)는 `docs/d/config.js`에만 두고, 없으면 미리보기 없이 버튼만 보인다. 개인정보처리방침이 이미 여기 있어 호스팅 비용 0. 설치 후 «다시 눌러 주세요» 같은 안내는 **넣지 않는다** |

### 6.1 걷어낼 것

- **제목 중복 검사.** `shareCuration`이 같은 제목을 `ilike`로 찾아 `DuplicateCurationError`를 던지고 «이미
  공유되어 있습니다, 갱신할까요?»를 묻는다. 만료 모델에서는 **다시 보내는 게 정상 흐름**이라 이 물음이 방해가
  된다. 관련 UI(`ListContextMenu`의 alreadyShared 분기)도 함께.
- 게스트에게 조건 없이 보이는 공유 항목 → 로그인 안내로. 지금은 제출까지 갔다가 **`GUEST_CANNOT_SHARE`가
  영문 코드 그대로** 알림에 뜬다(`ListContextMenu.tsx:330`, CLAUDE.md의 «게스트는 버튼이 비활성»은 사실과 다르다).

### 6.3 ~~단어장 삭제 확인 — 보낸 것이 있을 때만~~ — 안 함 (2026-09-11)

«친구에게 보낸 주소 N개도 함께 열리지 않게 됩니다»는 삭제 연동(§5.6)이 있어야 참이 되는 문장이다. §5.6을
