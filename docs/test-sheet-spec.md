# 시험지 — 스펙

작성·결정 2026-09-17. 상태: **구현 완료 · 실기 중.** 실릴 버전: **1.8.0**(친구 공유와 함께).

목업: <https://claude.ai/artifact/EfDTkYFBtD1WUiuG8Hj2fY> — 화면·문구는 목업이 앞선다.
다시 풀기 기록(§3.1): <https://claude.ai/artifact/VXyToR1ajgjNhu3MnYRGgt> — «다» 화면.

왼쪽에 뜻(또는 단어), 오른쪽 빈칸에 직접 적고, 한 세트를 다 풀면 한꺼번에 채점하는 학습 방식.
«단어 목록 위에 종이를 덮고 푼 다음 채점하는 것»(은정님 제안)을 앱으로 옮긴다.

## 0. 왜

2026-09-16, 한국 경쟁 앱 6개(원보카·모카·VoCat·암기고래·클래스카드·말해보카)의 앱스토어 리뷰
4,452개를 기능별로 셌다. **철자 쓰기·받아쓰기가 언급 211 · 요청 127**로 학습 방식 중 가장 많이
요청됐고, 가장 흔한 이유가 **«학원에서 매주 단어 시험을 본다»**였다. 원보카·VoCat·모카·클래스카드·
말해보카가 이미 갖고 있다.

지금 아보카도의 학습 방식 넷(카드·퀴즈·예문·자동재생)은 **전부 보고 고르거나 넘기는 방식**이다.
스스로 떠올려 적는 방식이 하나도 없다.

원래 «퀴즈에 철자 쓰기 옵션»으로 넣으려던 것을 **이 방식이 대신한다**.

**AI는 쓰지 않는다.** 채점은 글자 비교와 스스로 ○·✕로 끝난다 → AI 한도 차감 0, 오프라인·게스트에서도 된다.
AI가 «단어→뜻»을 매기게 하는 안은 기각했다 — 같은 뜻 판정을 다시 물으면 절반 가까이 뒤집힌 전례가 있고,
«AI가 채워 준 단어만 차감»이라는 요금 규칙과도 맞지 않는다.

#### 1.1 세트 크기를 따로 두는 이유 (D6)

«학습 단위»(`studyBatchSize`)는 **처음 값이 `'all'`**(`shared/contracts.ts:67`)이고 카드·퀴즈·예문·
자동재생이 **한 값을 같이 쓴다.** 그대로 쓰면 단어 100개짜리 단어장이 **100줄짜리 시험지 한 세트**로 열린다.
카드·퀴즈는 한 문제씩 넘기니 «전체»여도 괜찮지만, 시험지는 다 풀어야 채점되므로 세트 크기가 곧
«채점 전까지 한 번에 풀 양»이다. 대가: 퀴즈에서 바꾼 학습 단위가 시험지에 따라오지 않는다.

### 흐름 — 100단어, 세트 크기 10

| 순서 | 화면 | 채점 범위 |
|---|---|---|
| 1 | 세트 1(1~10번) 풀기 → [채점하기] | 이 10문제만 |
| 2 | «틀린 3개만 다시 풀기»(선택) | 세트 1에서 틀린 것만 — 맞히면 외운 단어로 기록(§3) |
| 3 | [다음 세트] → 세트 2(11~20번) … 세트 10 | 세트마다 따로 |
| 4 | 세트 10 채점 → [결과 보기] | |
| 5 | 결과 화면 | 100개 전체 합산 + 전체 답안지(D16) |

진행 줄 표시는 «1 / 10세트». 세트 크기 «전체»면 한 세트(«1 / 1세트»)로 끝에 한 번 채점.

## 2. 채점 규칙

### 뜻 → 단어 (앱이 매김)

- **봐주는 것**: 대소문자 · 앞뒤 빈칸 · 단어 사이 두 칸 이상 빈칸
- **틀림**: 한 글자라도 다른 철자 · 뜻이 같은 다른 단어(«충분한»에 enough) · 복수형·과거형 등 다른 꼴 ·
  일본어·중국어를 히라가나·병음으로 적은 것
- 앱이 틀림으로 매긴 줄은 **«맞게 썼어요»**로 ○로 바꿀 수 있다 → 규칙은 엄격하게 둔다
- 빈칸은 매기지 않고 정답을 보여 준다 → 직접 ○·✕

### 단어 → 뜻 (사람이 매김)

- 적은 뜻과 정답 뜻을 나란히 보여 주고 직접 ○·✕
- 적은 뜻이 **정답 뜻의 한 조각과 글자까지 같으면 ○를 미리 찍는다**(누르면 바뀜).
  조각 = `meaningKr`을 쉼표 · ①②③ 표시로 나눈 것. «곧, 얼마 안 있어»에 «곧» → ○

## 3. 기록 규칙

| 상황 | 기록 |
|---|---|
| 채점된 줄 ○ | 퀴즈와 같다 — «외웠어요», 복습 간격 갱신 |
| 채점된 줄 ✕ | 퀴즈와 같다 — 오답 +1 |
| «틀린 N개만 다시 풀기»에서 ○ | **«외웠어요» + 오답 +1.** 복습 간격은 **첫 칸(3일)부터** — 원래 외운 단어였어도 |
| «틀린 N개만 다시 풀기»에서 ✕ · 안 누름 | 처음 채점대로 — 틀린 단어, 오답 +1. 여러 번 다시 풀어도 오답은 **한 번만** 오른다 |
| 결과 화면 «못 외운 단어만 학습» | 새 학습으로 기록 (지금 퀴즈와 같음) — 시험지로 다시 열린다 |
| 중간에 뒤로 가기 | **채점한 세트까지** 기록(다시 풀어 맞힌 줄 포함). 채점 전인 세트는 기록 안 함 |

### 3.1 다시 풀어 맞힌 것을 «외웠어요»로 남기는 이유 (2026-09-17 변경)

처음 규칙은 «다시 풀기는 기록 안 함»이었다 — 방금 정답을 보고 맞힌 것을 «외웠어요»로 치면 부풀려진다는 이유.
은정님이 실기에서 다시 풀어 다 맞히고 «결국 학습 결과에는 반영이 안 된다는 게 아쉽다», 화면에만 표시하는 안(«나»)에는
«결국 맞췄는데 헷갈리지 않아?»(✕ 옆에 «맞힘»). 세 안(가 지금 그대로 · 나 화면에만 · 다 기록까지)을 그려 **«다»로 정했다.**

- **부풀려진다는 걱정은 복습이 받아 준다.** 3·10·30일… 간격으로 돌아오는 복습(`isWordDue`)은 **외운 단어만** 대상이다.
  틀린 단어로 남기면 복습에 **안 나오고**, 외운 단어로 남기면 **3일 뒤 복습에서 한 번 더 확인**되고 그때 틀리면
  미암기로 돌아간다. 카드 학습의 «외웠어요»가 이미 이 방식이다.
  🔴 처음에 «틀린 단어는 곧 복습에 다시 나온다»고 설명해 «나»를 추천했는데 틀린 설명이었다 — 기록 규칙을 말하기 전에
  `isWordDue` · `partitionSessionResults` 를 읽을 것.
- **오답 +1은 남긴다.** 한 번 틀렸던 흔적 — 홈 «오답 정복»에 계속 보인다. 다른 학습 방식은 맞히면 오답 수를 0으로
  되돌리는데, «다시 풀어 맞힘»은 처음에 틀린 것이라 예외다.
- **복습 간격은 첫 칸부터.** 원래 외운 단어(예: 30일 칸)를 처음에 틀렸다면 한 번 잊었던 것이다. 카드에서 «다시 볼게요»로
  미암기가 됐다가 다시 외운 것과 끝 상태를 같게 둔다(첫 칸 = 3일).

  (`features/settings/store.ts` `persisted(...)`)
- **기록**: `useSessionCommit` / `commitSessionResults` 그대로. 다시 풀기의 ○는 처음 채점 기록(`records`)의 그 줄에
  `retriedOk`로 남기고, `StudyResult.lapsed`로 넘긴다 — `partitionSessionResults`가 «외웠어요 + 오답 +1 + 사다리 첫 칸»으로 나눈다
  (보통의 ○는 오답 수를 0으로 되돌리고 사다리를 올리므로 따로 표시가 필요하다)
- **결과 화면**: `app/study-results.tsx`에 시험지일 때만 답안지 분기. `StudyResult`에는 **적은 답이 없다** → 적은 답·채점 방식(자동/직접/«맞게 썼어요»)·세트 번호를 따로 넘겨야 한다. 긴 목록이라 `FlatList` + 전환 줄 고정 헤더. 완주 축하·마일스톤 창은 지금처럼 이 화면 위에 뜬다
- **입력칸**: `autoCorrect={false}` · `spellCheck={false}` · `autoComplete="off"` · `autoCapitalize="none"` ·
  `returnKeyType` next/done · `blurOnSubmit={false}`. 안드로이드 추천 줄은 이것만으로 안 꺼질 수 있다(§5)
