# 기존 큐레이션 덱 로마자·예문 정리

**✅ 끝났다 (2026-08-02).** 한국어 출발 덱 19개 4,237단어에서 확실한 문제 **0건**.
아래는 무엇을 어떻게 판단했는지의 기록이다 — 새 덱을 만들 때 같은 기준을 쓰면 된다.

```bash
pnpm run diagnose:decks                 # 한국어 출발 덱 전체
pnpm run diagnose:decks --deck=ko-basic # 덱 하나만
pnpm test __tests__/romanize.test.ts    # 변환기 회귀 테스트
```

`⚠️`가 확실한 문제, `📋`는 오탐일 수 있어 사람이 판단할 항목이다. 남아 있는 `📋`
(예문에 표제어 없음·뜻에 표제어 포함)은 전부 확인 후 정상으로 판정한 것들이다 —
용언 활용(맵다 → 매워요)이나 학습 정보("짜다 also means to squeeze")라서 걸린다.

## 무엇을 고쳤나

| 유형 | 건수 | 비고 |
|---|---|---|
| 로마자 | 152 | ko→en 106 + vi/ja/zh 46 |
| 당신 | 2 | Basic·Intermediate, 4개 언어판까지 5장 |
| 예문 중복 | 3 | 4개 언어판까지 |
| 번역 미완성 | 2 | ko→ja 문장에 한국어가 남아 있었다 |

### 🔴 검사 범위가 절반을 가리고 있었다

처음 센 111건은 **ko→en 덱만**이었다. `Basic Korean 500`은 vi/ja/zh 판이 따로 있고
로마자를 각각 생성해 둬서, 같은 오류가 3벌 더 있었다(+33건). `Gen-Z Slang`의 베트남어
판은 아예 **다른 오류 세트**를 갖고 있었다(+13건, 소오름 soooreum·개꿀 gaekkulk 등).

그래서 `diagnose-ko-decks.ts`의 대상을 `targetLanguage === 'en'` 조건 없이 **한국어가
출발어인 덱 전체**로 넓혔다. 로마자·'당신'·예문 중복은 도착어와 무관한 검사다.
넓히자마자 ko→ja 덱의 번역 미완성 2건이 새로 잡혔다 — 사용자에게 그대로 보이던 오류다.

**새 언어판을 추가하면 로마자는 복제가 아니라 재생성된다는 걸 전제로 볼 것.**

## 판단 기준 (유형별)

**A. 순수 오타** — 그냥 고친다. `대제학` daejehagi → daejehak, `현감` hyeogam → hyeongam,
`케바케` kebabke → kebake, `자전거` jajeongeoji → jajeongeo.

**B. 음운 변화 미반영** — 변환기 결과가 맞다. 개정 로마자는 표기가 아니라 **표준 발음**을 적는다.
비음화 `학년` → hangnyeon, `막내` → mangnae · 유음화 `관리` → gwalli, `만렙` → mallep ·
연음 `과몰입` → gwamorip · 격음화 `좋다` → jota.

**C. 된소리되기를 적어 버린 것** — 개정 로마자는 **된소리되기를 표기하지 않는다**.
`활동` hwalttong → hwaldong · `앉다` antta → anda · `맡다` matta → matda · `갓생` gatssaeng → gatsaeng.
(ㄲ·ㅆ·ㅉ 같은 된소리 **글자 자체**는 적는다 — 첫째 cheotjjae.)

**D. 자모 매핑 오류** — ㄸ=tt(`띵작` ddingjak → ttingjak) · ㅐ=ae(`워라밸` worabel → worabael) ·
ㅓ=eo(`농업` nongup → nongeop) · c와 sh는 개정 로마자에 없다(`직캠` jikcaem → jikkaem).

**E. ⚠️ ㄴ 첨가 — 변환기가 틀리고 원래 값이 맞는 경우**

`알약` allyak, `물약` mullyak은 **원래 값이 정답**이었다. 합성어 ㄴ첨가로 [알략]으로 소리 나는데
변환기가 그 규칙을 몰라 aryak을 기대한 것이다. 모르고 "고쳤다면" 정답을 오답으로 바꿨다.

이제 `romanize.ts`의 `N_INSERTION`에 등록해 첨가형도 후보로 인정한다. 첨가형을 **더할 뿐**이라
미첨가 표기도 계속 통과하고, 오타는 여전히 걸린다(테스트로 고정해 두었다).
합성어에서 앞말이 자음으로 끝나고 뒷말이 **이·야·여·요·유**로 시작하면 의심할 것 —
`색연필`·`담요`·`한여름` 류가 앞으로 걸리면 고치지 말고 등록부터 해야 한다.

## 이번에 정한 표기 정책

**사극 덱의 문장형 표제어는 개정 로마자 표준(어절 단위, 붙임표 없음)으로 통일한다.**
형태소마다 붙임표를 넣던 `seong-eun-i mang-geuk-ha-op-ni-da`는 `-op-ni-da`가 실제 발음
[ㅁ니다]와 어긋나기까지 했다. → `seongeuni manggeukaomnida`.
다른 덱의 다국절 표제어(`수고하셨습니다` sugohasyeotseumnida)와도 표기가 맞는다.

발음 혼동을 막는 붙임표(`암행어사` amhaeng-eosa, `상궁` sang-gung)는 규정이 권장하는
용법이므로 그대로 둔다 — 없앤 것은 형태소마다 끊어 넣은 쪽뿐이다.

## 새로 쓴 예문

'당신'은 한국어가 2인칭 대명사를 쓰지 않는 자리라 주어를 뺐다. 번역문은 도착어 관습대로
2인칭을 쓰는 게 맞으므로 손대지 않았다.

- `언제` — "당신은 언제 한국에 왔어요?" → "언제 한국에 왔어요?"
- `어울리다` — "그 옷은 당신에게…" → "그 옷이 정말 잘 어울리니까 꼭 사세요!"

예문 중복은 문장이 더 어울리는 쪽에 두고 다른 쪽을 새로 썼다(4개 언어판 번역까지).

- `시간` — "시간이 없어서 빨리 가야 해요." ("지금 몇 시예요?"는 `지금`에 남김)
- `버스` — "버스 정류장이 어디에 있어요?" ("버스를 타고 학교에 가요."는 `타다`에 남김)
- `발전` — "이 도시는 최근 몇 년 사이에 눈부신 발전을 이루었습니다." (동사 예문은 `발전하다`에 남김)

## 고칠 때의 실무

`constants/curationData.ts`와 `scripts/<deck>-translated.json` **두 곳을 함께** 고쳐야 한다.
curationData.ts는 덱마다 들여쓰기가 달라 통째로 재직렬화하면 diff가 폭발하므로,
`"term"` 줄로 표제어를 따라가며 **줄 단위로** 바꿀 것. (표제어, 현재값) 쌍이 정확히 맞을
때만 치환하면 같은 표제어가 여러 덱에 있어도 안전하다.
