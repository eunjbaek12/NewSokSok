# 아보카도 회고 — 5.3개월 653커밋에서 남은 것

> 쏙쏙 보카(아보카도) 개발에서 실제로 겪은 시행착오를 다음 프로젝트로 옮기기 위해 정리한 문서.
> 작성 2026-08-07. 근거는 세션 기억 90여 건 + 저장소 문서 + 프로덕션 실측.

## 0. 이 문서를 읽는 법

각 항목은 **원칙**과 **그 원칙을 만든 사건**으로 되어 있다. 원칙만 읽으면 다 아는 소리처럼
들리는데, 실제로는 전부 한 번씩 틀려서 값을 치른 것들이다. 증거를 같이 남기는 이유는
나중에 그 규칙이 귀찮아졌을 때 "이거 정말 필요한가"를 다시 판단할 근거가 필요하기 때문이다.

- **1~9장**은 아보카도 고유의 기록이다. 새 프로젝트로 옮기지 않는다.
- **10~11장**은 새 프로젝트 `CLAUDE.md`에 그대로 붙일 수 있는 형태로 썼다.

### 전체를 관통한 한 문장

값비쌌던 실수는 기능별로 흩어져 보이지만, 실제로는 거의 전부 같은 모양이었다.

> **"확인했다고 생각했는데, 확인 범위 밖이었다."**

| 무엇을 확인했다고 믿었나 | 실제 범위 |
|---|---|
| dev 빌드에서 UI 확인 | 릴리스 빌드에서만 나는 버그가 있었다 |
| 덱 검사 0건 통과 | 검사 대상이 전체의 절반(두 번 연속) |
| 폭 예산 검사 통과 | 등록제 — 미등록 자리는 검사되지 않음 |
| 사람이 눈으로 확인 | 영어 화면을 본 적이 없어 영어가 안 보였다 |
| 원고 준비 완료 | 스토어에는 반영되지 않았다 |
| Play Console 권한 체크 확인 | UI 체크 ≠ 실효 권한 |
| 리베이스 충돌 0건 | 결과물은 깨져 있었다 |

여섯 층에서 같은 모양이 반복됐다. 그래서 다음 프로젝트에서 가장 값이 나갈 습관은
"더 꼼꼼히 보기"가 아니라 **"내 확인이 무엇을 안 보고 있는지 먼저 말하기"** 다.

## 1. 디버깅 — 비싼 실수는 전부 같은 모양이었다

### 1.1 값을 바꾸기 전에 값을 프린트하라

**사건: 달력 동그라미를 여섯 번 고쳤다.**

통계 화면의 "암기한 날" 표시가 Android에서 원이 아니라 사각형으로 그려졌다.
수정 이력이 이렇다.

| 시도 | 무엇을 바꿨나 | 결과 |
|---|---|---|
| 1 | `borderRadius: 999` | 사각형 |
| 2 | `borderRadius: '50%'` | 사각형 |
| 3 | `onLayout`으로 실측 픽셀 반경 | 사각형 |
| 4 | `Dimensions.get('window').width`에서 결정적 계산 | 사각형 (한 번 "종결" 선언 → 오판) |
| 5 | `borderWidth` 추가 (1px·2px) | 사각형 |
| 6 | **`overflow: 'hidden'`** | ✅ 원 |

다섯 번 헛짚은 이유가 하나다. **전부 "값을 어떻게 계산하나"만 바꿨다.**
여섯 번째 시도 직전에 온디바이스에서 `console.log(StyleSheet.flatten(...))`를 찍어보니
`borderRadius: 19, w = h = 38, backgroundColor 설정됨` — **값은 처음부터 내내 맞았다.**
버그는 계산이 아니라 한 겹 아래, Android(New Arch/Fabric)가 배경색 있는 View의
`borderRadius`를 렌더링에서 무시하는 데 있었다.

> **원칙: 왜 틀렸는지 이론을 세우기 전에, 지금 값이 무엇인지 출력한다.**
> 값이 맞는데 화면이 틀렸다면 문제는 그 아래 층에 있다. 계산식을 다섯 번 바꿔도
> 안 고쳐지는 건 계산식이 원인이 아니라는 뜻이다.

부수 교훈 하나 — **같은 View에 배경 없이 테두리만 준 "오늘" 칸은 처음부터 원이었다.**
두 케이스가 갈린 사실 자체가 단서였는데, 값을 찍기 전엔 그게 단서로 안 보였다.

### 1.2 첫 진단은 자주 틀린다

기억에 남은 오진만 모아도 이 정도다.

| 첫 진단 | 실제 |
|---|---|
| "복원 경로가 죽었다" | Android는 정상. iPhone 무반응은 **설계상 당연**(Play 구독은 StoreKit에 없음) |
| "한도 초과 시 광고 모달이 뜰 기회가 없다" | **이미 뜨고 있었다.** 주석 한 줄만 보고 위 계층을 확인 안 함 |
| Android 결제 실패 = "Play 계정 ≠ 앱 계정" | 아님. `verify-purchase`는 Play 계정을 아예 안 본다 |
| Android 결제 실패 = SA 키 만료 | 아님. 토큰 교환은 성공(=키 정상) |
| Android 결제 실패 = GCP API 미활성 | 아님. 꺼졌으면 403인데 401이었다 |
| "Play Console 권한은 체크돼 있으니 권한 문제 아님" | **틀림.** UI 체크 ≠ 실효 권한 |
| "iOS 릴리스에도 패딩 회귀가 있다" | 틀림. 실기 확인 없이 "플랫폼 공통"이라 가정한 것 |
| "패딩 회귀 원인 = default param이 릴리스에서 샌다" | 반증됨 (다른 모달은 정상) |
| "React Compiler 단독 원인" | 반증됨 (dev에서도 도는데 dev는 정상) |
| "단어장이 사라진 건 빌드 버전 차이" | 아님. 같은 버전 재설치로 복구됨 → 진짜는 pull 1000행 잘림 |
| "리베이스 충돌 0이니 정상" | 결과물이 깨져 있었다 (`tsc`가 잡음) |

**Android 결제 건이 특히 교훈적이다.** 5월부터 두 달간 한 번도 성공하지 못했는데,
가설 다섯 개가 순서대로 전부 탈락했고 진짜 원인은
**Play Console에서 서비스 계정의 "앱 권한" 목록에 이 앱 자체가 없던 것**이었다.
코드·키·DB·시크릿·패키지명 전부 정상이었다.

> **원칙: 고치기 전에 증상이 실재하는지부터 확인한다.**
> 그리고 가설을 세울 때마다 **그 가설을 반증할 관찰**을 같이 적어둔다
> (예: "키 문제라면 토큰 교환이 실패해야 한다" → 성공했으므로 탈락).
> 이 형식으로 적으면 가설이 하나씩 실제로 죽고, 안 적으면 같은 가설을 다시 판다.

### 1.3 침묵 — 성공과 실패가 화면에서 똑같아 보이는 자리

이게 아보카도에서 가장 반복적으로 시간을 잡아먹은 부류다.

- **복원 버튼**: 정상적으로 "복원할 구매가 없음"인 경우와 진짜 고장이 **둘 다 무반응**이었다.
  사용자도 진단하는 쪽도 구분할 수 없었다. → 결과를 4갈래로 나누고 각각 다른 문구를 띄우도록 수정.
- **AI 보강**: 잘못된 API 키를 넣으면 오류가 안 뜨고 **무료 사전으로 조용히 폴백**해서
  뜻만 비고 나머지가 채워졌다. 화면은 성공처럼 보였다.
- **인앱 리뷰 버튼**: OS가 팝업 표시 여부를 정하면서 **알려주지 않는다.**
  이미 평가한 사용자에겐 호출이 `resolve`(성공)하면서 아무것도 안 뜨고, 성공이라 폴백도 안 타서
  **버튼이 완전히 먹통**이 됐다.
- **verify-purchase Edge Function**: 실패 세 갈래가 전부 `console` 없이 리턴해서 로그가 비어 있었다.
  로깅 네 줄을 넣자 다음 재현 한 번에 원인이 나왔다.
- **Edge 게이트웨이**: 만료된 JWT는 **함수가 부팅되기 전에** 401로 잘려서 함수 로그에 아무것도 안 남는다.
  → "로그에 요청이 없다"를 "클라이언트가 호출을 안 했다"로 읽으면 안 된다.
  미호출·게이트웨이 401·성공했는데 값이 같음 — **셋이 DB에서 전부 "변화 없음"으로 보인다.**
- **PostgREST**: 응답을 서버 max-rows(1000)로 **조용히** 자른다. 에러가 없다.
- **SQLite 매퍼 누락**: 마이그레이션과 INSERT는 멀쩡한데 `rowTo*` 매퍼에 한 줄이 빠져
  SELECT 결과에서 필드가 사라졌다. 매퍼가 `any` row를 받으니 **타입 체커도 안 잡는다.**
- **`supabase db push`**: 타임스탬프가 역전되면 마이그레이션을 건너뛰면서 **exit 0**과 성공처럼 보이는
  JSON을 낸다. `--include-all`이 필요하고, 적용 여부는 `migration list --linked`로 봐야 한다.
- **`cmd | tail`**: exit code는 `tail`의 것이다. `tsc | tail`이 0으로 보였지만 실제는 2였다.

> **원칙: 실패는 성공과 다르게 생겨야 한다.**
> 새 경로를 만들 때 "이게 실패하면 화면에서 어떻게 보이나"를 한 번 묻는다.
> 답이 "성공했을 때와 같다"면 그 자리는 나중에 반드시 시간을 잡아먹는다.

### 1.4 원인이 코드 밖에 있을 수 있다

코드를 아무리 읽어도 안 나오는 부류가 실제로 여러 번 있었다.

- **Android 결제 두 달 실패** → Play Console SA 앱 권한 목록 (위 참조)
- **배너 광고가 안 뜸** → 코드 결함이 아니라 AdMob "광고 게재 제한됨". 앱이 스토어에 라이브로
  연결되기 전엔 서빙을 near-zero로 제한한다. **출시 전엔 빈 배너가 정상**이었다.
- **AdMob iOS 인증 실패** → 진범은 **App Store 마케팅 URL이 비어 있던 것**.
  게다가 마케팅 URL은 라이브 앱에서 잠겨 **새 버전 제출로만 수정 가능**했다.
- **연간 구독이 매월 청구되도록 설정돼 있었음** → 앱은 결제 주기를 알 수 없어 그대로 사고가 날 자리.
  Play는 기본 요금제 생성 후 결제 주기를 못 바꿔서 요금제를 새로 만들어야 했다.

> **원칙: "코드는 맞는데 안 된다"가 3회 반복되면 콘솔·계정·권한·스토어 설정을 의심한다.**
> 그리고 그 판정을 위해서라도 **서버 쪽 실패 경로에 로그가 있어야 한다**(1.3 참조).

## 2. 검증 — "확인했다"에 등급을 매겨라

### 2.1 dev ≠ release (실측)

출시본 1.2.1에서 시트 본문 패딩만 0으로 나갔다. **같은 소스**를 dev 클라이언트에서 돌려
재현되지 않음을 실측으로 확인했다.

| | 릴리스 vCode18 | dev (같은 소스) |
|---|---|---|
| 본문 패딩 | **1.0dp** ✗ | **25.0dp** ✓ |
| 제목·버튼 | 24dp ✓ | 24dp ✓ |

정밀화된 조건: `scrollable={false}` → `Body=View`일 때 배열 조건부 스타일
(`[styles.body, cond && styles.bodyPadded]`)이 **Android 릴리스에서만** 조건부 항목을 잃는다.
`Body=ScrollView`(대다수 모달)는 정상, iOS 릴리스도 정상.

> **원칙: "dev에서 확인했다"는 이 클래스의 버그에 대해 검증이 아니다.**
> 시각 검증은 `preview` 프로필(= 스토어를 거치지 않는 **릴리스 모드** APK)로 한다.
> dev는 JS 즉시 반영이 필요한 로직 디버깅용으로만 쓴다.

⚠️ 여기서 또 한 번 틀렸다. **"iOS는 릴리스에서 무조건 안전"은 잘못된 일반화**다 —
같은 JS 번들이므로 iOS도 다른 지점이 릴리스에서만 깨질 수 있다. 확인된 건 실기로 본 화면뿐이다.

### 2.2 검증 등급 표 (다음 프로젝트에 그대로 옮길 것)

아보카도에서 이걸 문서로 안 갖고 있어서, 같은 질문을 매번 다시 판단했다.

| 무엇을 바꿨나 | 최소 검증 | 이유 |
|---|---|---|
| 순수 로직 | 유닛 테스트 | 렌더링 무관 |
| 화면 레이아웃·패딩·모양 | **릴리스 모드 빌드** | 릴리스 전용 변환이 스타일을 먹는 전례 |
| 네이티브 팝업(리뷰·권한) | **프로덕션 빌드** | dev/Expo Go에선 아예 안 뜬다 |
| 광고 | **스토어 라이브 이후** | 연결 전엔 서빙 제한이 정상 |
| 결제 | **실기 + 서버 로그** | 클라이언트 성공이 서버 성공이 아니다 |

| 마이그레이션 | **`migration list`의 remote 칸** | exit code가 거짓말한다 |

### 2.3 범위가 절반을 가린다 — 두 번 연속

한국어 덱 자동 검수를 만들고 "확실한 문제 0건"으로 종결했다. 그런데:

1. **1차**: 대상이 `targetLanguage === 'en'`인 덱뿐이었다. `Basic Korean 500`은 vi/ja/zh 판이 따로
   있고 로마자를 각각 **재생성**해 둬서 같은 오류가 3벌 더 있었다(+33건). 베트남어판은 아예
   **다른 오류 세트**였다(+13건).
2. **2차**: 1차 확대 후에도 대상은 `sourceLanguage === 'ko'`뿐이라
   **한국어가 도착어인 덱 44개(9,337단어)를 한 번도 안 봤다.**
   "0건 종결"은 그 절반 안에서만 참이었다.

최종 대상은 63덱 13,574단어. 두 번 다 "이제 전부 봤다"고 믿고 있었다.

**범위를 넓힐 때 조심할 자리 둘** (다음에 또 넓힐 때 그대로 적용된다):

- **옵션 이름이 역할과 어긋나면 검사가 조용히 꺼진다.** `targetIsKorean`의 실제 역할은
  "번역 슬롯에 한글이 있어도 정상이냐"인데 이름은 "도착어가 한국어냐"로 읽힌다.
  en→ko도 도착어는 한국어라 이름대로 넘겼다면 검사가 통과해 버렸을 것.
  → `allowHangulInTranslation`으로 리네임.
- **판정 기준을 바꾸면 오탐이 줄면서 진짜 문제가 늘 수 있다.** 예문 중복을 번역문 기준으로 재면
  원문이 다른데 번역만 수렴한 것까지 잡힌다(13건 중 6건 오탐). 기준을 **학습자가 읽는 원어 문장**으로
  바꾸니 오탐이 빠지는 동시에 **가려져 있던 진짜 중복 11건이 드러났다**(→18건).

> **원칙: 검사가 통과했다고 보고할 때는 "무엇을 봤는지"를 같이 적는다.**
> "0건"이 아니라 "63덱 13,574단어 중 0건"이라고 쓰면 다음 사람이 범위를 의심할 수 있다.

### 2.4 사람이 못 보는 축이 있다

- **영어 탭 라벨이 원래 잘리고 있었다.** `Collections`·`Vocab Lists`(둘 다 11자)가 스페인어를
  넣기 전부터 잘려 있었는데 **아무도 몰랐다** — 운영자가 앱을 영어로 쓴 적이 없기 때문이다.
- 폭 예산 검사를 도입하자 **넣자마자 4건을 잡았고 그중 3건이 영어**였다.
  `Learned today`·`Intermediate`·영어 주제 예시. 같은 구도가 반복됐다.
- **스페인어 문장의 존칭·문법은 운영자가 판정 불가**하다(언어를 모름).
  이 축은 앞으로도 사람 검증에 기대면 안 된다.
- `usted` 존칭을 **8키로 추정했는데 실제로는 52곳**이었다 — 6배를 놓쳤다.
  `su`/`le`/`usted` 표지만 봤기 때문인데, 스페인어 존칭은 그런 표지 없이도 성립한다
  (지시법, 접미대명사가 붙은 명령형 `Contáctenos`·`Apóyenos`).
  → **가장 확실한 검출법은 "문장 첫 낱말 전수 열거"** 였다. 정규식에 동사를 나열하는 방식은 매번 빠뜨린다.

> **원칙: 내가 못 보는 축을 먼저 적고, 그 축은 도구에 맡긴다.**
> "눈으로 봤다"가 통하는 범위를 스스로 좁게 잡는 게 정확도를 올린다.

## 3. 자동 검수 — 경고는 아무도 안 본다

### 3.1 만든 도구와 실제 수확

| 도구 | 무엇을 잡나 | 실제 수확 |
|---|---|---|
| `pnpm run i18n:check` | 키 누락·잉여·보간 변수 유실 + **폭 예산 7축** | 도입 즉시 4건(3건이 영어), 이후 2건 추가. "정렬이 안 맞다"고 보고된 자리의 **진짜 원인이 길이**였음 |
| `pnpm run diagnose:decks` | 로마자 오류·중복 예문·번역 미완성 | 로마자 152건 수정. 눈검수로는 350단어 덱에서 16건씩 새고 있었다 |
| `pnpm run i18n:fill` | 빠진 키만 AI로 채움 | 1,037/1,040키 번역 |

### 3.2 설계에서 배운 것

- **exit 1이어야 한다. 경고는 아무도 안 본다.** 영어 탭 라벨이 그 증거다 —
  경고였다면 몇 달 더 잘려 있었을 것이다.
- **등록제는 "미등록 = 안전"이 아니다.** 폭 예산은 좁은 자리를 손으로 등록하는 방식인데,
  등록 안 된 자리 3곳이 그대로 빠져나가 다음 검증에서 깨졌다.
  → 새 UI를 만들 때 "이 자리는 몇 em까지"를 스펙에 적어야 한다. 도구만으론 안 된다.
- **단위는 상대값으로.** 폭 예산을 px로 적으면 폰트 크기를 바꿀 때 같이 못 고친다.
  em으로 적고 한글 1.0 / 라틴 소문자 0.52 가중치를 뒀다.
- **검사(사후)와 프롬프트 규칙(사전)을 같이 둔다.** 덱 생성 스크립트가 각자 검사 함수를
  복제하고 있어서 새 덱이 이전 덱의 실수를 그대로 되풀이했다. 공용 모듈 + `SHARED_PROMPT_RULES`로 합쳤다.
- **오탐을 줄이려 규칙을 느슨하게 만들 때 조심.** 로마자 `ㄴ 첨가`(`알약` → allyak)는
  **원래 값이 정답**이었다. 모르고 "고쳤다면" 정답을 오답으로 바꿨을 것이다.
  → 예외는 지우지 말고 **등록**한다.

### 3.3 게임 프로젝트에서의 대응물

| 아보카도 | 게임 |
|---|---|
| i18n 키 무결성 | 대사 테이블 참조 무결성 (끊긴 화자·도달 불가능한 분기) |

## 4. 데이터 — 로컬·클라우드가 갈리는 순간의 함정

오프라인 우선 + 30초 디바운스 동기화 구조에서 실제로 터진 것들. 게임의 세이브/클라우드 세이브에
그대로 재발한다.

### 4.1 조용한 잘림 → 영구 유실

PostgREST가 응답을 1000행으로 조용히 자르는데, 워터마크가 배치 max(updated_at)로 점프해서
잘린 행들이 `.gt(updated_at)`에 **영원히** 걸러졌다. 증상은 "어떤 단어장은 멀쩡, 어떤 건 빔"이라
원인 추정이 계속 빗나갔다.

**수정**: `(updated_at, id)` **키셋** 페이지네이션으로 전량 드레인.
- offset이 아니라 키셋인 이유 — 페이지네이션 도중 행이 갱신되면 offset은 밀려 들어온 행을 놓친다.
- `updated_at` 동률이 흔하므로(배치 upsert 트리거가 시각을 통일) **id 타이브레이커 필수**.
- 페이지 크기는 서버 캡의 **절반**(500). 캡과 같으면 "짧은 페이지 = 끝" 판정이 캡에 잘린 페이지를
  끝으로 오판한다.

### 4.2 삭제가 부활한다

로컬 소프트삭제는 즉시 커밋되는데 클라우드 push는 30초 디바운스였고, **dirty set이 메모리에만**
있었다. 크래시가 그 창을 끊으면 삭제가 영영 안 올라가고, 이후 pull이 살아있는 복사본을
`INSERT OR REPLACE`로 덮어써 부활시켰다.

**수정**: pull 트랜잭션 시작부에서 tombstone id를 prefetch → 살아있는 클라우드 행이라도 skip.
- **`updatedAt` 비교 LWW는 폐기했다.** 클라우드는 서버 시계, 로컬은 클라이언트 `Date.now()`,
  게다가 pull이 서버값을 로컬 컬럼에 써넣어 **시계가 혼재**해 비교 자체가 불가능했다.
- tombstone은 디스크에 커밋돼 리로드에도 살아남으므로 권위 신호로 적합하다.

> **원칙: 두 시계를 비교하지 말고, 한쪽에 사실을 기록한다.**

### 4.3 디바운스와 유실

생성·삭제 같은 **구조 변경까지 디바운스에 묶으면** 재설치 직전 작업이 유실된다.
편집만 디바운스로 두고 구조 변경은 즉시 flush하는 게 맞다.

부수 교훈 — **"최근 것이 없다" 신고를 받으면 저장소부터 구분한다.**
아보카도는 저장소가 셋이었다(개인=디바운스 동기화 / 공유=즉시 insert / 공식=앱 번들).
공식 덱이 안 보이는 건 동기화 문제가 아니라 **그 빌드의 나이** 문제였다.

### 4.4 스키마 변경이 세 곳에 흩어져 있다

마이그레이션에 컬럼을 추가했는데 `rowTo*` 매퍼에 한 줄을 안 넣어서, INSERT는 되는데
SELECT 결과에 필드가 없었다. 증상은 엉뚱한 데서 나왔다 —
`getTtsLang(undefined)`가 `en-US`로 폴백해 **일본어 단어장이 영어 보이스로 읽히다가 무음**이 됐다.

컴파일러가 못 잡는 이유: 매퍼가 `any` row를 받고, 호출부는 그 필드를 nullable로 선언해 뒀다.
같은 변형이 Supabase에도 있었다 — `...theme` spread만 하고 `creator_id → creatorId` 명시 변환을
빠뜨려 **모든 권한 가드가 조용히 false**가 됐다(`passthrough()` Zod라 타입 체커도 통과).

> **원칙: 스키마·직렬화·역직렬화가 세 파일에 흩어져 있으면 그건 구조 문제다.**
> 한 곳에서 파생시키거나, 최소한 "컬럼 추가 PR에는 매퍼도 포함"을 규칙으로 못 박는다.

### 4.5 그 밖에 반복된 것

- **stale state**: `useState` 초기값을 캐시 파생값으로 잡고 동기화 effect를 안 뒀다.
  캐시가 교체되자 죽은 id에 고착 → FK 위반. **같은 안티패턴이 다른 화면에도 있다고 전제할 것.**
- **중첩 트랜잭션**: 새 트랜잭션은 반드시 공용 `runInTransaction`을 거치게. 크래시가
  §4.2 부활 버그의 방아쇠였다.
- **대량 쓰기는 행 단위 호출부터 의심**: 단어마다 `runAsync`를 부르던 브리지 왕복 5,605번이
  10.9초였다. 다중 VALUES 배치(22컬럼 × 40행)로 왕복을 1/40로 줄이자 **7배** 빨라졌다(→1.5초).
- **타입 폭**: `Date.now()`를 `position`(int4)에 넣어 22003 오류. 범위를 먼저 본다.

## 5. 결제 — 처음부터 구조로 넣었어야 했던 것

### 5.1 소유권 바인딩이 없었다

**증상**: 한 계정으로 Pro를 결제한 뒤 **같은 Play 계정에서 다른 앱 아이디로 로그인하니 거기서도 Pro**.
실측 — `play_purchase_token` 1개에 `user_id` 2개, `pro_until`이 밀리초까지 동일.

**한 문장 원인**:
> 구매의 소유자는 **스토어 계정**(Google Play / Apple ID)인데
> 권한의 소유자는 **앱 계정**이고, 그 둘을 잇는 바인딩이 어디에도 기록돼 있지 않았다.

`verify-purchase`는 스토어에 "이 구독이 유효한가"만 묻고 그 답을 **지금 로그인한 user_id에 적었다.**
스토어는 "누구 것인가"에 답하지 않는다 — 물어본 적이 없으니까.

**고친 방식이 두 층인 게 핵심이다.**
- **지혈**: 토큰 소유자 조회 + 409, 그리고 `play_purchase_token` **부분 unique 인덱스**.
  코드 검사는 좋은 에러 메시지를 위한 것이고 **최종 방어선은 인덱스**다
  (동시 요청 경쟁과 조회 함수의 fail-open까지 막는다).
- **근본**: 구매 시점에 `obfuscatedAccountId`(Android) / `appAccountToken`(iOS)에 user_id를 실어 보낸다.
  🔑 **서버는 앱이 보낸 값을 믿지 않고 Play/Apple API 응답에서 직접 읽는다** → 위조 불가.

**반드시 지켜야 했던 것들** (게임에도 그대로 적용):
- **각인 없는 옛 구매는 통과시켜야 한다.** 거기서 막으면 기존 유료 사용자가 전원 차단된다.
- **iOS는 `originalTransactionId`로 조회한다.** 갱신마다 `transactionId`는 바뀌므로
  후자를 안 보면 갱신 때마다 "주인 없음"이 되어 검사가 통째로 무의미해진다.
- 계정 이전은 조용한 자동 이전이 아니라 **명시적 절차**여야 한다. 말없이 소유자를 바꾸면
  "의도한 이전"과 "권한 새기"를 서버가 구분할 수 없다.

### 5.2 SoT가 앱에 있으면 샌다

구독 상태의 실질적 단일 출처가 **앱**이었다(앱이 verify를 호출해야 서버가 안다).
그래서 구멍이 둘 남았다.

1. **갱신 반영 gap** — 만료 경계에서 잠시 Free가 된다.
2. **환불·해지 미반영** — 검증 시점엔 거부하지만 **이미 부여된 `pro_until`을 되돌리는 경로가 없다.**

여기에 더해 **크로스 스토어 사각**이 있다. 갱신 재검증이 전부 `getAvailablePurchases()`에
의존하는데, 이건 **구매가 존재하는 스토어의 기기에서만** 값을 준다.
Play로 결제하고 iPhone만 쓰면 갱신할 주체가 아무도 없고, 권한은 계정 단위라
**양쪽 기기에서 동시에 Pro가 끊긴다.**

구조적 해법은 서버 알림(RTDN / App Store Server Notifications)뿐이다.

> **원칙: 결제를 넣기로 했다면 "서버가 스스로 아는가"를 첫 질문으로 둔다.**
> 앱이 알려줘야만 서버가 아는 구조는 갱신·환불·크로스 플랫폼에서 반드시 샌다.
> RevenueCat 같은 서비스는 이 문제 전체를 대신해 준다 — 직접 구현한 뒤에 옮기려면 비싸므로
> **시작 시점에 판단해야 한다.**

### 5.3 테스트 환경이 거짓말하는 자리

- 라이선스 테스터는 구독 기간이 **압축**된다(1개월→5분, 1년→30분).
  결제 시트의 `/5min`·`/30min`이 **어떤 기본 요금제가 잡혔는지 그대로 알려준다** — 유용한 진단 신호.
- 하지만 **"3분 무료 체험"은 콘솔 설정과 무관한 테스트 고정값**이다.
  7일로 설정해도 3분으로 뜬다 → **이걸로 체험 일수를 검증할 수 없다.**
- Play는 (기본 요금제 × 혜택)만큼 오퍼를 **순서 보장 없이** 내려준다.
  `[0]`을 무조건 쓰면 엉뚱한 주기로 결제된다. 일치하는 요금제가 없으면
  **폴백하지 말고 실패시킨다** — 엉뚱한 금액으로 결제되느니 실패가 낫다.

## 6. 성능 — 측정 → 분해 → 큰 덩어리부터

### 6.1 콜드 스타트 3.0초 분해

```
콜드 스타트 4회: 3018 / 3010 / 3023 / 3015 ms   ← 편차 13ms
```

| 구간 | 시간 | 비중 |
|---|---|---|
| 네이티브 → 첫 프레임 | 314 ms | 10% |
| **고정 스플래시 타이머** | **1,500 ms** | **50%** |
| JS 번들 + 폰트 6MB + 트리 마운트 + 큐레이션 8MB + 홈 | ~1,200 ms | 40% |

🔑 **편차 13ms가 결정적 단서였다** — 가변 작업이 아니라 **고정 타이머가 지배한다**는 뜻이다.
이걸 보고 나서야 코드를 열어볼 생각을 했다.

원인은 스플래시가 **early return**이라 그때까지 Provider 트리가 아예 마운트되지 않던 것.
게다가 1500ms 타이머가 폰트 로딩 **뒤에** 시작해서 겹치는 게 아니라 더해졌다.
스플래시를 오버레이로 바꾸자 추가 작업 0으로 3.0초 → 약 1.8초.

**순서를 뒤집으면 효과가 없다는 것도 배웠다.**
JS 구간이 1,200ms인데 `SPLASH_MS`부터 줄이면 그 밑으로 안 내려간다. 큰 덩어리를 먼저 뗀 다음에야
작은 조정이 의미를 갖는다.

### 6.2 데이터가 커지면 시작 시간이 된다

`constants/curationData.ts` = **8.16MB · 231,251줄 · 63덱 · 13,574단어** 단일 배열 리터럴.
expo-router 기본 import mode가 `sync`라 **큐레이션 탭을 안 열어도** 홈보다 먼저 전부 생성됐다.

성장 이력이 그대로 시작 시간이 됐다:
`149KB → 2,296KB → 6,239KB → 8,130KB` — **56배**.

수정 후 **프로덕션 번들을 열어 검증했다** — 컴파일된 모듈의 최상단 require가 셋뿐이고
큐레이션은 함수 안에서 asyncRequire로 나간 것을 확인. **추측이 아니라 번들을 연 것.**

### 6.3 로그인 29.5초 → 13.7초

| 구간 | 전 | 후 |
|---|---|---|
| DB 트랜잭션 쓰기 | 10,930ms | **1,551ms** |
| 리스트별 완전성 조회 | 2,306ms | **2ms** |
| fetch 4 tables | 7,359ms | 7,016ms |

**순위가 직관과 달랐다.** 진범은 네트워크가 아니라 SQLite 쓰기(전체의 37%)였다.
남은 최대는 네트워크 7초인데 페이로드 대부분이 실제 데이터라 물리적 한계에 가깝다.

> **원칙: 최적화는 총량 측정 → 구간 분해 → 가장 큰 덩어리 순으로만 한다.**
> 짐작으로 시작하면 반드시 헛다리를 짚는다. 아보카도에서 두 번 다 그랬다.

**빌드 없이 재는 법**(재사용 가치 있음): `adb shell am start -W`의 `WaitTime`이 체감과 일치했다.
⚠️ 단, 잠금 화면 뒤에서 재면 값이 오염된다 — `dumpsys window`로 `mScreenLocked=false`를 먼저 확인할 것.
이걸 몰라서 측정 하나를 통째로 버렸다.

## 7. 다국어·콘텐츠 — 나중에 붙이면 비싸다

### 7.1 언어를 추가할 때마다 재발하는 것

- 🔴 **`alignItems: 'center'`만으로는 감긴 줄이 왼쪽에 붙는다.**
  그 속성은 자식 **뷰**를 가운데 놓을 뿐이고, `Text`가 줄바꿈되면 Text 노드가 가용 폭을 다 차지해
  안쪽 글자는 기본값인 왼쪽 정렬로 흐른다. ko/en은 늘 한 줄이라 안 보이다가 es에서 드러났다.
  → 가운데 정렬 라벨엔 `textAlign: 'center'`를 반드시 같이 준다.
  ⚠️ **전수 수정은 금지** — 스캔하면 51파일 346곳이 나오지만 절반 이상이 오탐이다.
- 🔴 **`{n}{t('unit')}` 연결은 언어별 띄어쓰기를 담지 못한다.** ko `10개`는 붙여야 맞고
  es `10 palabras`는 띄어야 맞는데 `10palabras`가 나왔다.
  **영어는 단위가 빈 문자열이라 우연히 멀쩡했다 — "영어가 멀쩡하다"가 검증이 안 되는 전형.**
- **스페인어는 한국어보다 텍스트가 2~3배 길다.** 짧은 라벨 중 18자 넘는 게 224개였다.
- **`locale === 'ko' ? A : B` 삼항은 언어를 추가해도 컴파일이 통과하면서 조용히 영어가 나온다.**
  → 공용 `resolveLocale()`을 거치게 한다.

### 7.2 자동 번역을 쓰면 안 되는 자리

- **샘플 데이터·온보딩 데모** — 번역이 아니라 **학습 방향이 뒤집힌다.**
  ko판은 "영어 표제어 + 한국어 뜻", es판은 "한국어 표제어 + 스페인어 뜻"이어야 하는데
  기계번역하면 스페인어 단어에 스페인어 뜻이 되어 배울 게 없다.
- **명언·인용** — 번역이 아니라 **대체**다. es판은 스페인 속담과 세르반테스로 갈았다.
- **CSV 헤더** — 헤더를 번역하면 **별칭 테이블에도 등록**해야 내보낸 파일을 다시 가져올 수 있다.
- **법률 문서·FAQ 장문** — 의도적으로 영어 폴백. 기계번역을 얹지 않는다.

### 7.3 원고 ≠ 반영

앱 약관을 새 정책으로 고쳤는데 **스토어 설명은 별개 매체**라 옛 문구가 그대로 라이브였다.
저장소 원고는 이미 새 정책이었다 — **작성만 되고 반영이 안 된 상태**를 "완료"로 적어뒀던 것.

그리고 매체마다 고칠 수 있는 시점이 다르다.

| 위치 | 매체 | 언제 고치나 |
|---|---|---|
| 앱 안 문구 | **앱 번들** | 새 빌드 + 심사 |
| Play 설명 | 스토어 | **언제든 즉시** |
| App Store 이름·부제·키워드·설명 | 스토어 | **새 버전 제출 시에만**(빌드가 딸려온다) |
| App Store 프로모션 텍스트 170자 | 스토어 | 언제든 |
| 웹 방침 | GitHub Pages | 언제든 |

**적용 순서를 뒤집으면 약속을 어긴다.** 약관은 빌드에 먼저 담고, 서버 마이그레이션은 출시 후.
그 사이 공백은 "약관엔 없다는데 서버가 더 준다"라 무해하다 — 반대 순서라야 거짓 약속이 된다.

> **원칙: "완료"라고 적기 전에 라이브를 직접 확인한다.**
> ⚠️ Play 스토어 페이지는 WebFetch로 못 읽는다(본문이 통째로 빠진다) → curl + 문자열 검색.
> App Store 페이지는 반대로 WebFetch가 잘 읽힌다.

### 7.4 콘텐츠는 관문이 열려 있을 때만 의미가 있다

새 언어 덱 제작을 제안받았을 때, 제작비(반나절)가 아니라 **관문 3개**를 먼저 봤어야 했다.

1. 스토어 등록정보 로케일에 그 언어가 있는가
2. UI 로케일에 있는가
3. 앱 기본값이 그 언어로 유도되는가

실측 — ko→vi·ja·zh 덱은 **저장한 사용자가 한 명도 없었다.** 스토어 등록정보 로케일까지
만들어 둔 언어인데도 0이었다.

그런데 **전제는 뒤집힐 수 있다.** UI 스페인어가 나가면서 스페인어 기기는 뜻 언어가 자동으로 es가
되는데, 공식 덱 63개 중 **es는 0개**라 큐레이션 탭이 빈다. "덱이 없어도 손해 없다"가
유입이 생기는 순간 깨진 것이다.

> **원칙: 콘텐츠 추가 판단은 "만드는 비용"이 아니라 "닿을 경로가 열려 있는가"로 한다.**
> 그리고 그 판단의 전제(관문)를 **문서에 적어두면** 전제가 바뀔 때 알아챌 수 있다.

## 8. 성장 — 만드는 문제와 알려지는 문제는 다르다

### 8.1 퍼널 실측

```
노출 351 → 설치 27 (전환율 38.71%) → 첫 실행 13 (48%) → MAU 18 → 7일 유지 1
```

- ✅ **스토어 등록정보 전환율 38.71%는 우수하다**(통상 20~30%).
  아이콘·스크린샷·설명은 제 몫을 하고 있다 → **손대지 말 것.**
- 🚨 **설치→첫 실행 48%가 진짜 누수**다(정상 80~90%). 27명 중 14명이 설치하고 한 번도 안 열었다.
- ⚠️ 안정성 지표가 전부 "데이터 없음"인 건 표본 부족이지 **크래시가 없다는 뜻이 아니다.**

### 8.2 반복해서 확인된 것

- **병목은 발견(discovery)이다.** 가입 퍼널의 활성화율(단어 추가까지)은 60%로 양호했다.
  앱이 나빠서가 아니라 아무도 모르기 때문이다.
- **로케일 등록정보만으로는 유입이 0이다.** ko/en/ja/vi/zh 5개 로케일 스토어 텍스트를 써 뒀는데
  베트남·일본·중국 설치는 0이었다. 신규 앱은 순위 근거가 될 다운로드가 없어 검색에 안 뜨고,
  안 떠서 다운로드가 없다. **pull 채널은 부트스트랩 전까지 작동하지 않는다.**
- **표본 19건으로 시장을 판단하면 안 된다.** 국가 차이가 전부 노이즈다.
  ⚠️ 단, **외부 데이터**(경쟁 앱이 실제로 고른 언어, 업계 리포트)로 판단하는 건 다른 종류다.
- **체험 61명 중 유료 전환 0명.** 표본이 48→61로 커져도 결과가 같았다.
  ⚠️ 하지만 **"체험을 없애면 전환이 는다"는 논리는 절반만 맞다** — 폐지의 실제 이득은
  비용과 한도 절벽 제거이지 전환 증대가 아니다. 병목은 여전히 유입이다.
- **커뮤니티는 획득 채널이 아니라 피드백 채널로 보는 게 맞았다.** 100명이 오지는 않는다.
  대신 "왜 안 쓰는지" 말해주는 몇 명을 얻는다. 실제로 그 댓글 하나가 기능 개편의 발단이 됐다.

### 8.3 사용 데이터가 설계를 바꿨다

```
직접 만든 단어장    2,277단어 / 1,058 암기 = 46.5%
큐레이션에서 가져옴 18,388단어 / 2,345 암기 = 12.8%
```

**"넓게 쓰지만 깊게 안 쓴다."** 진짜 학습은 자기가 만든 것에서 일어난다.
이 숫자 하나가 "덱부터 채우고 UI는 나중"이라는 순서를 뒤집었다.

⚠️ 지표 함정도 같이 배웠다 — `last_studied_at`은 **생성 시점에 채워져** 학습 여부를 못 가른다
(양쪽 다 100%로 보인다). 암기 비율로 봐야 한다.

### 8.4 지표를 읽을 때의 함정

- 게스트는 서버에 흔적이 없다 → 실제 DAU는 항상 집계보다 크다.
- `last_sign_in_at`은 세션 유지 시 갱신 안 됨 → **사용 지표로 쓰면 안 된다.**
- 테이블이 특정 날짜부터만 존재하면, 그 이전 가입자의 0은 **이탈이 아니라 기록 부재**다.
  정착률을 볼 땐 기간을 좁혀야 한다(전체로는 48명 중 33명 미학습처럼 보이지만,
  좁히면 10명 중 1명이었다).
- 날짜 기준이 컬럼마다 다르다(기기 로컬 날짜 vs 절대시각) → **해외 사용자는 한 세션이 이틀에 걸쳐 보인다.**
- 봇·본인 계정이 상시 섞인다. 어느 날은 활동자 9명 중 3명이 그것이었다.

## 10. 협업 규율 — 새 프로젝트로 그대로 옮길 것

### 10.1 다중 세션이 워킹 트리 하나를 공유할 때

여러 Claude 세션을 한 체크아웃에 돌리면 브랜치는 하나뿐이고 미커밋 변경이 브랜치 전환을 따라간다.
실제로 사고가 났다 — 브랜치를 옮기자 **다른 세션이 새 브랜치로 따라왔고**, 그쪽은 영문도 모른 채
커밋 4개를 거기 쌓았고, 이후 그 브랜치에서 분기해 push하자 **남의 미푸시 커밋 4개가 내 PR에 섞여** 올라갔다.

- **브랜치 전환 승인은 1회성이다.** "그 순간 옮겨도 된다"이지 "앞으로 자유롭게"가 아니다.
- **`git add -A` / `git commit -a` 금지.** 경로를 명시해 스테이징한다.
- **`git stash` 금지.** 남의 변경이 stash 스택에 들어가면 그쪽이 영문을 모른다.
  스크래치패드로 백업 → 복원 → `diff`로 확인.
- **되돌리려고 rebase·cherry-pick 하지 말 것.** 작업 트리 파일이 되돌려져 진행 중인 세션에 실제 피해가 간다.
  원격에 올라간 커밋 자체는 손실이 아니라 백업이다 — **사실을 보고하고 판단을 받는 편이 항상 낫다.**
- **`git reflog`에 모든 세션의 활동이 남는다.** 다른 세션의 실제 위치를 확인하는 가장 빠른 방법.
- push / PR 생성 / merge는 **원격에서 일어나므로 체크아웃이 필요 없다.**

### 10.2 검증 결과를 보고할 때

- **`cmd | tail`의 exit code는 `tail`의 것이다.** 따로 잰다.
- **리베이스 충돌 0은 텍스트 이야기일 뿐이다.** 추가된 블록과 수정된 블록이 다른 자리면
  git은 충돌로 보지 않는다. 오래된 브랜치는 리베이스 직후 **반드시 타입체크를 돌린다**.
- 에러가 "기존 것"이라고 말하려면 근거를 댄다(`git blame` + `merge-base --is-ancestor`).

### 10.3 제안·구현·배포의 단계 분리

- **검토를 요청받으면 검토만 한다.** 내 종합은 *제안*이지 합의가 아니다.
  "결론"이라고 부르며 구현으로 넘어가면 검토·반대할 여지를 건너뛰게 된다.
- **개선안은 두 칸으로 낸다.**
  `[선택 불필요]`(근거: 다수·자기모순·문서화된 규칙) / `[선택 필요]`.
  ⚠️ "선택 불필요"라고 주장하기 전에 **실측으로 다수를 확인**한다.
  앱 전반이 안 지키는 규칙을 근거로 삼으면 안 된다.
- **개별 화면의 선택지를 하나씩 묻지 말고 공용 스펙을 먼저 확정한다.**
  화면 단위로 물으면 같은 질문을 화면마다 다시 하게 되고 답이 축적되지 않는다.
  실제로 두 질문이 공용 스펙 하나를 정하니 저절로 풀렸다.
- **후보는 글로 설명하지 말고 그려서 보여준다.**
- **프로덕션 반영(배포·DB 변경·스토어 제출)은 선택 승인과 별개로 실행 직전 재확인한다.**

### 10.4 문서 배치

| 문서 | 역할 |
|---|---|
| `CLAUDE.md` | 명령어 · 아키텍처 결정 · **실제로 배포된 실수만** 담은 체크리스트 |
| `DESIGN.md` | 공용 UI 스펙의 단일 출처 + 적용 대기 목록 |
| 기억 파일 | 왜 그렇게 결정했는지, 무엇이 오진이었는지 |

`CLAUDE.md` 체크리스트에는 **일반론적 베스트 프랙티스를 넣지 않는다.**
아보카도 것이 유용했던 이유는 전부 실제로 겪은 것이었기 때문이다.
그리고 **"기본값이 실수를 쉽게 만들었다"를 발견하면 규칙을 추가하기 전에 기본값을 고친다** —
모달 패딩을 컴포넌트 기본값으로 옮기자 규칙 하나가 사라졌다.

## 11. 다음 프로젝트 복사용 체크리스트

### 11.1 디버깅

- [ ] 값을 바꾸기 전에 **값을 프린트**한다. 값이 맞는데 화면이 틀리면 문제는 한 층 아래다.
- [ ] 고치기 전에 **증상이 실재하는지** 확인한다. 첫 진단은 자주 틀린다.
- [ ] 가설마다 **그 가설을 반증할 관찰**을 같이 적는다.
- [ ] "코드는 맞는데 안 된다"가 3회 반복되면 **코드 밖**(콘솔·권한·설정)을 본다.
- [ ] 새 경로를 만들 때 **"실패하면 화면에서 어떻게 보이나"** 를 묻는다.
      답이 "성공과 같다"면 그 자리를 고친다.
- [ ] 실패 경로에 로그를 남긴다. 조용한 리턴은 나중에 며칠을 잡아먹는다.

### 11.2 검증

- [ ] **검증 등급 표**를 프로젝트 문서에 둔다(§2.2 형식).
- [ ] "dev에서 확인했다"를 시각 버그의 검증으로 쓰지 않는다.
- [ ] 검사 결과를 보고할 때 **무엇을 봤는지(범위)** 를 같이 적는다.
- [ ] **내가 못 보는 축**을 먼저 적고, 그 축은 도구에 맡긴다.
- [ ] 자동 검사는 **exit 1**. 경고는 아무도 안 본다.
- [ ] 등록제 검사는 "미등록 = 안전"이 아님을 문서에 명시한다.

### 11.3 데이터 (게임 = 세이브)

- [ ] **첫 커밋부터 `version` 필드 + 마이그레이션 체인.** 세이브는 못 다시 만든다.
- [ ] 직렬화·역직렬화·스키마가 세 곳에 흩어지지 않게 한다. 흩어졌다면 규칙으로 못 박는다.
- [ ] 목록 조회는 처음부터 **페이지네이션**(키셋). 조용한 잘림을 전제한다.
- [ ] 삭제는 **tombstone**. 두 시계를 비교하지 말고 한쪽에 사실을 기록한다.
- [ ] 대량 쓰기는 **행 단위 호출부터 의심**한다.
- [ ] 상태 초기값을 캐시 파생값으로 잡았으면 **동기화 경로**를 같이 만든다.

### 11.4 게임 특유

- [ ] **난수는 시드 주입 + 시드 로깅.** 재현 불가능한 버그를 원천 차단한다.
- [ ] **시간은 직접 부르지 말고 주입.** 일일 보상·쿨다운·디버깅이 전부 여기 걸린다.
- [ ] **게임 로직에 렌더링을 섞지 않는다.** 헤드리스 시뮬레이터가 가능해야
      밸런싱을 감이 아니라 데이터로 한다.
- [ ] **밸런스·콘텐츠·대사는 코드 밖 데이터로.** 각각 검수 스크립트를 붙인다.
- [ ] **대사는 키-값 테이블로.** 지금 다국어를 하지 않더라도 문을 잠그지는 않는다.
- [ ] **계측 훅은 지금, 서버는 나중.** 나중에 붙이면 초기 데이터가 영영 없다.

### 11.5 수익화 (넣기로 했다면)

- [ ] **소유권 바인딩을 첫 설계에 넣는다.** 스토어 계정 ≠ 앱 계정.
- [ ] 최종 방어선은 **DB 인덱스**. 코드 검사는 에러 메시지용이다.
- [ ] **"서버가 스스로 아는가"** 를 첫 질문으로. 앱이 알려줘야만 아는 구조는 반드시 샌다.
- [ ] 각인 없는 옛 구매를 통과시키는 폴백을 **테스트로 고정**한다.
- [ ] 대행 서비스를 쓸지는 **시작 시점에** 판단한다. 나중에 옮기면 비싸다.

### 11.6 성장

- [ ] 등록정보만 만들어 놓고 유입을 기대하지 않는다. **pull 채널은 부트스트랩 전까지 안 돈다.**
- [ ] 표본이 작으면 시장 판단에 쓰지 않는다. 대신 **외부 데이터**를 쓴다.
- [ ] 잘 작동하는 지표는 **손대지 않는다**(전환율 38.71%처럼).
- [ ] 지표마다 **무엇을 못 세는지**를 적어둔다(게스트·기록 부재·시간대·봇).
- [ ] 커뮤니티는 획득이 아니라 **피드백 채널**로 기대한다.

### 11.7 협업

- [ ] 브랜치 전환 승인은 1회성. `git add -A` / `stash` 금지.
- [ ] 검토 요청엔 검토만. 구현은 명시적 동의 후.
- [ ] 제안은 `[선택 불필요]` / `[선택 필요]` 두 칸으로.
- [ ] 공용 스펙을 먼저 확정하고 개별 적용은 그다음.
- [ ] 후보는 글이 아니라 **그림**으로.
- [ ] 프로덕션 반영은 실행 직전 재확인.
- [ ] `CLAUDE.md`에는 **겪은 것만** 적는다. 규칙이 늘면 **기본값을 고칠 신호**로 읽는다.

## 부록 — 환경에서 배운 것 (Windows + OneDrive)

같은 환경을 계속 쓰신다면 그대로 재발한다.

- **저장소가 OneDrive 폴더 안에 있으면 네이티브 파일 작업이 깨진다.**
  `fs.cpSync`가 디렉터리를 복사하지 못하고(파일 0개 복사 + node 크래시) `expo prebuild`가 실패했다.
  `pnpm add`의 ENOENT도 같은 뿌리다.
  → **근본 해결은 저장소를 OneDrive 밖으로 옮기는 것**(예: `C:\dev\...`). 안 옮기면 클라우드 빌드를 쓴다.
- **새 프로젝트는 처음부터 OneDrive 밖에 만드는 게 좋다.** 아보카도는 이 결정을 미뤄서
  로컬 빌드를 통째로 포기했다.
- 콘솔이 CP949라 한글 출력이 깨진다 → 파일로 쓰고 읽는다.
- `adb`는 PATH에 없다(`%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`).
  기기가 안 붙은 상태에서 `logcat -d`를 부르면 **기기를 기다리며 멈춘다** → 먼저 `adb devices`.
- **adb에 기기가 안 뜨는 게 케이블 탓이 아닐 수 있다.** MTP는 붙어 있는데 ADB 인터페이스가
  없으면 USB 디버깅이 꺼진 것이다. 케이블은 멀쩡했다.
