## §1 왜 지금인가

애플 에디터의 7가지 채점 기준 중 🔴가 둘이다 — **접근성**과 **사용자 경험**.
사용자 경험(= 평점·리뷰)은 8일에 만들 수 없다. **접근성은 만들 수 있다.**
7기준 중 우리 손으로 뒤집을 수 있는 유일한 항목이라 꺼냈다.

⚠️ 목적이 지명 점수만은 아니다. 어휘 앱은 **글자를 크게 쓰는 사용자 비중이 실제로 있다**.
다만 마감이 지명에 걸려 있어 범위를 그 날짜에 맞춰 자른다.

## §2 실측 (2026-09-03)

```
누를 수 있는 것        359 개   ← Pressable + TouchableOpacity
  accessibilityLabel    18 개   (5%)

아이콘 전용 버튼       108 개   ← 안에 <Text> 없이 아이콘만 = VoiceOver 가 "버튼" 이라고만 읽는다
  라벨 있는 것           9 개
  🔴 라벨 없는 것       99 개 · 30 개 파일

fontSize 리터럴        636 개   ← FontSize 토큰은 16 개뿐
고정 height            198 개 · 53 개 파일
lineHeight 리터럴       83 개
numberOfLines          106 개
```

🔑 **이 숫자가 범위를 결정한다.** 글자가 있는 버튼은 VoiceOver 가 그 글자를 읽으므로
라벨이 없어도 최소한 동작한다. 문제는 **아이콘만 있는 99개**다 — 이것만 채우면
"모든 컨트롤에 이름이 있다"가 성립한다.

반면 Dynamic Type 은 **fontSize 636 + 고정 height 198** 을 손대야 한다. 5일에 불가능하고,
무리하면 레이아웃 회귀를 대량으로 만든다.

### B. 라벨 문구는 i18n 으로, 공용 키로 묶는다

99개를 낱낱이 번역하면 297개 문자열이 된다. 실제로는 **같은 말이 반복**된다
(닫기·삭제·재생·다음·이전·더보기·뒤로). **공용 키 30~40개로 묶고** 화면 고유한 것만 따로 둔다.

```
a11y.close / a11y.back / a11y.delete / a11y.play / a11y.pause /
a11y.next / a11y.prev / a11y.more / a11y.star / a11y.unstar / ...
```

⚠️ **`accessibilityRole` 도 함께 준다.** 라벨만 있고 역할이 없으면 VoiceOver 가
"두 번 탭하여 실행"을 안내하지 못한다. 아이콘 버튼은 `role="button"`.

### C. Dynamic Type 은 **고치지 않고 재기만 한다**

5일에 636개를 토큰화할 수 없다. 대신 **지금 무엇이 깨지는지 실측**한다.

- 설정 › 손쉬운 사용 › 디스플레이 및 텍스트 크기 › **더 큰 텍스트를 최대**로
- 대표 화면 8개(홈·단어장 목록·단어장 상세·단어 추가·플래시카드·퀴즈·결과·설정)를 열어
  **스크린샷으로 남긴다**
- 결과를 이 문서 §6 에 표로 적는다

🔑 **재는 것 자체가 산출물이다.** 지금은 큰 글자에서 무슨 일이 벌어지는지 **아무도 모른다**.
알고 나면 §6 을 정직하게 쓸 수 있고, 1월 작업의 범위도 그 표에서 나온다.

## §6 Dynamic Type 측정 결과 ✅ (2026-09-03 · 갤럭시 S22 실기)

`adb shell settings put system font_scale N` 으로 재고 **끝난 뒤 1.0 으로 되돌렸다.**
Android 의 `font_scale` 은 iOS Dynamic Type 과 같은 축이다(둘 다 앱이 지정한 sp/pt 에
곱해진다). 1.3 ≈ iOS 최대 **표준** 크기(XXXL), 1.8 ≈ **손쉬운 사용** 크기대.

### 결론 — 표준 크기는 통과, 접근성 크기에서 깨진다

| 화면 | 1.3× (표준 최대) | 1.8× (손쉬운 사용) |
|---|---|---|
| 홈 | 🟢 통과 · `Day 1: 4/8 암기 50%` → `Day 1..50%` 로 축약 | 🟡 곳곳이 `…` 로 줄지만 레이아웃은 유지 |
| 단어장 목록 | 🟢 통과 | 🟢 통과 — 카드가 늘어나며 전부 읽힘 |
| 단어장 상세 | 🟢 통과 | (미측정) |
| 카드 학습 앞면 | 🟢 통과 | 🟢 통과 |
| **카드 학습 뒷면** | 🟢 통과 | 🔴 **한국어 예문 번역이 사라짐** + **판정 버튼이 카드를 파고듦** + 버튼 글자 잘림 |
| **예문 학습** | (미측정) | 🔴 **문제 문장이 잘림** — "A [?] crossed the still" 에서 `pond.` 가 사라진다 |

🔑 **1.3× 까지는 문제가 없다.** 글자가 커지면 카드도 함께 커지도록 잡혀 있어서,
축약(`…`)은 생겨도 잘리거나 겹치는 곳이 없었다. 예상보다 좋았다 — `fontSize` 리터럴
636 개를 손대지 않고도 표준 Dynamic Type 은 이미 통과한다.

🔴 **1.8× 에서 무너지는 곳은 "카드 높이가 내용보다 먼저 정해지는" 두 화면**이다.
학습 카드와 예문 카드는 화면 높이에서 역산한 상한을 쓰는데, 글자가 그 상한을 넘으면
늘어나지 않고 잘린다. [[project_example_card_layout]] 의 E4·E5 와 같은 뿌리다.

### 그래서 §5 에 무엇을 체크하나

**Dynamic Type 은 체크하지 않는다.** 표준 크기가 통과한다고 체크하면, 에디터가
손쉬운 사용 크기로 켰을 때 카드 학습이 깨지는 것을 본다 — 과장이 역효과가 되는
전형적인 자리다. §6 에는 위 표를 그대로 적어 **어디까지 되는지**를 말한다.

### ⏭️ 1 월에 할 일 (범위가 여기서 나왔다)

636 개를 전부 토큰화할 필요가 없다. **카드 높이를 역산하는 두 곳**만 고치면 1.8× 도
통과한다 — 학습 카드(`features/study/flashcards`)와 예문 카드
(`features/study/examples`). 나머지는 이미 늘어난다.

## §6-2 VoiceOver 실기 검증 ✅ (2026-09-03 · 갤럭시 S22)

**빌드 없이 됐다.** JS 만 바뀌었으므로 Metro 번들 교체로 반영된다(개발 빌드 필요).
TalkBack 을 켜는 대신 **접근성 트리를 직접 덤프**했다 — 기기 설정을 건드리지 않고,
스크린리더가 읽을 이름을 화면마다 전수로 볼 수 있다.

```
adb shell uiautomator dump /sdcard/ui.xml      # ⚠️ Git Bash 는 /sdcard 를
adb pull /sdcard/ui.xml                        #    Windows 경로로 바꾼다 → PowerShell
```

| 화면 | 클릭 가능 | 🔴 읽을 수 없음 | ⚠️ 글리프 섞임 |
|---|---|---|---|
| 홈 | 20 | **0** | 7 |
| 단어장 목록 | 15 | **0** | 5 |
| 단어장 상세 | 40 | **7 → 0** | 6 |
| 카드 학습 | 7 | **0** | 2 |
| 큐레이션 | 19 | **0** | 4 |

붙인 이름이 이렇게 읽힌다: `quiver 별표 하기` · `quiver 안 외운 단어로 표시`(이미 외운
단어라 반대 문구) · `bramble 외운 단어로 표시` · `별표 단어만 보기` · `나의 단어장 관리`.

### 🔴 여기서만 나온 결함 — 발음 버튼 11 곳 전부

`SpeakerButton` 의 `accessibilityLabel` 이 **선택 prop** 이라 호출자가 안 넘기면
`undefined` → RN 이 자식(`<Ionicons>` = 아이콘 폰트 `<Text>`)을 대신 읽어
**글리프 코드포인트가 이름이 된다**(`content-desc=""`). 호출자 11 곳이 전부
안 넘기고 있었다 = 앱의 모든 발음 버튼. 기본값을 고쳐 해결(`387a31c`).

🔑 **소스 스캔으로는 구조적으로 못 잡는다** — 파일에 `accessibilityLabel` 이라는
글자가 있으니 "라벨 있음" 으로 세어 버린다.
🔴 **콘솔에는 빈 문자열로 보인다.** 처음엔 "이름 없음 0" 으로 세었고, `repr()` 을
찍고서야 사설영역(U+E000~U+F8FF) 문자인 걸 알았다. **값을 추측하지 말고 찍을 것.**

⚠️ 남은 "글리프 섞임"은 `"[글리프] 카드 학습"` 처럼 뒤에 진짜 글자가 있어 읽히긴 한다
(아이콘과 글자를 함께 담은 버튼을 RN 이 이어 붙인 것). 우선순위 낮음.

## §7 검증

- **실기**: iOS 실기에서 VoiceOver 를 켜고 §3-A 의 흐름 1~4 를 손끝으로 훑는다.
  "버튼"이라고만 읽히는 곳이 남아 있으면 실패.
  ⚠️ 시뮬레이터가 아니라 실기 — 이전에 *"dev 에서 확인했다"가 검증이 아니었던* 전례가 있다.
- **자동**: 아이콘 전용 버튼에 라벨이 없으면 걸리는 소스 검사 테스트.
  🔴 **주석까지 훑지 않게 할 것** — 소스 검사 테스트가 주석 이력에 걸린 전례가 있다.
- **Android**: TalkBack 도 같은 속성을 읽는다. iOS 를 먼저 맞추고 한 바퀴 확인.
