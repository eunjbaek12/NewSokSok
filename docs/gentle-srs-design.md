# Gentle SRS — 설계 문서 (보류 / parked)

> **상태: 보류 — 지금 구현하지 않음.** 나중에 꺼낼 카드로 남겨두는 설계 기준선.
> 결정 배경은 아래 §0을 먼저 볼 것.

---

## 0. 상태 & 결정 (먼저 읽기)

- **결정(2026-07):** **지금 짓지 않는다.**
- **이유:** 이 앱의 병목은 **발견(discovery)** 이다(DAU 10명 미만, 구독 0, 활성화 60%는 양호).
  gentle SRS는 **리텐션·구독 지렛대**라, *남길 사람*이 거의 없는 지금은 순서가 거꾸로다.
  10명한테 완벽한 복습을 줘도 사업적으로 0 변화. 게다가 이 기능의 실제 효과 엔진은
  **홈 원탭 + 알림(Phase 3)** 인데, Phase 1만으론 반쪽이다.
- **언제 꺼내나:** DAU가 유의미하게(수백+) 늘고 **리텐션이 실제 병목**이 됐을 때. 그때도 **최소 버전부터**.
- **지금 정당한 유일한 사유:** 크레딧/완성도(레딧 심사·리뷰에서 "SRS 있냐?"에 정직하게 "예, 부드러운 버전"이라
  답하려면). 그 경우에도 **최소 버전**(§9)만, 풀 버전은 아님.
- **최종 설계 방향:** **"복습" = 기존 필터 하나** (채점 버튼 없음). 아래 전체가 그 기준선이다.
  (초기 검토의 "복습 세션 전용 3-way 채점 버튼" 안은 **폐기** — 앱과 이질적이고 마찰. §3 참고.)

## 1. 배경 & 문제 (왜)

- 진지한 어휘 앱은 거의 다 SRS를 갖고 있다(= table stakes). 없으면 감점, 있어도 그 자체론 가점 아님.
- 이탈의 진짜 원인은 SRS의 *효과*가 아니라 **백로그(밀린 복습)와 죄책감**:
  하루 빠지면 밀린 게 한꺼번에 쏟아짐 → 벽 → 앱 열기 무서움 → 죄책감 → 조용한 이탈.
  (Anki "week 3 이탈", WaniKani "며칠 결석→400~600 백로그" 등 커뮤니티 근거 다수.)
- **우리의 승부처는 "SRS를 넣느냐"가 아니라 "Anki가 못 하는 부드러운·자동화된 SRS"** 다.
  이 앱의 따뜻한(아보카도) 톤과도 맞는다.
- **타겟:** Anki가 어렵거나 부담스러워 튕겨나온 캐주얼·초보. **비타겟:** Anki/WaniKani 정착 하드코어(뺏으려 하지 않음).

## 2. 설계 원칙 (anti-Anki)

| # | 원칙 | 의미 |
|---|---|---|
| P1 | **백로그 벽 금지** | 일일 노출에 상한. 총량("543개") 안 보여줌 |
| P2 | **결석 무처벌** | 며칠 빠져도 한꺼번에 안 쏟아짐. 복귀는 "환영", "밀림" 아님 |
| P3 | **기계 숨김** | 간격 숫자·설정·스케줄 내부 노출 안 함 |
| P4 | **최소 마찰** | 복습 전용 새 UI를 만들지 않는다 — 기존 카드학습을 그대로 씀 |
| P5 | **죄책감 없는 톤** | 빨간 overdue 배지·스트릭 압박 없음. 부드러운 카운트만 |
| P6 | **자명함 우선** | 설명이 필요하면 → 설명을 붙이지 말고 UI를 더 단순하게 |

## 3. 핵심 접근 — "복습"은 필터 하나 (채점 버튼 아님)

**폐기된 안:** 복습 세션 전용 채점 버튼(다시/기억남/쉬워요 3-way). → 앱과 이질적, 문구 충돌
("다시 볼게요"는 원래 카드학습의 '암기 안 됨' 표시), 좌우 스와이프(2방향)와 안 맞음.

**채택안:** 기존 학습 범위 필터(`전체 / 미암기 / 암기 / 오답 / 최근 / 별표`)에 **`복습` 하나를 추가**한다.
- 복습 = **기존 카드학습/퀴즈를 "복습" 범위로 돌리는 것.** 새 화면·새 채점 버튼 0.
- 오답·별표 필터와 똑같은 패턴이라 사용자가 이미 아는 UX.
- 난이도 신호는 **앱이 이미 가진 것**으로 대체(§4) — 별도 등급 입력 없음.

## 4. 스케줄 모델 — 전부 자동 (채점 버튼 없이)

복습 전용 입력 없이, 앱이 이미 가진 신호만으로 각 단어의 재등장 간격을 조절한다.

### 4.1 쓰는 신호 (전부 기존 + 1개 신규)

| 신호 | 출처 | 쓰임 |
|---|---|---|
| **외웠어요 / 다시 볼게요** | 카드학습 좌우 스와이프(`flashcards.memorized`/`reviewBtn`) | 성공/실패 |
| 오답 횟수 | 퀴즈 `wrongCount` | 어려움 정도 (우선순위 가중) |
| 별표 | `isStarred` | 우선순위 |
| 암기 여부 | `isMemorized` | 복습 후보 = 외운 것 |
| **마지막 학습 시각** | **신규 `lastReviewedAt`** (볼 때마다 자동 갱신) | 재등장 타이밍 |

### 4.2 숨은 간격 사다리 (사용자에게 안 보임)

```
성공(외웠어요)이 쌓일수록 재등장 간격이 늘어난다 (예): 3일 → 10일 → 30일 → 90일
실패(다시 볼게요/퀴즈 오답) → 간격이 한 칸 당겨짐 (자주 등장)
```

- **외웠어요 반복 → 간격 증가 → 쉬운 단어가 자연히 졸업(안 뜸).** "쉬운 건 오래돼도 안 보고 싶다" 해결.
- **간격 숫자·사다리는 전혀 노출하지 않는다**(P3).
- 정밀 SM-2/FSRS 아님 — **근사(gentle) SRS.** 근사라서 앱과 완전 일관·마찰 0이 이득.

### 4.3 "복습" 후보 선정

```
후보 = isMemorized = true
       AND (lastReviewedAt IS NULL OR now − lastReviewedAt ≥ 그 단어의 현재 간격)
정렬 = 위험한 것 우선: 오래된 순 → wrongCount 높은 순 → isStarred
노출 = min(후보 수, DAILY_CAP)   // 예: 20
```

- **핵심:** 기준은 **"마지막 학습 후 경과"**. "외운 후 경과"로 하면 복습해도 필터에서 안 빠져
  같은 단어 무한 반복 → `lastReviewedAt` 자동 갱신이 이 기능의 성패를 가름.

### 4.4 결석 처리 (P2)

- due가 쌓여도 UI는 상한(20)까지만. "많이 밀림" 숫자 안 보여줌.
- 간격은 결석으로 리셋되지 않음. 100일 밀린 단어도 그냥 "due"일 뿐, 정상 복습.
- 복귀 문구: "돌아오셨네요 🥑 오늘은 N개만 볼까요?" (밀림/실패 언어 금지).

### 4.5 "다시 볼게요" 규칙 (복습 맥락) — 못 박기

- 복습 중 "다시 볼게요"는 **암기를 해제하지 않는다**(isMemorized 유지). **재등장 간격만 당긴다.**
- 이유: 복습하다 하나 틀렸다고 미암기로 강등되면 사용자가 놀란다. UI에 안심 문구 노출
  ("복습에선 '다시 볼게요'를 눌러도 암기가 풀리지 않아요").

## 5. 사용자 경험

### 5.1 두 진입 경로 (원탭 ≠ 필터) — 깊이가 다름

같은 목적지(기존 카드학습)로 모이되, 깊이가 다르다. **이 둘을 한 화면 흐름으로 붙이면
"원탭인데 왜 또 고르지?" 모순이 생긴다** — 반드시 분리.

- **경로 A · 원탭:** 홈 "복습 · N" 카드 → **(설정/필터 화면 건너뜀)** → 카드학습 → 완료.
  매일 돌아오는 저마찰 훅. **리텐션 엔진은 사실상 이것.**
- **경로 B · 필터:** 맞춤학습 → 학습 범위에서 "복습" 선택 → 카드학습 → 완료.
  직접 범위를 조절하고 싶은 파워 유저용.

### 5.2 홈 진입점 (경로 A)

- 홈에 "오늘의 복습 · N" 히어로 카드. `N` = due(상한 표시). 부드러운 카운트, **빨간 배지·"밀림" 금지**(P5).
- 탭 = 설정 없이 바로 카드학습. "고르는 화면 없음"을 카드에 명시.
- ⚠️ 홈에 이미 학습 진입점이 많음(맞춤/오답/별표 + 단어장). **복습을 '추가'하면 결정 피로** — 자리 정리 고려.

### 5.3 콜드스타트 (due 0개)

- 신규/라이트 유저는 한동안 복습할 게 없다 → **"복습 0"으로 죽은 자리**가 되면 안 됨.
- 0개면 큰 카드 대신 **격려 상태**: "🌱 아직 복습할 단어가 없어요 · 단어를 외우면 잊을 때쯤 모아 드려요".
- **최소 임계**(외운 지 3일+ 몇 개) 넘어야 복습 등장. 초반엔 "새 단어에 집중" 유도.

### 5.4 "복습" 필터 구분 (경로 B) — "암기"와 헷갈림 방지

- 다른 필터는 전부 정적 속성인데 "복습"만 **동적/계산된** 필터라 성격이 다르다. 특히 **"암기"와 헷갈림**.
- 대응: 필터 목록에서 **"추천" 구역으로 분리** + **부제 상시 노출**("잊을 때 된 단어 · 암기=외운 것 전부와 다름").
- 이름은 "복습"이 가장 자연스러우니 유지하되 의미를 계속 보여준다.

### 5.5 세션 = 기존 카드학습 그대로

- 기존 플래시카드/퀴즈 화면·버튼("다시 볼게요 / 외웠어요") 재사용. **새 채점 UI 0.**
- 뒤에서 `lastReviewedAt` 자동 갱신(§4). 완료는 "다음 200개 더" 없이 "오늘은 충분해요" 톤(P1/P5).

## 6. 데이터 모델

`words`(로컬)에 최소 추가:

| 컬럼 | 타입 | 용도 |
|---|---|---|
| `lastReviewedAt` | INTEGER (epoch ms, nullable) | **핵심.** due 판정 기준. null = 미복습 |
| `reviewSuccessCount` | INTEGER DEFAULT 0 | 성공 누적 → 간격 사다리 위치 근사 |

- `difficulty` 컬럼도, `reviewStage` 명시 컬럼도, 3-way 채점 UI도 **필요 없음**(성공 카운트로 간격 근사).
- 마이그레이션: 버전 018 신설, 기존 스텝 수정 금지. **새 컬럼 시 `features/vocab/db.ts` rowTo* 매퍼도 동기 갱신**(과거 누락 사례).
- 재활용: `isMemorized`·`wrongCount`·`isStarred`·`memorized_log`(초기 시드).

## 8. 효과성 & 리스크 (솔직히)

- **효과의 실제 엔진 = 홈 원탭 + 알림(Phase 3).** 필터는 저관여라 그 자체론 사람을 안 부른다.
  알림을 너무 미루면 핵심 가치("잊을 때 다시 만난다")가 반쪽 — 우연히 앱 열어야만 작동.
- **기존 대비 증분이 작다:** 이미 맞춤학습(암기)·오답·별표로 복습 가능. 더해주는 "타이밍 지능"이 invisible이라 체감이 약함.
- **세그먼트:** 하드코어는 이미 Anki. 캐주얼은 SRS를 강하게 원치 않음 → "있으면 쓰는" 미지근한 포지션.
- **결론(재확인):** 좋은 리텐션 카드지만 **0→1(발견)을 만드는 카드는 아니다.** §0 참고.

## 9. 범위 (만들 때)

**최소 버전 (크레딧/완성도용, 반나절~1일 규모)**
- migration 018: `lastReviewedAt`(+`reviewSuccessCount`) + db.ts 매퍼
- "복습" 필터 하나(§5.4) + 후보 선정(§4.3, lastReviewedAt 기준)
- 기존 카드학습 재사용 + 완주 시 lastReviewedAt 갱신
- 홈 원탭 카드(경로 A) + 콜드스타트 0개 상태(§5.3)
- "다시 볼게요" 암기 유지 규칙(§4.5)

**후속 (풀 버전, 리텐션이 병목 될 때)**
- 성공 카운트 기반 간격 사다리 정교화(§4.2)
- 클라우드 동기화(Phase 2)
- 부드러운 복습 알림(Phase 3) — 습관 루프
- 필터 세부 옵션(오래된 순/어려운 것/단어장별)

## 10. 나중에 결정할 것

1. 홈 진입점 과다 정리(맞춤/오답/별표 + 복습 공존) 방식
2. `DAILY_CAP` 기본값(20?) · 간격 사다리 수치(`3/10/30/90`?)
3. 알림(Phase 3)을 얼마나 앞당길지 — 효과의 실제 엔진이라 순서가 중요
4. 로컬 전용 캐비앗(기기 변경 시 진도 유실) 안내 방식
5. 미암기 단어 포함 옵션 여부(기본은 isMemorized=true만)
