# 예문 학습이 묻지 않고 AI 한도를 쓰던 것 — 설계

2026-09-02 · 목업: `예문 학습 차감 설계안` (Artifact)

---

## §1 무엇이 문제인가

예문 없는 단어가 섞인 단어장에서 「예문 학습」을 누르면, 앱은 **묻지 않고** 그 단어
전부를 배경에서 AI로 채운다. `screen.tsx:311`

```
all = 필터에 걸린 단어
  ├ ready   = 예문 있고 빈칸 가능        → 바로 출제
  └ missing = 예문 없음                 → startBackgroundEnrich(missing)
                                          동시성 3 · 상한 없음 · 단어당 한도 1
```

화면에는 「AI 예문 생성 중 3/12」 배너만 뜬다. **차감 이야기는 없다.**

🔴 **한 번의 탭이 하루치를 넘긴다.** Free 한도는 하루 50단어다.

```
100단어 덱 · 예문 없는 단어 80개
  → 50개 채우고 한도 소진
  → 남은 30개는 뜻만 돌아와 예문 없이 끝남
  → 사용자가 본 것은 진행 배너 하나
```

🔑 문제는 **알림이 아니라 동의**다. 배너에 차감 문구를 넣어도 이미 나간 뒤다.

---

## §2 세우는 규칙

> **AI가 단어를 채우는 일은 언제나 사용자가 누른 버튼 뒤에서만 일어난다.**

채우기·사진 스캔·AI 생성이 이미 이 규칙을 지킨다. 예문 학습만 예외였다.

따라오는 것 하나: **거절이 실패가 되면 안 된다.** 「예문 학습」이 한 약속은 학습이지
생성이 아니다. 예문 있는 단어가 8개면 8개로 학습이 성립한다.

---

## §3 대상 — `isBareWord` 를 그대로 쓸 수 없다

🔴 **두 집합이 다르다.**

| | 정의 | 조건 |
|---|---|---|
| `isBareWord` (1.6.2 채우기) | 뜻은 있고 발음·예문·정의가 **모두** 빔 | AND |
| 예문 학습이 필요로 하는 것 | 예문이 없음 | `!exampleEn` |

실측(2026-09-02, 전체 사용자·살아 있는 단어):

```
예문 없는 단어 1,672
  ├ 1,212  isBareWord 가 잡음
  └   460  못 잡음 (발음·정의는 있고 예문만 없음)   ← 28%
```

그래서 「배너를 누르면 기존 채우기 시트」로 두면 **12개라고 알린 뒤 4개만 채워진다.**
몰래 차감을 고치려다 새 거짓말을 만드는 셈이다.

✅ **시트는 그대로 쓰되 대상만 갈아 끼운다.**

- 예문 학습에서 열면 → 대상 `!exampleEn`, 제목 「예문 없는 단어 채우기」
- 단어장에서 열면 → 대상 `isBareWord`, 제목 「뜻만 있는 단어 채우기」

모양·차감·부분 채움 판정·고르기 화면·얼굴 판정(`face.ts`)은 **한 벌**이다.

⚠️ `detect.ts` 주석의 "OR 로 하면 대상이 폭증한다"는 경고는 **단어장에 상시 뜨는
배너**에 대한 것이다. 목적이 예문인 화면에서 예문 없는 단어를 세는 것은 오히려
정확한 대상이다.

## §4 화면

### 상태 A — 예문 있는 것 8 · 없는 것 12

학습은 **그냥 시작한다.** 위에 배너 한 줄.

```
● 예문 없는 단어 12개                    ›  ✕
  채우면 함께 학습할 수 있어요
```

배너를 무시하면 그것으로 끝이다 — 차감 없음. 누르면 채우기 시트가 뜬다.

### 상태 B — 예문 있는 것 0

```
        📄
  예문이 있는 단어가 없어요
  12개를 채우면 시작할 수 있어요

  [ 12개 채우기 ]   [ 돌아가기 ]
```

🔑 「채워야 시작된다」는 **여기서만** 나온다. 규칙을 새로 만든 게 아니라 §2에서 저절로
따라온다.

### 시트 (배너를 눌렀을 때)

1.6.2 채우기 시트와 같은 틀. 문구만 예문 쪽으로.

```
예문 없는 단어 채우기
예문과 함께 비어 있는 발음·정의도 채웁니다. 이미 적어둔 것은 그대로 둡니다.

  예문 없는 단어          12개
  지금 채울 수 있는 수     12개

[ 12개 채우기 ]
  채울 단어 고르기
```

## §5 차감 — 지금 흐름 그대로 (2026-09-02 확정)

**단어 검색과 똑같다: 호출할 때 차감하고, 실패하면 환불한다.** 새로 만들 것이 없다 —
같은 `enrichWord` 를 타므로 서버(`supabase/functions/enrich-word/index.ts`)가 이미 한다.

환불이 도는 경우 셋:

| 조건 | 응답 | 처리 |
|---|---|---|
| `isReal === false` 또는 뜻이 빔 | 404 `not_found` | 환불 |
| 폭주 산출물 | 500 `upstream_failure` | 환불 |
| 상류 실패 | 500 | 환불 |

⚠️ **예문이 안 온 경우는 환불 대상이 아니다.** 뜻이 있으면 200이고 차감이 남는다.
그런데 실측하니 **일어나지 않는다** — `full` 캐시 최근 20,000행 중 예문이 빈 것 **0건**.
일어나지 않는 일을 위해 자동완성과 규칙을 가를 이유가 없다. 그대로 둔다.

🔴 세는 법은 갈라야 한다. 지금 `useBareFill` 은 **발음만 채워져도 1로 센다.** 예문
학습에서는 **예문이 채워진 것만** 세야 「12개 채웠어요」가 거짓이 되지 않는다.

## §6 채운 뒤 흐름 — 시트가 닫힐 때 합류

세 갈래가 있었다.

| | 문제 |
|---|---|
| 진행 중 하나씩 합류 (지금 동작) | 학습 도중 총 문항이 슬금슬금 는다. 진도 표시가 흔들린다 |
| 다음 진입 때 포함 | 「채우기」를 누른 의도가 "지금 하고 싶다"인데 나갔다 다시 들어와야 한다 |
| **시트가 닫힐 때 한 번에 합류** ✅ | 경계가 뚜렷하다 |

채우기는 **시트 안에서** 일어나고 시트는 학습 화면 위에 뜬다. 시트를 닫는 순간이
자연스러운 경계다 — 진행 중 슬금슬금이 아니라 한 번에 늘고, 사용자는 「5개가
늘었어요」로 확인한다.

⚠️ **현재 배치는 건드리지 않는다.** `studyBatchSize` 로 나뉜 배치 한가운데를 바꾸면
남은 문항 수가 어긋난다. 합류는 **다음 배치부터**.

## §7 한도가 모자랄 때 — 이미 있는 것을 그대로

새로 설계할 것이 없다. 시트가 「지금 채울 수 있는 수」를 따로 보여주고, 한도가 대상을
자르면 `face.ts` 가 `quota` 얼굴로 간다.

| 상황 | 화면 |
|---|---|
| 한도 5 남음 | 대상 12 · 가능 5 를 따로 적고 버튼이 「5개 채우기」로 줄어든다. 「나머지 7개는 내일 이어서」 |
| 한도 0 | 「0개 채우기」는 누를 수 없다 → **광고가 주 버튼**, 부차는 「내일 이어서」 |
| 채운 뒤 잘림 | 「5개를 채웠어요 / 아직 7개에 예문이 없어요」 + 광고·내일·Pro. **학습은 5개 늘어난 채로 계속** |

### 부분 한도 + 광고 (2026-09-02 추가)

🔴 **지금은 광고 경로가 한도 0 일 때만 열린다** — `BareWordsSheet.tsx:91` 의 `!canFill`.
5개가 남아 있으면 광고는 아예 안 보이고 「나머지 7개는 내일 이어서」만 뜬다. 그래서
12개를 다 채우려면 **5개 채우고 → 벽에 부딪히고 → 그제서야 광고** 두 단계를 밟는다.

✅ **한 번에 끝낼 길을 연다.** 무료 경로는 주 버튼 그대로 두고, 그 아래 「광고 보고 12개
다 채우기」를 놓는다. 광고가 **주 버튼이 되는 것은 한도 0 일 때뿐** — 달리 방법이 없을
때만이라는 규칙이 이미 서 있고, 그것을 깨지 않는다.

🔴 **개수를 정직하게 말할 것.** 보상은 20개다. **남은 한도 + 보상을 넘는 수를 약속하면
안 된다.**

| 대상 | 남은 한도 | 버튼 |
|---|---|---|
| 12 | 5 | 5+20=25 ≥ 12 → 「12개 다 채우기」 |
| 30 | 5 | 5+20=25 < 30 → 「**25개** 채우기」 |

이 저장소는 이미 한 번 그렇게 틀렸다 — `hasRewardViewsRemaining` 으로 횟수를 말해
**못 받을 보상을 약속**한 건([[project_rewarded_modal_copy_split]]). 광고 시청 상한
(Free 2회/일)에 걸리면 이 버튼은 아예 내지 않는다 — 기존 `canWatchAd` 판정을 그대로 쓴다.

---

🔴 **`partial` 과 `quota` 를 섞지 말 것.** 고르기에서 일부만 골라 다 채웠을 때
「오늘 광고 혜택을 모두 사용했어요」가 뜬 적이 있다 — 한도가 35개 남아 있었는데도.
남은 것이 있다고 해서 한도가 없는 것은 아니다. 예문 학습 배너도 **같은 판정을 그대로**
쓴다.

## §8 범위 밖 — 빈칸을 못 뚫는 단어

예문에 표제어가 **어떤 형태로도 안 나오는** 부류가 있다. 활용형 미스매치가 아니라
찾을 대상이 없다.

```
올리다 :: 그는 자신의 연구 논문을 저명한 학술지에 성공적으로 게재하여 …
遣る   :: 彼は日夜を問わず、研究室に籠もり、ひたすら難解な数式と格闘しておった。
```

빈칸을 뚫을 수 없어 출제에서 빠지는데 **조용히** 빠진다. 20개짜리 덱에서 8개만 나와도
사용자는 이유를 모른다.

이건 이 스펙의 문제가 아니라 **AI 생성 프롬프트 문제**이고 `backlog-examples-enrich.md`
P6 에 이미 있다. 여기서는 하나만 다룬다:

⚠️ **상태 B 의 문구가 거짓이 되는 경우.** 예문은 다 있는데 전부 빈칸을 못 뚫어 R=0 이면
「예문이 있는 단어가 없어요」는 틀린 말이다. 그 경우를 갈라 다른 문구를 낸다.

| `i18n/locales/{ko,en,es}.json` | 예문 쪽 문구 |

✅ **선행 작업은 끝났다** — 채우기가 손으로 적어 둔 칸을 덮어쓰던 것을 먼저 떼어
고쳤다(`9756de7`). 대상을 넓히면 460행이 걸리던 자리다.

### 구현하며 갈린 것 넷

1. **컴포넌트가 아니라 훅**(`useExampleFill`). 예문 학습 화면은 출제할 것이 없으면 이른
   return 으로 다른 트리를 그린다 — 배선을 컴포넌트로 두면 채우다가 첫 단어가 들어오는
   순간 그 갈래를 넘어가며 **언마운트돼 진행 배너가 통째로 사라진다.**
2. **채우는 중에는 학습을 열지 않는다.** 상태 B 에서 첫 단어가 들어오자마자 열면 그 한
   개로 묶음 크기가 굳어(「전체」 설정) 이후 단어가 한 개짜리 묶음으로 쏟아진다. 배치가
   끝난 뒤 한 번에 연다 — §6 의 "한 번에 합류"와 같은 규칙이다.
3. **합류로 지금 묶음이 늘어나면 세션을 끝내지 않는다.** 예문 있는 단어 8개로 시작한
   세션(묶음 크기 20)에 12개가 붙으면 그것은 다음 묶음이 아니라 이 묶음의 9번째 문항이다.
   여기서 끝내면 방금 채운 12개가 이번 세션에서 통째로 빠진다. 그래서 완료 문구도
   「다음 묶음부터」가 아니라 **「지금 묶음이 끝나면 이어서 나와요」**다 — 두 경우 모두 참이다.
4. **「전체」 묶음 크기를 세션 시작 시점에 굳힌다**(`allBatchSize`). 안 굳히면 채울 때마다
   묶음 크기가 따라 늘어 지금 묶음의 남은 문항 수가 바뀐다(3/8 이 3/20 이 된다).

### ✅ 실기 검증 (2026-09-02 · Galaxy S22 · dev 빌드 + adb)

검증용 단어장을 심어 세 갈래를 다 밟았다. **「뜻만 있는 단어」와 「예문 없는 단어」가 갈리는
것을 화면으로 확인했다** — 같은 단어장에서 단어장 배너는 「3개」, 예문 학습은 「7개」였다.

| 확인 | 결과 |
|---|---|
| 상태 B → 채우기 → 학습이 열림 | ✅ 「7개를 채웠어요」 → 1/7 |
| 상태 A (예문 3 · 없는 것 4) | ✅ 학습이 그냥 시작(1/3)되고 배너만 뜸 · 차감 0 |
| 묶음 경계 | ✅ 채우는 동안 3/3 유지 → 마지막 카드 뒤 **4/7 로 이어짐** |
| 고르기 화면 왕복 | ✅ 확정하면 단어장이 아니라 **학습 화면으로 복귀**, 곧바로 채우기 시작 |
| 시트·배너 문구 | ✅ 「예문 없는 단어 채우기」·「예문 없음」·「지금 묶음이 끝나면 이어서 나와요」 |
| **부분 한도 + 광고** | ✅ 잔량 2·대상 4 → 「광고 보고 **4개 다** 채우기」(4 ≤ 2+20) · 무료 경로가 주 버튼 · 「나머지는 내일」 줄은 안 나옴 |
| 광고 뒤 동작 | ✅ 보상 뒤 **시트가 닫히고 곧장 4개를 채웠다** — 약속한 개수 그대로 |

**실기에서만 나온 결함 둘 — 둘 다 고쳤다.**

1. 🔴 **7개를 채웠는데 학습에 4개만 들어왔다.** `useBareFill` 이 `updateWord` 를 던져만
   놓고(`void`) 큐가 비는 순간 "끝났다"를 알린 탓에, **마지막 세 건의 저장이 도착하기 전에**
   합류가 계산됐다. → 배치의 `finally` 에서 저장을 모두 기다린 뒤 결과를 알린다. 재검증에서
   7/7 이 됐다. (결과를 보고 무언가를 세는 화면은 전부 이 경계를 믿는다.)
2. 🔴 **결과 배너가 떠 있는 동안 예문 문장이 잘렸다.** 로그로 값을 찍어 보니 문장 칸이
   143dp → **51dp** 로 줄었고, 가장 작은 글자(16dp)로도 두 줄(58dp)이 안 들어갔다. 크기
   엔진은 잘못이 없다 — 0→1→2→3 까지 이미 다 줄인 뒤였고 그 아래로는 줄이지 않기로 한
   결정이다(`sentence-size.ts`). → **결과 배너를 8초 뒤 자동으로 거둔다.** 성과는 몇 초면
   읽히고 행동(광고·내일·Pro)은 시트에 그대로 있다. 진행 배너는 그대로 둔다.

**광고 경로는 서버 값으로 확인했다** — `used 25 → 29`(약속한 4개가 정확히 차감),
`bonus 0 → 20`(보상), `reward_views 0 → 1`. 잔량은 `getQuotaLeft` 에 오프셋을 임시로
주입해 만들었고(실제 한도를 태우지 않으려고) 검증 뒤 되돌렸다.

🔑 광고가 **두 갈래로 갈리는 것**을 확인했다 — 잔량 0 에서 본 광고는 시트를 ①의 얼굴로
되돌리고(어느 것을 채울지 다시 고르게), 「광고 보고 N개 채우기」는 **약속했으므로 곧장
채운다.** 약속한 문장이 다르면 다음 동작도 달라야 한다.

### 🔴 실기 결함 셋째 — 채우는 동안 화면이 채우기를 또 권했다 (2026-09-02)

상태 B(예문 있는 것 0)의 화면이 **`fillUi.running` 을 아예 보지 않았다.** 배너만 진행
얼굴로 바뀌고 그 아래 아이콘·제목·설명·버튼은 채우기 전 그대로였다 — 「채우는 중 · 0/7」
바로 밑에 「7개를 채우면 시작할 수 있어요」와 **[7개 채우기]** 가 서 있었다.

한 자리에서 셋이 어긋난다:

1. **눌러도 아무 일이 없다.** 버튼 → 시트 → [N개 채우기] 는 `useBareFill` 의 재진입
   가드(`abortRef.current`)에 걸려 조용히 return 한다. 시트만 닫히고 끝이다.
2. **고른 것이 증발한다.** 그 시트의 [채울 단어 고르기] 로 갔다 오면 `takePendingFill` 이
   선택을 **읽으면서 비우고**, 이어지는 `fill()` 이 같은 가드에 걸린다. 핸드오프는 이미
   소비됐으니 재시도 경로도 없다. 채우는 중에 시트로 들어가는 문은 ①의 버튼 하나뿐이다.
3. **숫자 둘이 반대로 움직인다.** 배너는 `1/7 → 2/7` 로 올라가는데 제목·설명·버튼은
   `targets.length` 파생이라 `7 → 6 → 5` 로 내려간다. 마지막 저장이 도착하고 `running` 이
   내려가기 전 한 프레임에는 `canFill` 이 false 라 **「빈칸을 만들 수 없어요 / 설정 변경」이
   번쩍**이기까지 한다(전부 채웠으니 `unblankable` 이 성립한다).

**고친 방식 — 진행 중에는 숫자를 배너 한 곳에서만 센다.** `running` 이면 제목·설명을
대상 수와 무관한 고정 문구(`examples.fillingTitle` / `fillingDesc`)로 바꾸고 주 버튼을
내지 않는다. 행동은 배너의 [중단] 하나다. ②는 문이 닫히면서 같이 막힌다.

🔑 **버튼을 지우지는 않는다.** 결과 배너(중단·한도·못 찾음)는 8초 뒤 스스로 사라지고 이
갈래는 권유 배너를 내지 않으므로(`idleBanner: false`), 그때는 이 버튼이 채우기로 가는
유일한 길이다. 감추는 것은 **채우는 동안만**이다.

## §10 배너가 카드를 먹던 것 — 칩으로 접는다 (2026-09-02)

§9 에서 결과 배너를 8초 뒤 거두기로 했지만 그것은 증상만 덮은 것이었다. 은정님이 짚었다 —
「그 배너가 떠있는 동안 계속 카드가 작아진 상태로 나올테니까 별로인것같아.」 재어 보니
**짐작보다 나빴다.**

### 10-1. 재어 본 것 — 카드가 내줄 수 있는 것은 89dp뿐이다

배너는 `header` 안에 산다. 헤더가 커지면 `body` 가 밀리고, `body` 안에서 `cardArea` 만
`flex:1` 이라 **손실을 전부 카드가 받는다**(선택지는 `flexShrink:0` 으로 자리를 먼저 확보한다 —
이전 회귀의 처방이라 건드릴 수 없다).

| | 값 |
|---|---|
| 무배너 카드 | 229dp |
| 카드 바닥(`CARD_MIN_HEIGHT`) | 140dp |
| **카드가 내줄 수 있는 전부** | **89dp** |
| 배너 권유 / 진행 / 결과 / 한도 | 82 / 99 / 143 / **191dp** |

**가장 작은 얼굴조차 여유를 거의 다 먹는다.** 어느 얼굴이 떠도 문장 칸은 143 → **51dp** 바닥으로
떨어지고, 51dp 는 가장 작은 글자(16dp)로도 두 줄(58dp)이 안 들어가 **모든 문장이 스크롤로
넘어간다** — 그것이 「잘렸다」로 보인다. 크기 엔진은 잘못이 없다(`sentence-size.ts`).

그리는 동안 둘이 더 나왔다:

- **권유 배너도 세션 내내 82dp 를 먹는다.** ✕ 를 누르기 전까지다 — 아무것도 안 눌러도 카드는
  이미 줄어 있다. 사실 진행 배너보다 자주 보이는 쪽이다.
- **줄어든 글자는 스스로 안 돌아온다.** `nextSentenceStep` 은 진동 방지로 **단조 증가만** 한다.
  다만 문항이 바뀔 때 초기화되므로(`screen.tsx` 의 `setSentenceSteps(INITIAL)`) 손해는 그 문항
  하나로 끝난다 — 이 사실이 아래 「접는 시점」을 정했다.

### 10-2. 세우는 규칙

> **예문 학습 화면에서 채우기 UI 는 카드의 몫을 건드리지 않는다.**

143dp 는 "문제 푸는 동안 100%가 스크롤 없이 들어간다"의 근거값이고, 채우기는 곁가지다.
곁가지가 본체의 근거값을 깎으면 안 된다.

### 10-3. 그래서 — 첫 문항만 배너, 나머지는 전부 칩

배너는 **세션의 첫 문항 동안만** 뜨고 **문항이 넘어가는 순간** 칩으로 접힌다.

🔑 **접는 시점을 타이머가 아니라 문항 전환에 맞춘 이유**: 크기 단계는 문항이 바뀔 때만
초기화된다. 타이머로 접으면 문항 **도중에** 칸만 커지고 글자는 작은 채 남는다. 접히는 자리를
초기화 자리에 포개면 한 번에 제 크기로 돌아온다. §9 의 8초 타이머는 이것으로 대체됐다.

결과적으로 **카드가 줄어드는 문항은 세션당 하나**이고, 그 하나도 61dp 라 16dp 글자 두 줄이
들어간다 — 잘리지 않고 작아지기만 한다. 잘림을 만들던 51dp 는 진행·결과 얼굴의 값이었고
그 둘이 칩으로 빠졌다.

### 10-4. 칩 — 아이콘이 뜻을 지고, 색은 무게를 진다

숫자만으로는 「7」이 무엇의 7인지 알 수 없다. 판정은 `chip.ts` 한 벌이다(`face.ts` 와 같은 이유 —
아이콘·숫자·색이 각자 판정하면 하나가 분기를 빠뜨린다).

| 칩 | 뜻 | 숫자 | Ionicons |
|---|---|---|---|
| 테두리 ✨ 7 | 채울 것이 있다 | 남은 대상 | `sparkles` |
| 채움 ↻ 2/7 (회전) | 지금 채우는 중 · 마무리하는 중 | 진행 | `sync` |
| 채움 ✓ 4 | 방금 채웠다(중단·일부 포함) | **받은 수** | `checkmark` |
| 주황 ⏱ 2/7 | 서버를 기다린다(429) | 진행 | `time-outline` |
| 주황 ⏱ 3 | 오늘 한도에 닿았다 | 남은 대상 | `time-outline` |
| 주황 ⚠ 2 | AI 가 못 찾았다 | 못 찾은 수 | `alert-circle` |

🔴 **색은 둘뿐이다.** 앱 토큰의 `success` 가 `primary` 와 같은 값이라(`#2A7B78`) 진행과 완료를
색으로 가를 수 없다. 그래서 테두리(할 일) / 채움(도는 중) / 주황(기다림·봐야 할 것) 세 겹으로
나누고, **주황 둘은 숫자 모양이 가른다** — `2/7` 꼴이면 곧 이어지고 `3` 이면 오늘은 끝이다.

🔑 **완료 칩은 받은 수를 말한다**(남은 수가 아니라). 남은 수로 돌아가면 방금 한 일이 화면에서
사라진다. 문항이 바뀌면 거두고 남은 대상 수(테두리)로 돌아간다 — 🔴 **한도 도달만 예외로 남긴다.**
그것은 방금 한 일의 결과가 아니라 「오늘의 상태」라, 칩이 ✨ 로 돌아가면 「다시 눌러 보라」는
뜻이 되는데 오늘은 안 된다.

### 10-5. 시트가 다섯을 받는다 — 언제든 지금이 보인다

배너가 지던 말이 전부 시트로 왔다. **칩을 누르면 그 순간의 얼굴로 열린다.**

| 얼굴 | 무엇을 말하나 |
|---|---|
| 권유 | 대상 수 · 지금 채울 수 있는 수 · [N개 채우기] · [채울 단어 고르기] |
| 진행 | 진행바 · 지금 채우는 단어 · **[중단]** |
| 기다림(429) | 남은 초 카운트다운 · [중단] |
| 마무리 | 「이미 요청한 것은 받아서 저장해요」 · **[중단] 없음** |
| 결과 | 채운 수 · 남은 수 · [이어서 채우기] / 못 찾은 단어 이름 · [고치기] |
| 한도 | [광고 보고 +N단어] · [내일 이어서] · **Pro 링크** |

🔴 **마무리 화면에는 [중단]을 두지 않는다.** 이미 멈춘 뒤라 멈출 것이 없는데 버튼이 남아
있으면 「아직 안 멈췄나」로 읽힌다 — 회색으로 죽여 놔도 마찬가지다. [닫기]와 「닫아도 저장은
계속돼요」만 준다.

🔴 **예문 학습 시트가 채우는 기준을 빠뜨리고 있었다.** 단어장 시트의 `sheetDesc` 에는
「오래 담아둔 것부터 채워요」가 있는데 `fillSheetDesc` 에는 없었다 — 같은 시트인데 한쪽만
기준을 말하지 않았다. 7개 중 5개만 되는 날 **어느 5개인지**가 실제로 중요하다. 되살렸다.

🔑 **고르기 화면의 숫자는 시트가 아니라 그 화면이 센다.** [채울 단어 고르기] → 시트가 닫히고
고르기 화면이 열리며, 체크할 때마다 **그 화면 아래 버튼**이 「5개 채우기」로 바뀐다. 확정하면
시트로 돌아오지 않고 곧장 채우기가 시작된다(`fill-bare/[id].tsx` 의 `router.back()`).

### 10-6. 🔴 [중단]은 하드 abort 가 아니다 — 차감된 것은 반드시 받는다

서버는 AI 를 부르기 **전에** 차감한다(`consume_ai_quota` → Vertex → 실패면 환불). 그런데
[중단]이 `AbortController` 를 그대로 끊고 있어서, **진행 중이던 요청 최대 4건(동시성)이 차감만
되고 버려졌다.** 화면은 「2개를 채웠어요」인데 한도는 6이 줄어 있을 수 있었다.

규칙을 이렇게 세운다:

> **차감된 것은 반드시 받는다. 아직 차감 안 된 것은 버린다.**

신호를 둘로 갈랐다(`enrich-queue-core.ts` 의 `BatchStopOptions`):

- `stopSignal` — [중단]. 새 작업을 시작하지 않되 **이미 나간 fetch 는 끝까지 받는다.** 2차 패스도
  돌지 않는다(그것도 새 요청이다).
- `signal` — 진짜 teardown. 받을 사람이 없을 때만 끊는다.

### 10-7. 429 — 서버가 「조금 쉬라」고 답하는 것

Edge 는 사용자당 **1분에 40콜**까지 받는다(`_shared/rate-limit.ts`; 사진 스캔 한 장이 30콜이라
그 위로 잡은 값). 넘으면 `429 rate_limited` 와 retry_after 를 주고, 큐는 그 단어를 **버리지 않고
기다렸다 1회 다시 부른다**(최대 60초). 동시성 4라 캐시가 잘 맞는 날 금방 닿고, 사진 스캔 직후면
10개 만에도 닿는다.

🔑 **429 는 차감 전에 일어난다.** 서버 순서가 `rate-limit(187) → consume_ai_quota(195)` 라
**기다리는 단어는 한도를 쓰지 않았다.** 그래서 중단할 때 이것까지 기다릴 이유가 없다 — 즉시
버려도 잃는 것이 없고, 붙들면 중단이 최대 60초 걸린다. `abortableDelay` 가 두 신호를 다 듣는다.

🔴 **고칠 것은 큐가 아니라 화면이었다.** 지금까지 최대 60초 동안 「apple 채우는 중…」이 얼어붙어
**고장으로 보였다.** 큐가 `onWait(초 | null)` 로 알리고, 칩이 ⏱ 로 바뀌고 시트가 남은 초를 센다 —
같은 동작이 「기다리는 중」으로 읽힌다. 워커가 여럿이라 **세어야 한다**(하나가 깨어났다고
「기다림 끝」이라 하면 아직 자는 워커가 있는데 진행 중으로 보인다).

### 10-8. 묶음 경계를 만들지 않는다 —「전체」는 말 그대로 전부다

`allBatchSize` 고정을 걷어냈다.

굳힌 이유는 「채우기로 단어가 늘면 묶음 한가운데서 남은 문항 수가 바뀐다(3/8 이 3/20 이 된다)」
였는데, 🔑 **§6 이 합류를 묶음 경계로 옮기면서 그 일은 일어날 수 없게 됐다.** `setStudyWords` 를
부르는 다섯 자리를 다 확인했다 — 개수가 느는 것은 세션 시작 · 상태 B 첫 개방 · 묶음 경계의
`flushJoin` 뿐이고 **묶음 도중은 하나도 없다.**

그래서 고정이 하던 일은 원래 막으려던 것이 아니라 **원치 않은 세트 경계를 만드는 것**뿐이었다.
예문 8개로 시작해 12개를 채우면, 기본값이 `'all'`(= 끊지 말라)인데도 8문항 뒤
「수고하셨습니다 / 다음 세트 학습하기」가 떴고, 거기서 **[학습 종료하기]를 누르면 방금 채운
12개가 통째로 빠진다** — §6 이 막으려던 손해를 사용자 손으로 내는 셈이었다.

이제 8번째를 풀면 멈춤 없이 9번째가 나오고 진도만 `8/8 → 9/20` 이 된다. 🔑 **묶음 크기를
숫자로 정한 사람은 그대로다** — 그 경계는 그 사람이 원한 것이다.

성과 문구는 칩(`✓ 4`)과 세션 결과 화면이 나눠 맡는다.

#### 🔴 실기에서만 나온 결함 셋 — 전부 고쳤다

코드 검토·타입·1,565건 테스트가 **하나도 못 잡았다.** 네 번째로 같은 일이 반복됐다.

**① 결과 얼굴이 한 프레임도 못 살고 사라졌다.** 채우기가 끝나도 칩이 `✓ N`이 되지 않고
곧장 사라졌다 — 화면은 「아무 일도 없었다」가 됐다.

원인은 **자기를 무효화하는 고리**였다. 문항 전환 effect 의 의존성에 `clearResult` 를 넣었는데,
그 함수가 `fill.outcome` 을 읽어 판정하느라 **outcome 이 세팅되는 순간 새 함수가 되고**, 그래서
effect 가 다시 돌아 방금 생긴 결과를 즉시 지웠다.

→ 판정을 `useBareFill` 안(`setState` 콜백)으로 옮겨 `clearMomentaryResult` 로 만들었다.
의존성이 비어 **함수가 영원히 같다.** 🔑 **effect 의존성에 넣을 콜백은 그 effect 가 바꾸는
상태에 의존하면 안 된다** — 자기가 만든 변화가 자기를 다시 부른다.

**② 배경색이 있는 칩은 아이콘·숫자가 통째로 안 보였다.** 알약만 그려지고 속이 비었다.
테두리 칩(배경 `transparent`)은 멀쩡했으니 갈리는 것은 `backgroundColor` 하나였다.

값을 찍어 갈랐다 — 화면에 상태를 렌더해 보니 `c0/8w`(라벨 `0/8`, 톤 warn)로 **값은 정상인데
화면에만 없었다.** 범인은 `overflow: 'hidden'` 이었고, 빼자 아이콘·숫자가 나오면서 **모서리도
둥근 채로 남았다.**

🔑 CLAUDE.md 의 «배경색 + borderRadius 는 `overflow:'hidden'` 이 필요하다»는 **자식이 없는
점(dot)의 이야기다.** 패딩과 자식을 가진 알약에서는 그것 없이도 Android 가 둥글게 그리고,
오히려 넣으면 **자식을 잘라낸다.** 규칙에 그 단서가 빠져 있었다.

(같은 자리에서 아이콘 크기도 11 → 12 로 올렸다. `checkmark` 만 11에서 잘려 「⌃」로 보였다.)

**③ 채울 것이 0인데 「광고 보고 +20단어」를 권했다.** 다 채운 뒤 시트를 열면 「예문 없는 단어
0개 / 지금 채울 수 있는 수 0개」인데 광고 버튼이 서 있었다. `fillable` 은 대상과 잔량의 min 이라
**대상이 0 이어도 0** 이 되는데, 그것만 보고 ②(광고·내일·Pro) 얼굴로 갔다.

→ `canFill` 에 `bareCount === 0` 을 먼저 둔다. 광고가 뜻을 갖는 것은 «채울 것은 있는데 잔량이
모자랄 때»뿐이다.

#### 검증 환경 메모

- 🔴 **한 번 채우면 그 id 가 서버에 생긴다.** 그래서 «새 id 로 심으면 pull 이 안 되돌린다»는
  1회용이다 — 로컬에서 예문을 지워도 다음 실행에서 복원됐다. **판마다 새 id** 로 심어야 한다.
- 🔴 **`sqlite3` CLI 에 한글을 직접 넘기면 CP949 로 깨진다.** 앱이 JNI 단계에서 죽었다
  (`illegal start byte 0xb0`). 시드는 **Python `sqlite3` 모듈**로 넣을 것.
- 🔴 **블라인드 연속 탭 금지.** 화면이 예상과 다르면(리로드·크래시) 좌표가 엉뚱한 것을 누른다 —
  남의 단어장 **삭제 확인창**까지 갔다. 매 탭 전에 `uiautomator dump` 로 화면을 확인할 것.
- 🔑 한도가 소진되면 **다른 계정으로 갈아타면 된다.** 로그아웃은 push 성공에 gated 된 뒤
  로컬을 지우므로, **바꾸기 전에 DB 를 백업**할 것.
