# 히어로 스크린샷 원본 · 실측 좌표

스토어 스크린샷 첫 2장(`00-hero-a`, `00-hero-b`)이 쓰는 원본과 부품.
설계 배경은 `docs/hero-screenshot-plan.md`.

```
hero.png       Gemini 생성 원본 1984x2144 (교체 대상)
notch.png      hero.png에서 오려낸 노치 (make-assets.py가 생성 — 직접 편집 금지)
make-assets.py 부품 추출 + 좌표 실측 출력
```

## 왜 캡처를 코드로 얹는가

폰 화면은 **그리지 않고 실제 앱 캡처를 얹는다**(가이드라인 2.3.10). 이 앱은 이미
2.1a/2.3.10으로 반려된 이력이 있어 그려낸 UI를 넣을 이유가 없고, 앱 UI가 바뀌어도
`raw/{lang}/05-home.png`만 갈아끼우면 끝난다.

캡처가 그림의 노치까지 덮어버리므로 노치는 원본에서 오려 두었다가 캡처 위에 다시
얹는다. 새로 그리면 그림과 미묘하게 어긋난다.

## 실측값 (hero.png 1984x2144 기준)

전부 눈이 아니라 픽셀로 잰 값이다. **원본을 바꾸면 `make-assets.py`를 다시 돌리고
아래 표와 두 `config.json`의 `hero` 블록을 갱신할 것.**

| 대상 | 값 | 재는 법 |
|---|---|---|
| 화면 안쪽 사각형 | x=1198, y=669, w=603, h=1285 | 무채색(\|R−B\|<12) + 밝기>140. 베젤(갈색)·배경(크림)은 R−B가 커서 걸러진다. 코너 라운딩을 피해 x=1300·1700 두 열에서 y 669..1953이 일치하는 것으로 확정 |
| 화면 코너 반경 | ≈46 | 좌상단에서 직선부에 도달하는 행까지의 거리 |
| 노치 | x=1334, y=669, w=330, h=75 | 화면 사각형 안의 비무채색 bbox. 화면 중심과 0.5px 오차로 정렬됨 |
| 폰 최좌단 | **x=1150** | 베젤(1159)이 아니라 **측면 버튼**이다. 1장에서 폰을 화면 밖으로 밀 때 기준이 되는 값 |
| 캐릭터 | x=25..1158, y=638..2024 (w=1134) | 폰 왼쪽 영역의 비배경 bbox |
| 배경색 | `#F4E5CA` | 네 가장자리 평균. 팔레트 크림 `#F2E8D5`과 다르므로 `hero.cream`으로 따로 둔다 |
| 화면 평균색 | rgb(205,200,197) | 합성 후 "잔상 없음" 검증의 기준값 |

화면 비율 603/1285 = 0.469, 캡처(1125×2436) = 0.462 — 캡처를 폭에 맞추면 하단
21px이 넘쳐 잘린다. 홈 인디케이터 여백만 잘리고 탭바는 남는다.

## 장별 배치가 그 값인 이유

**1장(캐릭터)** — 캐릭터 폭 1134가 캔버스 1290에 들어가지만, 캐릭터 오른쪽 끝과
폰이 맞붙어 있어(간격 20px) 폰을 밀어내면 캐릭터도 오른쪽 가장자리에 붙는다.
배율 1.12·x=4로 두면 폰 최좌단이 1150×1.12+4 = **1292px**, 즉 캔버스 밖 2px에
놓여 폰 조각이 사라지고 캐릭터 팔만 화면 밖으로 뻗는다.

**2장(폰)** — 폰 중심(원본 x=1533)이 캔버스 정중앙에 오도록 오프셋을 잡았다.
왼쪽에 캐릭터 몸통이 걸치는 건 의도 — "캐릭터가 폰을 들고 있다"가 읽힌다.

## 파노라마를 쓰지 않는 이유

원안은 원본 한 장을 두 장에 걸쳐 깔고 `background-position`만 바꿔 자르는
파노라마였다(이음새는 실측 평균차 1.7로 정확히 맞았다). **버린 이유는 기하학이다** —
캐릭터 폭 1134 > 분할 창 992라서 분할선을 어디로 옮겨도 1장에서 캐릭터가 잘린다.
원본이 프롬프트의 "중앙선을 비울 것"을 지키지 않았기 때문이고, 그림을 다시 만들지
않는 한 해결되지 않는다. 계획서 §2가 "스토어 갤러리는 어차피 간격·모서리 때문에
이어져 보이지 않으니 각 장이 단독으로 성립해야 한다"고 세운 원칙을 따라, 두 장을
독립 구성으로 바꿨다.

## 검증

합성 결과는 반드시 픽셀로 확인한다(이 저장소는 "눈으로 봤다"가 실측을 대신하지
못한 전례가 여러 번 있다).

- 화면 영역 안에 원본 회색 rgb(205,200,197)이 남아 있으면 캡처가 덜 덮인 것.
  정상 범위는 코너 안티에일리어싱뿐 — **0.05% 미만**.
- 화면 네 변 안쪽 1px이 캡처 색인지 확인(경계에 회색 테두리가 없어야 한다).
- 캡션 잉크가 좌우 96px 여백을 침범하지 않아야 한다.
