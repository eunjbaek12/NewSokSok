# App Store Connect — 앱 개인정보 답변지

App Store Connect → 앱 → **앱 개인정보(App Privacy)** → 데이터 수집 편집.
Play 쪽은 [`data-safety.md`](./data-safety.md).

**최종 갱신: 2026-07-28 (앱 1.3.0 — 문의 기능 추가 반영)**

ASC는 Play와 분류 체계가 달라서 그대로 옮길 수 없습니다. 데이터 유형마다 네 가지를 답합니다:

1. **수집 여부**
2. **용도** — 서드파티 광고 / 개발자의 광고·마케팅 / 분석 / 제품 개인화 / 앱 기능 / 기타
3. **사용자와 연결됨(Linked to You)** — 신원과 이어지는가
4. **추적에 사용됨(Tracking)** — 다른 회사의 앱·웹 데이터와 결합하는가

🆕 = 1.3.0에서 새로 추가. 나머지는 기존 제출과 같아야 합니다.

## 수집한다고 답할 항목

| 데이터 유형 | 용도 | 연결됨 | 추적 | 비고 |
|---|---|---|---|---|
| **연락처 정보 › 이름** | 앱 기능 | 예 | 아니요 | 소셜 로그인 이름, 공유자명 표시 |
| **연락처 정보 › 이메일 주소** | 앱 기능 | 예 | 아니요 | 로그인 이메일 + 🆕 문의 회신용(선택 입력) |
| **사용자 콘텐츠 › 사진 또는 동영상** | 앱 기능 | 아니요 | 아니요 | 사진 스캔. 저장하지 않고 OCR 결과만 |
| **사용자 콘텐츠 › 오디오 데이터** | 앱 기능 | 아니요 | 아니요 | 음성 입력. 기기 인식, 텍스트만 사용 |
| 🆕 **사용자 콘텐츠 › 고객 지원** | 앱 기능 | 예 | 아니요 | 문의 본문과 답장 |
| **사용자 콘텐츠 › 기타 사용자 콘텐츠** | 앱 기능, 제품 개인화 | 예 | 아니요 | 단어·단어장·학습 결과 |
| **식별자 › 사용자 ID** | 앱 기능 | 예 | 아니요 | Supabase `auth.uid()`, 🆕 `ticket_key` |
| **식별자 › 기기 ID** | **서드파티 광고**, 앱 기능 | 예 | **예** | IDFA(AdMob) + 🆕 문의 남용 방지 UUID |
| **구매 › 구매 내역** | 앱 기능 | 예 | 아니요 | Pro 구독 상태·구매 토큰 |
| **사용량 데이터 › 광고 데이터** | 서드파티 광고 | 예 | **예** | AdMob 노출·클릭 |
| 🆕 **진단 › 성능 데이터** | 앱 기능 | 예 | 아니요 | 문의에 붙는 진단 정보(끌 수 있음) |

### 추적(Tracking)에 대해

**앱 추적 투명성(ATT) 프롬프트를 띄웁니다** — `lib/ads/admob.ts`에서
`requestTrackingPermissionsAsync()`를 호출합니다(iOS 전용, `requireOptionalNativeModule`로 지연 로드).
따라서 위 표의 **기기 ID·광고 데이터는 "추적에 사용됨 = 예"**로 답해야 하고,
ASC의 "이 앱은 추적에 데이터를 사용합니다" 문항에도 **예**입니다.

Pro 구독자에게는 광고를 띄우지 않지만, 앱 전체 기준으로는 여전히 "예"입니다.

## 수집하지 않는다고 답할 항목

건강 및 피트니스, 금융 정보(결제 수단 — 스토어가 처리),
위치(정확·대략), 민감한 정보, 연락처, 검색 기록(로컬만 — 서버로 보내지 않음),
브라우징 기록, 사용량 데이터 › 제품 상호작용(분석 SDK 없음),
진단 › 충돌 데이터·기타 진단 데이터.

> **검색 기록**: 앱 내 단어 검색은 기기에만 남고 클라우드 동기화에 포함되지 않으므로
> ASC 기준 "수집"이 아닙니다. Play는 *수집 가능성*을 묻는 폼이라 답이 갈립니다 —
> 의도된 차이입니다.
