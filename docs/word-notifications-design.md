## 0. 한 줄

**앱을 안 열어도 단어가 온다.** 단어와 뜻만 보여 주고 버튼은 없다. 아무것도 기록하지 않는다. 기본은 꺼짐.

왜 만드나 — 8/19 실측에서 단어 20개 이상 가진 44명 중 22명이 학습을 한 번도 안 열었다.
«단어는 모으는데 학습을 안 연다»는 사람에게 단어를 가져다준다. 경쟁 앱의 잠금화면 단어와 같은 자리다.

## 2. 어떤 단어를 보내나

### 2.1 출처 단어장

| 설정 | 출처 |
|---|---|
| **자동**(처음 값) | 숨기지 않은 단어장 중 `lastStudiedAt` 이 가장 최근인 것. 학습 기록이 하나도 없으면 **단어장 탭 맨 위**(`lists` 순서 = `position DESC`). **단어가 0개인 단어장은 건너뛴다** — 방금 만든 빈 단어장이 맨 위에 있다고 알림이 멈추면 안 된다 |
| 단어장을 고름 | 그 단어장. 나중에 숨기거나 지우면 **자동으로 돌아간다** |

- 숨긴 단어장은 고르기 목록에 없다 — 앱 «복습하기»가 숨김을 «지금은 안 볼래»로 보고 빼는 것과 같게(`selectReviewWords`).
- 다 외운 단어장도 고를 수 있다(«암기» 조건이면 단어가 나온다). **단어가 0개인 단어장만** 흐리게 두고 못 고른다.

### 2.2 조건 — «골라서 학습» 재사용

| 칩 | `PickFilters.wordFilter` | 비고 |
|---|---|---|
| **미암기** (처음 값) | `learning` | 아직 안 외운 단어 |
| 암기 | `memorized` | |
| 많이 틀린 50 | `wrongCount` | 프리셋 — 50개까지 |
| 최근 추가 50 | `recent` | 프리셋 — 50개까지 |
| ☆ 별표 (따로 켜고 끔) | `starredOnly` | 위 조건과 함께 걸린다 |

- 조건은 하나만. 켜진 칩을 다시 누르면 처음 값(미암기)으로.
- «기본»·«복습» 칩은 **없다** — 알림은 복습할 단어를 안 보내므로(N2) 알림의 «기본»이 곧 «미암기»다.
- 후보 집합은 `features/study/pick/filter.ts` 의 `collectScopeItems` + `selectPickResults` 로 구한다
  (범위 = 그 단어장 하나). 계산을 복제하지 않는다 — 두 곳이 같은 칩 이름으로 다른 단어를 내면 안 된다.
- 품사·태그·Day 조건은 나중에(저장 모양이 `PickFilters` 라 붙이기 쉽다).

### 2.3 보내는 순서

**단어장 순서**(`list.words` 순서 = `position ASC` — 학습 화면·학습 계획이 쓰는 순서). 조건이 고른 단어를 이 순서로 보낸다.

- **9/17 뺌: «오답 많은 것 → 별표 먼저».** 단어장 순서를 흩뜨리는 숨은 규칙이다. 틀린 단어·별표만 보고 싶으면
  «많이 틀린 50»·별표 칩으로 직접 고른다(위젯도 같이 뺐다).
- 위젯의 «오늘 본 단어는 맨 뒤로»는 알림에 없다 — 예약 시점에 며칠 뒤를 알 수 없고, 같은 역할을 «보낸 단어 기억»(§2.4)이 한다.
- 계획의 Day도 단어장 순서대로 나뉘어 있어(`generatePlan`), 따로 처리하지 않아도 **앞 Day에 남은 단어 → 지금 Day →
  다음 Day** 순으로 이어진다.

### 2.4 보낸 단어 기억과 한 바퀴 (N7 · N8)

**상태**: «이번 바퀴에 보낸 단어» 집합. 설정이 아니라 내부 상태라 설정 저장소와 다른 키에 둔다.

```
예약할 때:  후보를 순서대로 훑으며 «이번 바퀴에 안 보낸 것»을 칸에 채운다.
            후보가 모두 보낸 것이 되면 → 집합을 비우고(새 바퀴) 처음부터 계속 채운다.
            각 칸에 {wordId, fireAt, 이 칸에서 새 바퀴 시작?} 을 적어 둔다.
다시 예약할 때: 지난번 칸 중 fireAt ≤ 지금 인 것(= 이미 나간 것)을 순서대로 되짚어
            집합을 복원한다(«새 바퀴 시작» 칸에서 비우고 넣기). 그 뒤 위와 같이 채운다.
```

- 외운 단어는 후보에서 빠지므로 저절로 안 온다. 집합에 남은 옛 단어는 «모두 보냈나» 판정에서 무시한다(후보 ⊆ 집합으로 판정).
- 출처나 조건을 바꾸면 후보가 통째로 바뀐다. 집합은 그대로 두어도 판정이 후보 기준이라 문제없다.

### 2.5 보낼 단어가 0일 때 (N11)

- 후보가 0개(다 외움 · 조건에 맞는 단어 없음 · 단어장이 빔)면 **단어 알림은 잡지 않고 «곧 멈춰요» 안내 1개**만 다음 첫 시각에 잡는다.
- «한 번»을 지키려고 **이미 나간 안내를 기억**한다. 후보가 다시 1개 이상이 되면 기억을 지운다.
  (안 그러면 앱을 열 때마다 다시 잡혀 매번 온다.)

## 3. 언제 보내나

### 3.1 하루 안의 시각

- 시작 `S`, 끝 `E` 는 30분 단위(복습 알림 시간 고르기와 같은 목록), **`S < E`**, 같은 날 안(자정을 넘는 시간대는 고르기 창에서 막는다).
- 하루 `n` 번:
  - `n = 1` → 가운데 `(S + E) / 2`
  - `n ≥ 2` → `S + k·(E − S)/(n − 1)` (`k = 0 … n−1`), 분 단위 내림
  - 기본 9~21시 · 5번 → **9:00 · 12:00 · 15:00 · 18:00 · 21:00** (목업 창의 줄과 같다)
  - 시간대가 좁아 촘촘해져도 막지 않는다(뺀 규칙). 최소 폭 30분 ÷ 11 = 2.7분이라 분 단위 내림으로 같은 시각이 겹치지 않는다.
- 날짜는 복습 알림과 같이 `new Date(y, m, d + offset, h, min)` — 폰의 달력일 기준이라 서머타임에도 «그날 9시». 이미 지난 시각은 건너뛴다.

### 3.2 몇 칸 잡나

| | 칸 |
|---|---|
| iOS 대기 알림 한도 | 64 |
| 복습 알림 최대 | **15** (오늘 + 14일. 목업·옛 문서의 «14»는 오늘 칸을 빠뜨린 값 — 정정) |
| «곧 멈춰요» 안내 | 1 |
| **단어 알림** | **48** → 하루 5번이면 **9일 반**(목업의 «10일» 정정) |

- 안내는 **마지막 단어 알림 다음 칸의 시각**에 둔다.
- [선택 불필요] **Android도 같은 48칸**. 두 OS가 같은 규칙이면 이 PC에서 가능한 Android 실기가 iOS 동작까지 확인해 준다.
  Android만 14일 치를 잡으면 iOS 쪽 끊김·안내 시점은 검증 수단이 없다(iOS 는 로컬 빌드 불가 — `widget-design.md` §-1).
- 합이 64를 넘지 않는 것이 구조로 보장된다(15 + 48 + 1). iOS 는 넘치면 **늦은 것부터 말없이 버린다.**

### 3.3 언제 다시 예약하나

- 복습 알림과 같은 트리거 — 단어장 데이터(`lists`) · 설정 · 앱 언어가 바뀔 때, 앱 시작 때.
- **추가: 앱이 앞으로 올 때(`AppState` → `active`).** [선택 불필요] 설정 화면 문구
  «앱을 오래 열지 않으면 알림이 멈춰요. 한 번 열면 다시 이어져요»의 약속이다. 지금 복습 알림은 백그라운드에서 돌아와도
  `lists` 가 안 바뀌면 다시 예약하지 않아서, **매일 열어도 공부를 안 하면 9일 반 뒤 끊긴다.** 시간대가 바뀐 뒤
  «앱을 열 때 다시 예약»(N13)도 이 트리거가 있어야 성립한다. → **복습 알림에도 같이 건다.**
- 직렬화·취소는 복습 알림의 수법을 그대로 쓴다(`features/study/review/notifications.ts`):
  **체인 + 세대 카운터**로 겹친 실행을 막고, 데이터에 **자기 태그**(`kind: 'word-notification'`)를 심어 그 태그만 취소한다
  — 복습 알림을 지우지 않는다.
- 디바운스 1.5초(복습 알림과 같다). 설정 화면에서 바꾼 값은 즉시 한 번 더 예약한다.

## 5. 누르면 (N10)

| 알림 | 가는 곳 |
|---|---|
| 단어 | **`/list/[listId]` 를 새로 연다** + 그 단어로 내려간다 |
| 곧 멈춰요 | 설정의 **«알림에 나올 단어»** 화면 |

단어장 화면에서:

- 새로 여는 화면이라 필터·정렬은 처음 값(전체 · 최신순) — 필터에 가려 단어가 안 보이는 일이 없다.
- 그 단어가 화면 위쪽에 오도록 내려가고, 카드 배경을 `primaryLight` 로 칠했다가 원래 색으로 돌린다. `새로 정한 값`
- 단어가 지워졌으면 단어장 화면만 연다. 단어장까지 없으면 단어장 탭으로.
- **아무것도 기록하지 않는다**(마지막 학습 · 학습량 · 연속 학습일 전부 그대로).

구현 때 주의:

- 🔴 **시작 탭 교체와 경합한다.** `app/(tabs)/_layout.tsx` 는 알림으로 열린 콜드 스타트에서
  `fromReviewNotification` 일 때만 시작 탭 `replace` 를 건너뛴다. 단어 알림도 같은 분기에 넣지 않으면
  단어장 화면이 열린 직후 시작 탭으로 덮인다.
- 콜드 스타트 탭은 `useLastNotificationResponse` 로 잡는다(리스너만 달면 이미 지나간 이벤트를 놓친다 — 복습 라우팅 주석).
- 단어 카드 높이가 뜻 줄 수에 따라 달라 `scrollToIndex` 가 바로 실패할 수 있다 → `onScrollToIndexFailed` 에서 대략 위치로 옮긴 뒤 재시도.

### 6.1 «단어 알림» 구역 — 설정 탭, 복습 알림 구역 바로 아래

- 스위치를 끄면 아래 두 줄이 흐려진다(복습 알림 구역과 같은 모양).

- 스위치를 켤 때 권한: **복습 알림 스위치와 같은 흐름**(`app/(tabs)/settings.tsx`) — 권한이 없으면 시스템 창,
  이미 거절됐으면 «알림이 꺼져 있어요» → 설정 열기. soft ask 는 없다(사용자가 직접 켠 것).

### 10.3 «켜면 복습 알림을 잃나» — 아니다

알림은 **문 하나 + 스위치 둘**이다. 문(OS 권한)은 앱에 하나지만 복습 알림·단어 알림은 그 안쪽에
각자 스위치를 갖는다. 카드로 켜도 복습 권유 창은 3일차에 그대로 뜬다 — 그 창은 자기 쪽 설정
(`reviewNotificationSettings.softAsked`)만 보기 때문이다. 이미 권한이 있으니 «알림 받기»는 OS 창 없이 바로 켜진다.

손해는 **거절 한 경우뿐**이다: 카드에서 «켜기» → 시스템 창 → 거절. 그러면 iOS는 다시 묻지 못해
복습 알림도 설정 앱을 거쳐야 한다. 그래도 카드를 먼저 띄우기로 한 이유 — 복습 알림은 «복습할 단어가
있을 때만» 온다. **학습을 한 번도 안 한 사람에게는 복습이 생기지 않아 잃을 것이 애초에 0이고**,
이 카드가 노리는 사람이 정확히 그 사람이다. 학습을 하는 사람은 3일차에 복습 권유를 먼저 보게 되므로
카드가 문을 열 일이 없다.

> 뒤집는 안(«알림이 이미 켜져 있을 때만 카드를 띄운다»)은 거절 문제를 없애지만, 학습을 안 하는
> 사람은 복습 권유 자체가 안 떠서 **타겟이 통째로 빠진다**. 그래서 쓰지 않는다.
