# Gentle SRS — 설계 문서 (부드러운 복습)

> **상태: CORE · UX · ENGINE · SYNC 전부 구현됨 — 실기 검증 대기 (2026-07-17 갱신).** 1.2.0급 "큰 업데이트"의 헤드라인.
> 범위는 **완성형** = MVP(홈 원탭) + 로컬 알림 + 클라우드 동기화. 진행 현황·구현 위치는 §9.
> 서버 마이그레이션은 배포 완료. 알림은 네이티브 모듈이라 **새 기기 빌드가 필요**하다.
> 이전 "보류" 판단과 초기 설계(필터 방식·암기 유지 규칙)는 **폐기**됐다. 아래 §0을 먼저 볼 것.
>
> ⚠️ **구현하며 뒤집힌 규칙이 4개 있다**(D13~D16, §0.1). 초기 설계대로 두면 기능이 조용히 죽는
> 문제들이라 코드가 정본이다: 사다리 전진 게이트(§4.2.1) · 365일 연장(§4.2.2) · 은퇴(§4.2.3) ·
> 배수 정렬(§4.3.1).

## 1. 배경 & 문제 (왜)

- 진지한 어휘 앱은 거의 다 SRS를 갖고 있다(= table stakes). 없으면 감점, 있어도 그 자체론 가점 아님.
- 이탈의 진짜 원인은 SRS의 *효과*가 아니라 **백로그(밀린 복습)와 죄책감**:
  하루 빠지면 밀린 게 한꺼번에 쏟아짐 → 벽 → 앱 열기 무서움 → 죄책감 → 조용한 이탈.
  (Anki "week 3 이탈", WaniKani "며칠 결석→400~600 백로그" 등 커뮤니티 근거 다수.)
- **우리의 승부처는 "SRS를 넣느냐"가 아니라 "Anki가 못 하는 부드러운·자동화된 SRS"** 다.
  이 앱의 따뜻한(아보카도) 톤과도 맞는다.
- **타겟:** Anki가 어렵거나 부담스러워 튕겨나온 캐주얼·초보. **비타겟:** Anki/WaniKani 정착 하드코어(뺏으려 하지 않음).

## 2. 설계 원칙 (anti-Anki)

| # | 원칙 | 의미 |
|---|---|---|
| P1 | **백로그 벽 금지** | 일일 노출에 상한. 총량("543개") 안 보여줌 |
| P2 | **결석 무처벌** | 며칠 빠져도 한꺼번에 안 쏟아짐. 복귀는 "환영", "밀림" 아님 |
| P3 | **기계 숨김** | 간격 숫자·설정·스케줄 내부 노출 안 함 |
| P4 | **최소 마찰** | 복습 전용 새 UI를 만들지 않는다 — 기존 카드학습을 그대로 씀 |
| P5 | **죄책감 없는 톤** | 빨간 overdue 배지·스트릭 압박 없음. 부드러운 카운트만 |
| P6 | **자명함 우선** | 설명이 필요하면 → 설명을 붙이지 말고 UI를 더 단순하게 |

> ⚠️ **P6은 이 문서의 개정을 이끈 원칙이다.** 초기 설계의 "복습에선 다시 볼게요를 눌러도 암기가 풀리지 않아요"
> 안심 문구가 바로 P6 위반의 증거였다 — 문구가 필요하다는 건 UI가 자기모순이라는 신호. §4.5에서 해소.

## 3. 핵심 접근 — "복습"은 홈 전용 행동 (필터 아님)

**폐기안 ①:** 복습 세션 전용 채점 버튼(다시/기억남/쉬워요 3-way). → 앱과 이질적, 문구 충돌, 좌우 스와이프(2방향)와 불일치.

**폐기안 ② (2026-07-17):** 학습 범위 필터에 `복습` 칩 추가. → **아래 이유로 폐기.**

**채택안:** 복습은 **홈의 원탭 배너**(§5.2)로만 진입한다. 학습설정 "학습 범위" 필터는 기존 6개
(`전체 / 미암기 / 암기 / 오답 / 최근 / 별표`)를 그대로 두고 **복습을 넣지 않는다.**

### 3.1 왜 필터가 아닌가

1. **범주 오류.** 다른 필터는 "어떤 단어?"라는 **슬라이스**(정적 속성)인데, 복습은 "지금 뭘 할까?"라는 **행동**이다.
   같은 줄에 세우는 것 자체가 어색하다.
2. **"암기"와 혼동.** 둘 다 외운 단어 기반인데, 차이(=타이밍)는 P3에 따라 **숨겨져 안 보인다.**
   나란히 두면 사용자는 반드시 *"둘 다 외운 건데 뭐가 달라?"* 라고 묻는다. (실제 설계 리뷰에서 나온 질문.)
3. **업계 표준이 전부 전용 액션이다.** 설정 화면 속 필터로 리뷰를 여는 앱은 없다:

   | 앱 | 복습 진입 |
   |---|---|
   | Anki | 덱 → **Study Now** (due 자동) |
   | Duolingo | **Practice** 전용 버튼 |
   | Quizlet | **Learn** 모드가 자동 관리 |
   | WaniKani | **Reviews** 버튼(오늘 due 개수) |
   | Memrise | **Review** 전용 버튼 |

4. **비용은 사실상 없다.** 잃는 것은 "복습을 퀴즈·예문 모드로도 돌리기"인데, 그 자체가 비표준
   (표준 앱들도 복습은 전용 흐름). 원하면 후속에서 추가 가능.

### 3.2 암기 vs 복습 (사용자에게 설명해야 할 일이 생기면)

| | 무엇을 | 예 | 성격 |
|---|---|---|---|
| **암기**(필터) | 외운 단어 **전부** | 128개(늘 같음) | 정적·수동 |
| **복습**(홈 행동) | 그중 **오늘 due만** | 12개(매일 바뀜·상한·위험순) | 동적·자동 |

비유: **암기 = "책장의 모든 책 다시 읽기", 복습 = "오늘 반납일 온 책만".**

## 4. 스케줄 모델 — 전부 자동 (채점 버튼 없이)

복습 전용 입력 없이, 앱이 이미 가진 신호만으로 각 단어의 재등장 간격을 조절한다.

### 4.1 쓰는 신호 (전부 기존 + 2개 신규)

| 신호 | 출처 | 쓰임 |
|---|---|---|
| **외웠어요 / 다시 볼게요** | 카드학습 좌우 스와이프(`flashcards.memorized`/`reviewBtn`) | 성공/실패 |
| 오답 횟수 | 퀴즈 `wrongCount` | 어려움 정도 (우선순위 가중) |
| 별표 | `isStarred` | 우선순위 |
| 암기 여부 | `isMemorized` | 복습 후보 = 외운 것 |
| **마지막 학습 시각** | **신규 `lastReviewedAt`** (볼 때마다 자동 갱신) | 재등장 타이밍 |
| **성공 누적** | **신규 `reviewSuccessCount`** | 간격 사다리 위치 |

### 4.2 숨은 간격 사다리 (사용자에게 안 보임)

```
due였을 때 성공(외웠어요)하면 재등장 간격이 한 칸 늘어난다:
    3일 → 10일 → 30일 → 90일 → 180일 → 365일 → 은퇴(더는 안 물어봄)

실패(다시 볼게요) → 미암기로 강등 (§4.5) → 복습 풀에서 빠지고 처음부터
```

**이상적 사용자(매번 due에 맞힘)의 일생:** D3 · D13 · D43 · D133 · D313 · D678에 만나고 **은퇴**.
6번 맞히는 데 약 2년. (테스트로 고정: `__tests__/review-engine.test.ts` "단어의 일생")

- **첫 간격 = 3일** (D5). 외운 다음 날 바로 묻지 않는다 — "어제 외웠다고 했는데 또?"는 gentle 위반.
  - 참고: SM-2 2차 간격 6일, Anki Easy 4일 → **3일도 표준 범위 안.**
  - ⚠️ **트레이드오프:** 신규 유저는 3일간 이 기능을 못 본다(콜드스타트 §5.3). **튜닝 가능한 값** —
    초반 이탈 데이터를 보고 조정할 수 있다(1~2일로 당기는 안이 검토됐으나 3일 채택).
- **균일 스테핑 (D4).** "외웠어요"는 전부 **한 칸씩**. Hard/Good/Easy 같은 차등 채점 **없음**.
  - 차등을 주려면 버튼이 3개가 돼야 하고, 그건 §3에서 폐기한 마찰이다.
  - 캐주얼 앱 표준: Duolingo·Quizlet·Memrise 전부 **이진**(맞음/틀림). 차등은 Anki·SuperMemo(파워유저)용.
  - **난이도 차등은 "채점"이 아니라 "이력"으로 자연 발생한다:** 쉬운 단어는 안 틀리니 6번이면 은퇴,
    어려운 단어는 강등·재진입을 반복해 노출이 훨씬 많아짐.
  - 파워유저가 Easy를 원하는 진짜 이유(복습량 감축)는 **`DAILY_CAP` + 위험순 정렬이 이미 해결**.
- **간격 숫자·사다리는 전혀 노출하지 않는다**(P3).
- 정밀 SM-2/FSRS 아님 — **근사(gentle) SRS.** 근사라서 앱과 완전 일관·마찰 0이 이득.

#### 4.2.1 전진은 **due였을 때만** (D13 · 개정 2026-07-17)

> **⚠️ 개정.** 초기 설계는 "'외웠어요'를 누를 때마다 한 칸"이었다. **폐기.**

- **왜 뒤집었나:** 이 앱의 핵심 사용 패턴은 같은 단어장을 며칠 연속 공부하는 것(플랜 Day 1..N)이다.
  누를 때마다 올리면 **나흘 연속 공부한 성실한 사용자의 단어가 전부 마지막 칸으로 밀려**
  복습이 몇 달간 사라진다. 성실할수록 기능이 빨리 죽는 셈.
- **논리:** 사다리 값은 **날짜 간격**이다 = "10일 뒤에도 기억한다"는 주장. 그런데 하루 만에 다시 맞힌 것은
  **하루치 기억력만 증명**할 뿐 그 주장의 근거가 못 된다. 그래서 사다리는 **"간격을 두고 되살린 횟수"** 만 센다.
- **⚠️ 게이트는 진입 경로가 아니라 단어의 상태를 본다.** 복습 배너를 거치지 않고 단어장에서 공부하다
  마침 due였던 단어를 맞혀도 **똑같이 전진한다.**
- **매일 공부하는 단어장의 단어는 칸이 멈춘다** — due가 될 틈이 없으므로. 이건 의도된 동작이다:
  매일 보는 단어에 "잊을 때가 됐어요"라고 알릴 이유가 없고, 그동안 배너에도 안 떠서 방해하지 않는다.
  공부를 멈추면 그때까지 쌓은 칸 기준으로 정상 재개된다.
- **"본 시각"(`lastReviewedAt`)은 게이트와 무관하게 볼 때마다 갱신된다**(§4.1). 게이트는 **카운트**에만 걸린다.
- 참고: Anki·FSRS도 조기 복습에 온전한 크레딧을 주지 않는다(경과 시간에 비례해 감쇠).

#### 4.2.2 마지막 칸을 365일로 (D14 · 개정 2026-07-17)

> **⚠️ 개정.** 초기 사다리는 `3/10/30/90`이었다. 뒤에 `180/365`를 **추가.**

두 가지가 동시에 풀린다.

1. **지겨움.** 90일이 끝이면 이미 아는 단어(예: `apple`)가 **영원히 3달마다** 돌아온다.
2. **영구 적체(더 심각).** 정상 상태의 하루 발생량 ≈ `외운 단어 수 ÷ 마지막 칸`.

   | 마지막 칸 | 하루 상한 20을 감당 가능한 서재 |
   |---|---|
   | 90일 | **1,800개** |
   | 180일 | 3,600개 |
   | **365일** | **7,300개** |

   번들 큐레이션만 **56덱 12,874단어**(단일 덱도 1,000단어)라 **1,800 천장은 실제로 닿는다.**
   넘는 순간 하루 상한을 영구 초과해 복습 줄이 **영영 안 줄어든다.**

- ⚠️ **`DAILY_CAP`을 올리는 건 해법이 아니다.** 50으로 올려도 4,500개일 뿐이고, "하루 50개"라는
  벽이 생겨 **P1을 정면으로 위반**한다. 레버는 상한이 아니라 **사다리**다.

#### 4.2.3 은퇴 — 진짜 안 물어보기 (D15 · 신규 2026-07-17)

- **마지막 칸(365일) 복습까지 성공하면 복습 후보에서 영구 제외**한다. `reviewSuccessCount >= 7`.
- 여기 닿으려면 **6번 연속**(D3·D13·D43·D133·D313·D678) 맞혀야 한다 — 약 2년.
  참고: WaniKani는 **4개월**이면 "Burned"로 제거한다. 우리 기준이 훨씬 보수적.
- **되돌릴 수 있다:** 나중에 일반 학습에서 그 단어를 "다시 볼게요"로 틀리면 카운트가 0으로 리셋되어(§4.5)
  사다리 첫 칸부터 재시작한다. **은퇴는 영구 추방이 아니다** — 진짜로 잊었다면 다시 잡아준다.
- **새 컬럼 불필요** — 카운트 하나로 판정한다.

### 4.3 "복습" 후보 선정

```
후보 = isMemorized = true                      // D2: 외운 것만
       AND reviewSuccessCount < 7              // D15: 은퇴하지 않은 것
       AND (경과일 ≥ 그 단어의 현재 간격)        // 날짜 단위 — 아래 참고
정렬 = 위험한 것 우선: 초과 배수 큰 순 → wrongCount 높은 순 → isStarred   // D16
노출 = min(후보 수, DAILY_CAP)                  // D6: 20
```

- **기준은 "마지막 학습 후 경과"**(`lastReviewedAt`). "외운 후 경과"로 하면 복습해도 due에서 안 빠져
  같은 단어 무한 반복 → **`lastReviewedAt` 자동 갱신이 이 기능의 성패를 가른다.**
- **due는 시각이 아니라 날짜(기기 로컬 자정 경계)로 잰다.** ms로 재면 밤 11시에 외운 3일짜리 단어가
  3일 뒤 **밤 11시**에야 due가 되어, **저녁 8시 알림(§8.1)도 그날 낮의 학습도 모두 놓친다.**
  날짜로 세면 due가 된 날 하루 종일 due다.
- `lastReviewedAt`이 NULL이면 **due가 아니다.** "학습 이력 없음"이지 "오래 됐음"이 아니고, due로 치면
  클라우드 복원 직후 서재 전체가 쏟아진다(P1 위반). ⚠️ SYNC(§7) 전까지 남는 구멍 — §7 참고.
- `lastReviewedAt`이 NULL인 기존 단어: 마이그레이션 시드 필요 — §6 참고.

#### 4.3.1 정렬은 "초과 배수" 순 (D16 · 개정 2026-07-17)

> **⚠️ 개정.** 초기 설계는 "오래된 순"(경과일)이었다. **폐기.**

- **왜 뒤집었나:** 365일짜리 베테랑은 **정의상 365일이나 안 본 단어**라 경과일로 줄 세우면 **항상 앞줄**을
  차지한다. 정작 3일짜리인데 10일 방치된 위태로운 단어가 하루 상한(20) 밖으로 밀려난다 —
  **위험순으로 보여주려던 의도와 정확히 반대.**
- **새 기준: `경과일 ÷ 그 단어의 간격`(초과 배수) 큰 순.**

  | 단어 | 간격 | 경과 | 경과일 정렬 | 배수 정렬 |
  |---|---|---|---|---|
  | 새 단어 | 3일 | 10일 | 10 → 뒷줄 ❌ | **3.3배 → 앞줄** ✅ |
  | 베테랑 | 90일 | 91일 | 91 → 앞줄 ❌ | 1.01배 → 뒷줄 ✅ |

- **왜 뺄셈(초과 일수)이 아니라 나눗셈인가:** 3일짜리가 6일 지난 것과 90일짜리가 180일 지난 것은
  **잊은 정도가 비슷한데**(둘 다 2배), 뺄셈이면 3일 초과 vs 90일 초과라 또 베테랑이 이긴다.
  **망각은 간격에 비례해 진행되므로 배수가 맞다.**
- **영향 범위:** due가 20개 이하인 날엔 순서만 바뀐다. **20개를 넘는 날 = 며칠 쉬었다 돌아온 날**이고,
  그날 무엇을 보여주느냐가 이 기능의 핵심이라 그때 결정적이다.

### 4.4 결석 처리 (P2)

- due가 쌓여도 UI는 상한(20)까지만. "많이 밀림" 숫자 안 보여줌.
- 간격은 결석으로 리셋되지 않음. 100일 밀린 단어도 그냥 "due"일 뿐, 정상 복습.
- 복귀 문구: "돌아오셨네요 🥑 오늘은 N개만 볼까요?" (밀림/실패 언어 금지).

### 4.5 "다시 볼게요" 규칙 — **미암기 강등 (개정됨)**

> **⚠️ 개정(2026-07-17).** 이전 규칙("복습 중 '다시 볼게요'는 암기를 해제하지 않는다 — 간격만 당긴다")은 **폐기.**

**새 규칙: "다시 볼게요" = 맥락 불문 미암기(`isMemorized = false`).**

- **왜 뒤집었나:**
  1. **혼란.** 같은 버튼이 맥락에 따라 암기 상태에 **정반대**로 작동했다(일반 학습=해제 / 복습=유지).
  2. **P6 위반.** 그 예외를 설명하려고 "복습에선 암기가 풀리지 않아요" **안심 문구**가 필요했다 —
     문구가 필요하다는 것 자체가 UI 자기모순의 증거.
  3. **논리.** 복습에서 "다시 볼게요"를 누른다 = **잊었다**는 뜻. 잊었으면 미암기가 맞다.
  4. **표준.** 잊음 = 강등/리셋이 업계 공통이다:

     | 앱/알고리즘 | 잊었을 때 |
     |---|---|
     | Anki | "Again" = lapse → **relearning 큐 + 간격 리셋**(기본 1일) |
     | SM-2 | 점수 < 3 → **반복 카운트 리셋** |
     | Quizlet | Mastered → **Still learning으로 되돌림** |
     | WaniKani | **SRS 레벨 하락**(Guru→Apprentice) |
     | Duolingo | 단어 **strength 하락** → 더 빨리 재등장 |

     → 기존의 "암기 유지"가 오히려 **예외적**이었다.
- **강등 후 동선:** 미암기가 되어 복습 풀에서 빠지고, **미암기·오답·별표 학습**에서 다시 배운다.
  다시 "외웠어요"가 되면 사다리 처음(3일)부터 재시작.
- **gentle함은 행동이 아니라 프레이밍으로 지킨다 (P5).** 진행도(외운 단어 수)가 줄어드는 것을
  "실패"로 말하지 않는다:
  - ❌ "틀렸어요" / "실패" / "까먹었네요"
  - ✅ "다시 배울 단어로 옮겼어요 · 곧 또 만나요" / "🌱 잊었으면 편하게 다시 볼게요"
  - 참고: Duolingo도 strength가 떨어져도 "실패"가 아니라 **"강화(strengthen)"** 로 말한다.

### 4.6 단어의 일생 (요약)

```
🆕 새 단어 → 🃏 카드학습
   ├ "다시 볼게요" → 미암기 → (복습 X) 미암기·오답·별표에서 계속 학습
   └ "외웠어요"   → 암기 ✅ (카운트=1) → 🥑 복습 풀 → 3일 뒤 재등장
                                             ├ due 전에 또 봄  → 간격만 뒤로 밀림 (칸 그대로)
                                             ├ due에 "외웠어요"  → 간격 ↑ (10→30→90→180→365→은퇴)
                                             └ "다시 볼게요"     → 미암기로 강등 → 위 루프로
                                                                   (은퇴한 단어도 여기로 복귀)
```

## 5. 사용자 경험

### 5.1 진입 경로 — 하나뿐 (홈)

```
🔔 알림  →  홈 "복습 · 12"  →  (설정 화면 건너뜀)  →  카드학습  →  완료 🥑
```

- **알림이 매일의 방아쇠**, 홈 배너가 **원탭 진입**, 목적지는 **기존 카드학습**.
- 필터 경로(구 "경로 B")는 **없다** (§3).

### 5.2 홈 진입점 — 컴팩트 배너 (개정됨)

> **⚠️ 개정(2026-07-17).** 이전안 "큰 히어로 카드(약 132px) + 맞춤/오답/별표를 '그 외 빠른 학습'으로 강등"은 **폐기.**
> 실제 홈의 세로 예산을 재보니 **"학습 중인 단어장"이 화면 밖으로 밀려났다**(§5.2.1).

- **형태: 컴팩트 배너 한 줄(약 58px).** `🥑 오늘의 복습 · N개 준비됨 ›` + 부제 "잊을 때가 된 단어 · 탭 한 번이면 바로 시작".
  - `N` = due(상한 표시). 부드러운 카운트, **빨간 배지·"밀림" 금지**(P5).
- **위치: 퀵액션(맞춤·오답·별표) 바로 위** = **학습 액션 블록의 머리.**
  - 근거: `StatsStrip`은 **지표(정보)**, 복습·맞춤·오답·별표는 **학습 액션**이다. **기능으로 묶는다.**
  - (검토 중 "최상단(검색 바로 아래)" 안도 나왔으나, 복습만 혼자 떠서 같은 성격의 액션들과 분리되므로 기각.)
- **색: 아보카도 그린 그라디언트 `#488325 → #2F5C18`** (`colors.reviewGradient`, 네 테마 공통).
  - ⚠️ **티에이룰 계열(`colors.accentActionGradient` = `#2A7B78 → #1F5C5A`)을 쓰면 안 된다** —
    실제 맞춤학습 카드가 이미 그 그라디언트라(`index.tsx`), 같은 색을 쓰면 배너가 **주인공이 아니라 경쟁자**가 되어
    "사이에 낀 것"처럼 보인다. (초기 목업의 실제 실패 원인.)
  - 브랜드 그린 `#6AB045`는 흰 텍스트 대비 **2.66:1로 미달** → 깊게 잡아 **4.5:1 이상** 확보.
  - ⚠️ **개정(2026-07-17):** 이 문서가 원래 지정한 `#4C8A2E`는 **실측 4.22:1로 목표에 미달**이었다
    (구현 중 계산해 확인). 의도(4.5:1 확보)를 지키려고 **`#488325`(4.62:1)** 로 한 단계 내렸다.
    육안 차이는 거의 없다. 어두운 쪽 `#2F5C18`은 7.88:1로 여유.
  - 흰 텍스트가 올라가므로 **부제를 투명도로 낮추지 말 것** — 대비가 깨진다. 위계는 크기로만.
- **간격: 비대칭.** 위는 넓게(StatsStrip과의 그룹 경계), 아래는 좁게(퀵액션과 근접).
  - **근접성(Gestalt)** 으로 `배너 + 퀵액션 = 한 덩어리`로 읽히게 하고, 등간격 밴드의 "낀" 느낌을 없앤다.
- **구별은 크기가 아니라 위치·색·형태·간격으로 만든다** — 세로 공간을 쓰지 않고도 위계는 만들어진다.
- 탭 = 설정 없이 바로 카드학습.
- **`"그 외 빠른 학습"` 라벨은 넣지 않는다** — 배너가 작아져 불필요하고(약 20px 절약), 현재 앱에도 없다.
- **due = 0이면 배너를 완전히 감춘다**(§5.3).

### 5.2.1 세로 예산 (측정)

iPhone 13 mini(375×812) 실측 — `app/(tabs)/index.tsx` 기준:

| 항목 | 높이 |
|---|---|
| 고정 헤더(캐릭터 56 + 인사) + 검색바 — **스크롤 안 됨** | 198 |
| 하단 탭 + 배너 광고(무료 사용자) | 133 |
| **→ 스크롤에 실제로 보이는 영역** | **≈ 481** |
| StatsStrip 72 + 퀵액션(**정사각** `aspectRatio:1`) 129 + 섹션헤더 42 | 243 |

- ❌ **히어로 132px** → 남는 자리 **106px** → 첫 단어장 카드(~110px)가 **절반 이상 잘림**
- ✅ **배너 58px** → 남는 자리 **180px** → 첫 카드가 **온전히 보임**

> ⚠️ **교훈:** 목업은 실제 화면의 근사일 뿐이다. 이 검토 전까지 목업엔 **고정 헤더(캐릭터+인사)가 빠져 있었고**
> 퀵액션도 납작하게 그려져 히어로가 실제보다 후해 보였다. **구현 전 실제 컴포넌트 높이로 다시 확인할 것.**

### 5.3 콜드스타트 (due 0개) — 아무것도 표시하지 않는다 (개정됨)

> **⚠️ 개정(2026-07-17).** 이전안 "0개면 큰 격려 카드(🌱 아직 복습할 단어가 없어요…)"는 **폐기.**

- **왜 폐기했나:** **"빈 자리"를 "빈 상태 카드"로 채워 해결하려던 게 모순**이었다.
  그 카드도 ~110px를 먹으며 "학습 중인 단어장"을 밀어낸다 — 게다가 **신규 유저는 첫 3일간
  "복습할 게 없다"는 안내가 자리를 차지하는** 꼴이 된다.
- **새 규칙: due = 0 → 배너를 아예 렌더하지 않는다.** 대체 카드도 없다.
  - 즉 **복습이 없는 날의 홈 = 지금 앱의 홈과 100% 동일.** 아무것도 바뀌지 않는다.
- **발견(discovery)은 어떻게?** — **3일차에 배너가 나타나는 것** + **권한 시트(§8.4)** 가 담당한다.
  (Duolingo도 "연습할 것 0개" 카드를 띄우지 않는다.)
- **첫 등장까지 3일**(§4.2 D5) — ⚠️ 신규 유저는 그동안 이 기능을 못 본다. 튜닝 가능한 값(§10).

### 5.4 세션 = 기존 카드학습 그대로

- 기존 플래시카드 화면·버튼("다시 볼게요 / 외웠어요") 재사용. **새 채점 UI 0.**
- 뒤에서 `lastReviewedAt` 자동 갱신(§4.3).
- **안심 문구는 §4.5 개정으로 불필요해졌다.** 대신 부드러운 톤 한 줄만:
  "🌱 잊었으면 편하게 '다시 볼게요' · 다시 배울 단어로 옮겨 곧 또 만나요"
- 완료는 "다음 200개 더" 없이 **"오늘은 충분해요"** 톤(P1/P5).

- ⚠️ **새 컬럼 시 `features/vocab/db.ts` rowTo* 매퍼도 동기 갱신** (과거 sourceLanguage 누락 → 일본어 TTS 무음 사례).
- **시드 전략:** 기존 암기 단어는 `lastReviewedAt = NULL`. `memorized_log`(migration 017)가 있으면
  그 날짜로 시드, 없으면 마이그레이션 시각으로 채워 **업데이트 직후 128개가 한꺼번에 due로 쏟아지는 것을 방지**(P1).
- 재활용: `isMemorized`·`wrongCount`·`isStarred`·`memorized_log`.

## 7. 동기화 — **스코프 포함 (개정됨)**

> **⚠️ 개정(2026-07-17).** 이전엔 "Phase 1 로컬 전용, 동기화는 Phase 2(후속)"였으나 **완성형 스코프로 편입**(D8).

- **왜 넣나:** `lastReviewedAt`이 이 기능의 엔진인데, 로컬 전용이면 **재설치·기기 변경 시 복습 진도가 통째로 리셋**된다.
  기능이 초기화되는 셈이라 "큰 업데이트"에 맞지 않는다.
  - ⚠️ **실제로는 더 나쁘다:** 엔진이 `lastReviewedAt = NULL`인 암기 단어를 **"due 아님"으로 취급**하므로
    (복원 직후 서재 전체가 쏟아지는 P1 위반을 막으려는 규칙 — §4.3), 동기화 없이 **로그인 한 번이면
    그 단어들은 영영 복습에 안 걸린다.** 조용히 기능이 무력화된다.
- **어떻게:** `cloud_words`에 `last_reviewed_at`(bigint) / `review_success_count`(int) 추가.
  마이그레이션: `supabase/migrations/20260717000000_review_sync.sql`.
- **병합 = 행 단위 LWW** (마지막 push가 이김) — `cloud_words`의 다른 컬럼과 동일.
  - `study_days`처럼 GREATEST 병합 RPC를 **두지 않는다**: 단어 행은 이미 통째로 LWW이고
    (`is_memorized`·`wrong_count`도 같은 노출), 두 컬럼만 특별 병합하면 규칙이 갈라진다.
  - 최악의 경우는 "두 기기에서 같은 단어를 같은 디바운스 창(30초) 안에 학습" → 늦게 push한 쪽이 이겨
    예정일이 조금 당겨지는 정도. 스스로 수렴한다.
- ⚠️ **배포 순서: 서버 마이그레이션이 앱보다 먼저.** 호환은 **한 방향으로만** 성립한다.
  - 구 클라이언트 → 신 서버: **OK** (컬럼 생략 → nullable/default가 받아줌). 라이브 앱은 안전.
  - 신 클라이언트 → 구 서버: **깨진다.** upsert가 없는 컬럼을 보내면 PostgREST가 PGRST204를 내고
    배치 전체가 실패 → dirty가 안 빠져 **단어 동기화 전체가 침묵 속에 막힌다**
    (`position` int4 사고와 같은 실패 방식).

### 7.1 ⚠️ 함정 — `INSERT OR REPLACE`는 빠진 컬럼을 지운다

이 기능에서 가장 조용한 실패 지점이다. pull과 첫 로그인은 단어 행을 **통째로 갈아끼우므로**,
INSERT 컬럼 목록에서 빠진 값은 보존되는 게 아니라 **DEFAULT(NULL/0)로 초기화된다.**
복습 컬럼을 빠뜨리면 pull이 돌 때마다 진도가 지워지고 → NULL이라 due가 안 되고 → **앱은 멀쩡해 보인다.**

**복원 경로 = pull 하나(갱신 완료):**

| 위치 | 언제 |
|---|---|
| `features/sync/engine.ts` pull `INSERT OR REPLACE INTO words` | 동기화마다 |

첫 로그인 "클라우드 선택"도 별도 복원 함수를 쓰지 않는다 — `features/sync/first-login.ts`가
`clearAllData` 후 `pullChanges`를 불러 위 INSERT를 그대로 탄다. (한때 `db.ts`에
`mergeCloudData`/`replaceLocalWithCloudData`가 있었으나 contexts→features 리팩터 때
호출자를 잃은 죽은 코드였고, 2026-07-17 삭제했다. 죽은 코드에 복습 컬럼을 실어두면
"복원 경로가 지켜지고 있다"는 착시만 준다.)

**새 단어를 만드는 INSERT(addWord·addBatchWords·createCuratedList·copyWords·mergeLists·샘플 시드)는
복습 컬럼을 넣지 않는 것이 맞다** — 미암기로 시작하므로 NULL/0이 정답.

🛡️ **`__tests__/review-sync-columns.test.ts`가 이 규칙을 강제한다.** 소스의 INSERT 컬럼 목록을 읽어
복원 경로(pull)에 복습 컬럼이 있는지, 새 단어 생성 INSERT엔 없는지 검사한다. 전례(컬럼 추가 시
매퍼 누락 → `sourceLanguage`가 새어 일본어 TTS 무음)를 자동화한 가드다.
**`words`에 새 컬럼을 추가할 때 이 테스트를 함께 볼 것.**

- **매퍼 4곳도 함께 갱신됨:** `wordToCloudRow`(push) · `dbRowToWord`(pull) · `cloudWordToWord` ·
  `engine.ts:rowToWord`(로컬 행 → push 도메인). 계약: `shared/contracts.ts`의 `WordSchema` / `CloudWordSchema`.
- ⚠️ **`?? 0`이 아니라 `?? null`**: `lastReviewedAt`을 0으로 뭉개면 1970-01-01이 되어 복원한 기기에서
  서재 전체가 즉시 due로 쏟아진다.
- ⚠️ 기존 동기화 함정 회피: 큰 정수 컬럼 타입(`last_reviewed_at`은 ms라 처음부터 **bigint** — int4였으면
  `position`처럼 22003으로 터진다), pull 1000행 잘림(키셋 페이지네이션), tombstone 가드. 각각
  `project_cloud_words_position_int4`·`project_sync_pull_pagination_fix`·`project_sync_delete_resurrection` 참고.

## 8. 알림 — **스코프 포함 (신규)**

> **효과의 실제 엔진.** 이게 없으면 "잊을 때 다시 만난다"가 **앱을 우연히 열어야만** 작동하는 반쪽이 된다.
> (이전 보류 판단의 핵심 사유이기도 했다 — §0.)

### 8.1 발송 규칙

- **방식:** `expo-notifications` **로컬** 스케줄 (서버·푸시 인프라 불필요).

#### 8.1.1 ⚠️ "due=0이면 안 보냄"을 어떻게 지키나 (구현 핵심)

**"매일 저녁 8시 반복 알림" 하나로는 이 약속을 지킬 수 없다.** 로컬 알림은 OS가 미리 잡아두고
발사하는 구조라, **8시에 우리 코드가 깨어나 "오늘 복습할 게 있나?"를 확인할 방법이 없다.**
반복 트리거를 쓰면 복습거리가 없는 날에도 부르게 되어 §8.3의 약속이 거짓말이 된다.

**해법: 미래의 due를 미리 계산해, 실제로 복습거리가 있을 날짜만 골라 일정을 잡는다.**
(`features/study/review/notification-plan.ts` — 순수 모듈)

- **이 예측이 정확한 이유:** due는 `isMemorized`·`lastReviewedAt`·`reviewSuccessCount`로만
  결정되고 그 값들은 **학습해야만 바뀐다.** 앱을 안 열면 예측은 근사가 아니라 **정확**하다
  (시간이 흐르면 due는 늘기만 한다). 학습하면 그 순간 앱이 켜져 있으므로 다시 계획한다.
- **어긋나는 유일한 경우:** 다른 기기에서 학습(동기화 전). "복습거리가 없는데 부르는" 쪽으로만
  틀리고 pull 이후 스스로 교정된다.
- **14일치를 잡아둔다.** 하나만 잡으면 안 된다 — 알림의 목적이 **앱을 안 여는 사용자를 데려오는
  것**인데, 첫 알림 발사 후 앱을 안 열면 다음 일정을 잡아줄 사람이 없어 영영 조용해진다.
  iOS 대기 알림 상한 64개 대비 여유.
- **재계획은 전체 취소 후 재생성.** 학습 한 번에 여러 날의 예측이 동시에 바뀌므로 증분 추적이
  재생성보다 비싸고 틀리기 쉽다. 15개 남짓이라 값싸다. 데이터·설정 변경 시 디바운스(1.5초).
- **시간: 기본 저녁 8시(20:00)** — 설정에서 변경 가능(§8.3).
  - 근거: 퇴근·하교 후 잠들기 전, 국내 학습 시간대로 가장 무난. Duolingo 기본값도 저녁 7~8시대.
  - due는 **날짜 단위**로 계산되므로 하루 중 어느 시각이든 무방 — 그래서 시각은 순수 UX 선택.
- **빈도: 1일 1회.** 이 상한이 "스팸 안 한다"는 우리의 **실제** 약속이다.
- **due = 0이면 보내지 않는다.** (복습할 게 없는데 부르지 않음)
- **톤(P5):** "밀렸어요 / 놓쳤어요 / 스트릭 끊겨요" **금지.** 초대이지 독촉이 아니다.
  - 문구 예: "복습하기 좋은 단어 12개 🌱 / 잊을 때가 된 단어를 모아뒀어요. 오늘도 3분이면 충분해요."
- 탭 → 홈 복습 배너(또는 바로 세션)로 딥링크.

### 8.2 조용한 시간대는 **OS에 위임** (개정됨)

> **⚠️ 개정(2026-07-17).** 이전 규칙 "**조용한 시간대 존중(밤에 안 보냄)**"은 **폐기.**

- **왜 폐기했나:** 사용자가 알림 시간을 고를 수 있게 되면(§8.3) 이 약속은 둘 중 하나가 된다 —
  **거짓말**(밤 11시로 맞추면 약속 위반) 또는 **간섭**(밤 시간대를 못 고르게 막으면 새벽 학습자에게 참견).
  앱이 시간을 자동으로 정할 때나 성립하던 문구였다.
- **올바른 계층:** 조용한 시간은 **iOS 집중 모드 / Android 방해 금지**가 이미 담당한다.
  사용자가 OS에 "밤엔 조용히"를 설정해뒀다면 우리 알림도 자동으로 조용해진다.
  **앱이 이를 중복 구현하면 모순만 낳는다.**
- **따라서 시간 선택에 밤 제한을 두지 않는다.** 사용자 자유.
- **안심 문구는 지킬 수 있는 것만 말한다:** "밤엔 안 보내요"(못 지킴) ❌ →
  **"매일 저녁 8시 · 언제든 끄거나 시간을 바꿀 수 있어요"** ✅ (구체적 사실 + 통제권).
  - "시간을"은 필수 — 없으면 *뭘* 바꾸는지 모호하다. "설정에서"는 뺀다(안심시키는 자리이지 사용법을 알려주는 자리가 아님).
  - "하루 한 번"은 바로 위 본문("하루 한 번, 딱 그때만요")과 중복되므로 이 줄에서 제거.

### 8.3 설정 — 토글 하나 + 시간 하나

- 설정 → **복습 알림** 섹션:

  | 행 | 값 | 부제 |
  |---|---|---|
  | 복습 알림 받기 | 토글 | "복습할 단어가 있을 때만" |
  | 알림 시간 | 오후 8:00 | "하루 한 번" |

- 하단 노트: "복습할 단어가 없는 날은 보내지 않아요. 조용한 시간대는 기기의 집중 모드·방해 금지 설정을 따라요."
- **딱 2줄.** 간격·`DAILY_CAP` 같은 기계는 노출하지 않는다(P3).
- **왜 시간 설정을 넣나(P3 예외):** 보통은 설정을 늘리지 않는 게 원칙이지만, **알림은 이 기능의 엔진**이다.
  시간이 안 맞아 거슬리면 사용자는 **알림을 꺼버리고**, 그러면 기능의 가치가 통째로 날아간다.
  아침형/저녁형을 감당하는 **값싼 보험.**

### 8.4 권한 요청 — 2단계 soft ask

- **타이밍: 첫 복습이 생긴 날(3일차).** 앱 설치 직후에는 요청하지 않는다 —
  **가치를 보여준 뒤**(홈에 "복습 4개 준비됨"이 이미 떠 있는 상태) 물어야 수락률이 높다.
- **2단계가 핵심:**
  1. **우리 시트(soft ask)** 로 먼저 묻는다 — "첫 복습이 준비됐어요! 잊을 때쯤 살짝 알려드릴까요?
     하루 한 번, 딱 그때만요." → [알림 받기] / [나중에]
  2. **"알림 받기"를 누른 경우에만** iOS 시스템 권한 창을 띄운다.
- **왜 2단계인가:** iOS는 **시스템 창을 한 번 거절하면 앱에서 다시 물어볼 수 없다**(설정으로 보내야 함).
  시스템 창은 한 발의 총알이므로 **아껴 쓴다.**
- **"나중에"도 존중(P5):** 앱은 그대로 전부 작동한다. 설정에서 언제든 켤 수 있고, **조르지 않는다.**
- 온보딩이나 권한 시트에서 **시간까지 묻지 않는다** — 마찰이 커져 수락률이 떨어진다.
  일단 저녁 8시로 시작하고, 바꾸고 싶은 사람만 설정에서.
