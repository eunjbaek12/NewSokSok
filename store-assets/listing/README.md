# Google Play Console — 스토어 등록 텍스트

Play Console에 앱 등록할 때 입력해야 하는 텍스트들을 언어별로 정리한 폴더.

## 파일

**Play 용** — `<lang>.md`

- [`ko.md`](./ko.md) — 한국어 (기본 언어)
- [`en.md`](./en.md) — 영어
- [`ja.md`](./ja.md) · [`vi.md`](./vi.md) · [`zh.md`](./zh.md)
- [`es.md`](./es.md) — 스페인어 (`es-ES` · `es-419`, 2026-08-05 신설)
- `play-description-1.3.0/*.txt` — 실제 붙여넣은 전체 설명 스냅샷

**App Store 용** — `ios-<lang>.md`

- [`ios-ko.md`](./ios-ko.md) · [`ios-en.md`](./ios-en.md) — ASC 등록 로케일
- [`ios-es.md`](./ios-es.md) — 스페인어 (Spain · Mexico, 2026-08-05 신설)
- [`ios-ja.md`](./ios-ja.md) · [`ios-vi.md`](./ios-vi.md) · [`ios-zh.md`](./ios-zh.md) — **ASC 미등록**(원고만 있음)

**버전별**

- `release-notes-<ver>.txt` — Play 출시 노트, `<로케일>` 태그 형식 그대로 붙여넣기
- `appstore-<ver>.txt` — App Store "이번 버전의 새로운 기능" + 홍보 텍스트

> ⚠️ **같은 로케일 원고가 Play 용·iOS 용 두 벌 있다.** 문구를 바꿀 땐
> `grep -rn "<문구>" store-assets/listing/` 로 **양쪽 다** 확인할 것 — 한쪽만 고쳐서
> iOS 원고 3개에 거짓 문구가 남았던 이력이 있다(2026-08-02).

## Play Console 입력 위치

각 텍스트가 어디에 들어가는지:

| 텍스트 항목 | Play Console 경로 |
|---|---|
| 앱 이름 | 앱 상세정보 → 앱 이름 |
| 짧은 설명 | 스토어 등록정보 → 짧은 설명 |
| 전체 설명 | 스토어 등록정보 → 전체 설명 |
| 출시 노트 | 프로덕션 → 출시 만들기 → 출시 노트 |
| 카테고리·등급·광고·결제 | 앱 콘텐츠 / 등급 |

## 출시 노트를 쓸 때 — 버전을 타지 않는 규칙

버전별 `release-notes-<ver>.txt` 상단 메모에 복사돼 다니던 것을 여기로 모았다
(500자 규칙은 1.4.0·1.5.0 두 파일에 같은 내용으로 들어가 있었다). **새 버전 노트는
지난 버전 파일을 복사하지 말고 여기서 시작한다** — 규칙이 낡았을 때 고칠 곳이 하나여야 한다.

- 🔴 **Play 출시 노트는 로케일마다 500자 제한이다.** 붙여넣기 전에 로케일마다
  `[...s].length` 로 셀 것(문자 수라 서로게이트가 섞이면 `.length` 와 다르다).
  1.4.0 은 en-US 가 530자로 넘어 있었고 1.5.0 도 처음 쓴 565자에서 줄였다 —
  **두 번 다 영어가 먼저 넘쳤다.**
- **스페인어는 영어보다 20~25% 길어진다.** 같은 구조로 그대로 옮기면 넘치므로
  「그 밖에」 같은 꼬리 항목을 한 줄로 합친다.
- 🔴 **그 로케일 사용자가 앱을 열면 실제로 보이는 것만 적는다.** 큐레이션 덱은 뜻 언어
  필터를 타므로 ko→en 덱은 **뜻 언어가 en 인 사용자에게만** 목록에 뜬다 — 한국어 노트에
  적으면 거짓이 된다(1.3.1·1.5.0 에서 두 번 겪었다).
- **요금제를 언급할 땐 앱 화면과 같은 이름을 붙인다** — ko `무료 (Free)` · en `Free` ·
  es `Gratis (Free)`(`i18n/locales/*.json` 의 `freeTitle`). "무료 한도"라고만 쓰면
  어느 요금제 얘긴지 흐려진다.
- **서버 정책과 짝인 문구는 적용 시점을 확인하고 쓴다.** 1.5.0 의 "Free 50" 은 서버
  마이그레이션이 적용돼야 참이 됐다 — 순서가 어긋나면 스토어에 적은 것과 앱이 주는 것이
  달라진다(`docs/release-checklist-next.md`).

## 🔴 App Store Connect 「앱 정보 → 기본 언어」는 English 다 (2026-08-24 결정)

**기본 언어의 자산은 "자기 것이 없는 로케일이 물려받는 값"이다** — 등록정보 텍스트도,
**미리보기 및 스크린샷도** 그렇다.

🔑 **이 앱에서는 영어가 맞다. 앱 UI 가 ko·en·es 셋뿐이기 때문이다.**

| 스토어 로케일 | 그 사용자가 앱을 열면 보는 UI |
|---|---|
| ko · en · es | 그 언어 |
| **ja · vi · zh** | **영어** (UI 번역이 없다) |

ja·vi·zh 사용자는 **영어 앱을 받는다.** 기본 언어가 한국어이면 그 셋은 **한국어 스크린샷**을
물려받아, 한국어 화면 사진을 보고 받았더니 영어 앱인 상태가 된다 — 두 겹으로 어긋난다.
기본 언어가 영어면 물려받는 것이 **영어 스크린샷**이고, 이는 **그들이 실제로 받는 화면과 같다.**

⚠️ **바꾸기 전에 ko-KR 에 한국어 스크린샷이 따로 올라가 있어야 한다.** 안 그러면 바꾸는 순간
한국 사용자가 영어 스크린샷을 보게 된다 — 주력 시장이라 가장 큰 손해다.
✅ **2026-08-24 확인: ko·en 은 각 로케일에 이미 따로 올려 두었다.** 자산도 저장소에 있다
(`screenshots/appstore/final/{6.9,6.5}inch/{ko,en}` 각 9장).

🔑 **그래서 ja·vi·zh 는 스크린샷을 따로 만들 필요가 없다.** 영어를 물려받으면 그것이 정답이다.
⏭️ **es 스크린샷은 아직 없다** — 지금은 영어를 물려받는다(한국어를 물려받던 것보다는 낫다).
스페인어 UI 가 있으므로 언젠가 만들면 더 맞지만 급하지 않다.

⚠️ **확인 못 한 것 둘.** ⑴ 심사 중에 기본 언어를 바꿀 수 있는지 — **제출 전에 바꾸는 편이 안전**.
⑵ 검색 색인에 영향이 있는지 — 이 저장소에 "en-US 칸 전체가 한국 스토어에 색인된다"는 실측이
있는데(`ios-ko.md` §검색 실측 ⑫) 기본 언어가 바뀌면 그 관계가 달라지는지는 미확인이다.
ko-KR 은 자기 이름·부제·키워드를 그대로 가지므로 직접 손실은 없어야 하지만,
**바꾼 뒤 한국 검색을 한 번 재 볼 것.** 기준선은 `ios-ko.md` §검색 실측의 8/23 값이다.

## 🔴 로케일을 새로 추가할 때 — 로케일마다 따로 채워야 하는 칸이 있다

**2026-08-24, ja·vi·zh 를 추가하고 1.6.0 을 심사에 넣으려다 막혔다.**

```
심사 절차를 시작하려면 아래의 항목이 필요합니다.
중국어(번체) - 개인정보 처리방침 URL - 반드시 기입해야 하는 필드입니다.
일본어     - 개인정보 처리방침 URL - 반드시 기입해야 하는 필드입니다.
베트남어    - 개인정보 처리방침 URL - 반드시 기입해야 하는 필드입니다.
```

🔑 **개인정보 처리방침 URL 은 앱 단위가 아니라 로케일 단위다.** 이미 라이브인 앱이라
ko·en·es 는 채워져 있었지만, **새로 추가한 로케일은 빈 채로 생기고** App Store Connect 가
제출 자체를 막는다. 위치는 **「앱 개인정보」(= 앱이 수집하는 개인정보)** 페이지의
개인정보 처리방침 섹션이고, 그 안에서 **언어를 바꿔 가며** 채운다(「앱 정보」가 아니다).

**여섯 로케일 모두 같은 값을 넣으면 된다** — 그 페이지가 ko/en 토글을 자체적으로 갖고 있다:
`https://eunjbaek12.github.io/NewSokSok/privacy-policy`

⏭️ **다음에 로케일을 추가하면 이 칸부터 채울 것.** 원고(이름·부제·키워드·설명·새 기능)만
준비하고 넘어가면 제출 직전에 막힌다.
⚠️ 같은 화면에서 함께 확인할 것: **마케팅 URL 은 반드시 비워 둘 것** — 그 칸에 공백이 들어가
iOS 인증이 거부된 전례가 있다. 지원 URL 은 `https://eunjbaek12.github.io/NewSokSok/`.
