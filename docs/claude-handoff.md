### 발견 버그 — 게스트 → Google → 로그아웃 → 게스트에서 한도 리셋

- 상태: **코드 수정 완료 · 실기 검증 대기 · 1.6.0 서버 마이그레이션 전 확인 필요**
- 실기 재현(2026-08-18): 게스트 한도+광고 보너스 20단어 소진 → Google 로그인 → Google 로그아웃 → `바로 시작하기` → 기존 게스트 단어장이 보이지 않고 AI 한도가 0으로 리셋됨.
- 단어장 판정: 현재 설계상 예상된 계정 격리 동작이다. 게스트 단어장은 Google 첫 로그인 때 로컬에서 클라우드로 업로드되고, Google 로그아웃이 성공하면 `features/auth/store.ts:logout()`이 클라우드 계정 데이터를 로컬에서 지운다. 따라서 다시 게스트로 시작했을 때 이전 단어장이 보이면 오히려 계정 데이터 노출이다. 이전 단어장은 같은 Google 계정으로 다시 로그인하면 클라우드에서 복원돼야 한다(별도 확인 필요).
- 한도 판정: **의도와 맞지 않는 우회 버그다.** 직접 게스트 로그아웃은 익명 세션을 보존하지만, 게스트 상태에서 `signInWithGoogle()`이 `signInWithIdToken()`을 호출하면 익명 세션이 Google 세션으로 교체된다. Google 로그아웃 뒤 `loginAsGuest()`에는 재사용할 익명 세션이 없어 `signInAnonymously()`로 새 UUID를 만든다. 사용량은 UUID별이라 0으로 시작한다.
- 영향: 1.6.0 서버 정책 적용 뒤에는 이 경로로 새 게스트의 첫 24시간 300단어를 반복 획득할 수 있다. 스펙이 막으려던 `로그아웃 → 재진입`보다 탭 몇 번만 더 필요한 손실 없는 우회라 출시 전 해소해야 한다.
- 테스트 공백: `__tests__/auth-guest-anonymous-session.test.ts`는 `게스트 → 로그아웃 → 게스트`만 검증하며, `게스트 → Google → 로그아웃 → 게스트` 세션 연속성은 검증하지 않는다.
- 공식 권장과 차이: Supabase는 익명 사용자를 영구 사용자로 전환할 때 OAuth `linkIdentity()`를 사용해 같은 사용자 ID에 신원을 연결하도록 안내한다. 현재 앱은 직접 `signInWithIdToken()`으로 별도 Google 세션에 로그인한다. 다만 identity linking만으로도 Google 로그아웃 후 다시 익명으로 접근할 수 있는 것은 아니므로, 수정안은 데이터 승격·기존 Google 계정 충돌·게스트 세션 복원 정책까지 함께 설계해야 한다.

#### 권장 수정안

- **게스트 익명 세션의 refresh token을 SecureStore에 별도 보관하고 복원한다.** Google/Apple 로그인 직전에 현재 세션이 익명이면 토큰을 저장한다. 클라우드 로그아웃 후 `바로 시작하기`에서는 새 익명 계정을 만들기 전에 저장한 refresh token으로 `supabase.auth.refreshSession({ refresh_token })`을 호출해 원래 익명 UUID를 복원한다.
- 복원 성공 시 refresh token이 회전하므로 반환된 새 토큰을 즉시 SecureStore에 덮어쓴다. 게스트 세션의 `TOKEN_REFRESHED` 이벤트에서도 최신 토큰을 저장한다.
- 저장 토큰이 없거나 서버에서 무효라면 그때만 `signInAnonymously()`로 새 게스트를 만들고 새 토큰을 저장한다.
- `deleteAccount()`처럼 기기 흔적 전체 삭제를 약속한 경로에서는 보관 토큰도 삭제한다. 일반 게스트 로그아웃과 Google 로그아웃에서는 삭제하지 않는다.
- 단어장은 현행 유지: 게스트 데이터가 Google로 업로드된 뒤 Google 로그아웃하면 로컬에서 지우고, 다시 게스트로 돌아와도 노출하지 않는다. 복원 대상은 익명 서버 신원/한도이며 단어 데이터가 아니다.
- 이 안을 고른 이유: 기존 Google 계정 로그인·첫 로그인 합치기·Apple 로그인을 그대로 유지하고 서버 DB 변경이 없다. `linkIdentity()`는 신규 Google 신원 승격에는 정석이지만 기존 Google 계정 충돌과 데이터 병합 정책을 다시 설계해야 하며, Google 로그아웃 후 익명 접근도 별도로 해결해야 한다. 기기 ID 기반 서버 한도는 서버 함수와 모든 Edge 호출 계약을 바꾸고 조작 가능한 새 식별자를 추가하므로 과하다.
- 필수 회귀 테스트: (1) 게스트 A → Google → 로그아웃 → 게스트가 A의 UUID/사용량 복원, (2) 회전 토큰 재저장, (3) 무효 토큰이면 새 익명 계정 폴백, (4) 직접 게스트 로그아웃 유지, (5) 늦게 끝난 Google 로그아웃이 복원된 게스트를 지우지 않음, (6) 계정 삭제 시 보관 토큰 삭제.
