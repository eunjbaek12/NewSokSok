# 예문 학습이 묻지 않고 AI 한도를 쓰던 것 — 설계

2026-09-02 · 목업: `예문 학습 차감 설계안` (Artifact)

---

## §1 무엇이 문제인가

예문 없는 단어가 섞인 단어장에서 「예문 학습」을 누르면, 앱은 **묻지 않고** 그 단어
전부를 배경에서 AI로 채운다. `screen.tsx:311`

```
all = 필터에 걸린 단어
  ├ ready   = 예문 있고 빈칸 가능        → 바로 출제
  └ missing = 예문 없음                 → startBackgroundEnrich(missing)
                                          동시성 3 · 상한 없음 · 단어당 한도 1
```

화면에는 「AI 예문 생성 중 3/12」 배너만 뜬다. **차감 이야기는 없다.**

🔴 **한 번의 탭이 하루치를 넘긴다.** Free 한도는 하루 50단어다.

```
100단어 덱 · 예문 없는 단어 80개
  → 50개 채우고 한도 소진
  → 남은 30개는 뜻만 돌아와 예문 없이 끝남
  → 사용자가 본 것은 진행 배너 하나
```

🔑 문제는 **알림이 아니라 동의**다. 배너에 차감 문구를 넣어도 이미 나간 뒤다.

---

## §2 세우는 규칙

> **AI가 단어를 채우는 일은 언제나 사용자가 누른 버튼 뒤에서만 일어난다.**

채우기·사진 스캔·AI 생성이 이미 이 규칙을 지킨다. 예문 학습만 예외였다.

따라오는 것 하나: **거절이 실패가 되면 안 된다.** 「예문 학습」이 한 약속은 학습이지
생성이 아니다. 예문 있는 단어가 8개면 8개로 학습이 성립한다.

---

## §3 대상 — `isBareWord` 를 그대로 쓸 수 없다

🔴 **두 집합이 다르다.**

| | 정의 | 조건 |
|---|---|---|
| `isBareWord` (1.6.2 채우기) | 뜻은 있고 발음·예문·정의가 **모두** 빔 | AND |
| 예문 학습이 필요로 하는 것 | 예문이 없음 | `!exampleEn` |

실측(2026-09-02, 전체 사용자·살아 있는 단어):

```
예문 없는 단어 1,672
  ├ 1,212  isBareWord 가 잡음
  └   460  못 잡음 (발음·정의는 있고 예문만 없음)   ← 28%
```

그래서 「배너를 누르면 기존 채우기 시트」로 두면 **12개라고 알린 뒤 4개만 채워진다.**
몰래 차감을 고치려다 새 거짓말을 만드는 셈이다.

✅ **시트는 그대로 쓰되 대상만 갈아 끼운다.**

- 예문 학습에서 열면 → 대상 `!exampleEn`, 제목 「예문 없는 단어 채우기」
- 단어장에서 열면 → 대상 `isBareWord`, 제목 「뜻만 있는 단어 채우기」

모양·차감·부분 채움 판정·고르기 화면·얼굴 판정(`face.ts`)은 **한 벌**이다.

⚠️ `detect.ts` 주석의 "OR 로 하면 대상이 폭증한다"는 경고는 **단어장에 상시 뜨는
배너**에 대한 것이다. 목적이 예문인 화면에서 예문 없는 단어를 세는 것은 오히려
정확한 대상이다.

## §4 화면

### 상태 A — 예문 있는 것 8 · 없는 것 12

학습은 **그냥 시작한다.** 위에 배너 한 줄.

```
● 예문 없는 단어 12개                    ›  ✕
  채우면 함께 학습할 수 있어요
```

배너를 무시하면 그것으로 끝이다 — 차감 없음. 누르면 채우기 시트가 뜬다.

### 상태 B — 예문 있는 것 0

```
        📄
  예문이 있는 단어가 없어요
  12개를 채우면 시작할 수 있어요

  [ 12개 채우기 ]   [ 돌아가기 ]
```

🔑 「채워야 시작된다」는 **여기서만** 나온다. 규칙을 새로 만든 게 아니라 §2에서 저절로
따라온다.

### 시트 (배너를 눌렀을 때)

1.6.2 채우기 시트와 같은 틀. 문구만 예문 쪽으로.

```
예문 없는 단어 채우기
예문과 함께 비어 있는 발음·정의도 채웁니다. 이미 적어둔 것은 그대로 둡니다.

  예문 없는 단어          12개
  지금 채울 수 있는 수     12개

[ 12개 채우기 ]
  채울 단어 고르기
```

## §5 차감 — 지금 흐름 그대로 (2026-09-02 확정)

**단어 검색과 똑같다: 호출할 때 차감하고, 실패하면 환불한다.** 새로 만들 것이 없다 —
같은 `enrichWord` 를 타므로 서버(`supabase/functions/enrich-word/index.ts`)가 이미 한다.

환불이 도는 경우 셋:

| 조건 | 응답 | 처리 |
|---|---|---|
| `isReal === false` 또는 뜻이 빔 | 404 `not_found` | 환불 |
| 폭주 산출물 | 500 `upstream_failure` | 환불 |
| 상류 실패 | 500 | 환불 |

⚠️ **예문이 안 온 경우는 환불 대상이 아니다.** 뜻이 있으면 200이고 차감이 남는다.
그런데 실측하니 **일어나지 않는다** — `full` 캐시 최근 20,000행 중 예문이 빈 것 **0건**.
일어나지 않는 일을 위해 자동완성과 규칙을 가를 이유가 없다. 그대로 둔다.

🔴 세는 법은 갈라야 한다. 지금 `useBareFill` 은 **발음만 채워져도 1로 센다.** 예문
학습에서는 **예문이 채워진 것만** 세야 「12개 채웠어요」가 거짓이 되지 않는다.

## §6 채운 뒤 흐름 — 시트가 닫힐 때 합류

세 갈래가 있었다.

| | 문제 |
|---|---|
| 진행 중 하나씩 합류 (지금 동작) | 학습 도중 총 문항이 슬금슬금 는다. 진도 표시가 흔들린다 |
| 다음 진입 때 포함 | 「채우기」를 누른 의도가 "지금 하고 싶다"인데 나갔다 다시 들어와야 한다 |
| **시트가 닫힐 때 한 번에 합류** ✅ | 경계가 뚜렷하다 |

채우기는 **시트 안에서** 일어나고 시트는 학습 화면 위에 뜬다. 시트를 닫는 순간이
자연스러운 경계다 — 진행 중 슬금슬금이 아니라 한 번에 늘고, 사용자는 「5개가
늘었어요」로 확인한다.

⚠️ **현재 배치는 건드리지 않는다.** `studyBatchSize` 로 나뉜 배치 한가운데를 바꾸면
남은 문항 수가 어긋난다. 합류는 **다음 배치부터**.

---

## §7 한도가 모자랄 때 — 이미 있는 것을 그대로

새로 설계할 것이 없다. 시트가 「지금 채울 수 있는 수」를 따로 보여주고, 한도가 대상을
자르면 `face.ts` 가 `quota` 얼굴로 간다.

| 상황 | 화면 |
|---|---|
| 한도 5 남음 | 대상 12 · 가능 5 를 따로 적고 버튼이 「5개 채우기」로 줄어든다. 「나머지 7개는 내일 이어서」 |
| 한도 0 | 「0개 채우기」는 누를 수 없다 → **광고가 주 버튼**, 부차는 「내일 이어서」 |
| 채운 뒤 잘림 | 「5개를 채웠어요 / 아직 7개에 예문이 없어요」 + 광고·내일·Pro. **학습은 5개 늘어난 채로 계속** |

🔴 **`partial` 과 `quota` 를 섞지 말 것.** 고르기에서 일부만 골라 다 채웠을 때
「오늘 광고 혜택을 모두 사용했어요」가 뜬 적이 있다 — 한도가 35개 남아 있었는데도.
남은 것이 있다고 해서 한도가 없는 것은 아니다. 예문 학습 배너도 **같은 판정을 그대로**
쓴다.

## §8 범위 밖 — 빈칸을 못 뚫는 단어

예문에 표제어가 **어떤 형태로도 안 나오는** 부류가 있다. 활용형 미스매치가 아니라
찾을 대상이 없다.

```
올리다 :: 그는 자신의 연구 논문을 저명한 학술지에 성공적으로 게재하여 …
遣る   :: 彼は日夜を問わず、研究室に籠もり、ひたすら難解な数式と格闘しておった。
```

빈칸을 뚫을 수 없어 출제에서 빠지는데 **조용히** 빠진다. 20개짜리 덱에서 8개만 나와도
사용자는 이유를 모른다.

이건 이 스펙의 문제가 아니라 **AI 생성 프롬프트 문제**이고 `backlog-examples-enrich.md`
P6 에 이미 있다. 여기서는 하나만 다룬다:

⚠️ **상태 B 의 문구가 거짓이 되는 경우.** 예문은 다 있는데 전부 빈칸을 못 뚫어 R=0 이면
「예문이 있는 단어가 없어요」는 틀린 말이다. 그 경우를 갈라 다른 문구를 낸다.
