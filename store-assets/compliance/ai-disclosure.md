# Generative AI 사용 신고

Play Console → 앱 콘텐츠 → **Generative AI (생성형 AI)** 섹션 답변.

2024년부터 Play 정책으로 생성형 AI를 사용하는 앱은 의무 신고 대상입니다.

---

## 핵심 사실

아보카도의 AI 사용 특성:
- **사용자가 본인 Gemini API 키를 직접 입력**하고, 그 키로 호출
- AI 호출은 **사용자 기기 → Google Gemini API**로 직접 전송 (우리 서버 미경유)
- 비용은 사용자 부담 (Google AI Studio 무료 티어 또는 유료)
- 데이터(단어·이미지)는 사용자가 명시적으로 AI 기능 트리거 시에만 전송

코드 근거: `lib/ai/gemini-client.ts`, `lib/translation-api.ts`, `features/curation/screen.tsx`

## 설문 답변

### Q. 앱에 생성형 AI 기능이 있나요?
**Yes**

### Q. AI 기능 목록과 설명

다음 기능들을 신고합니다:

**1. AI 자동 보강 (AI auto-fill)**
- 사용자가 단어만 입력하면 AI가 뜻·예문·발음을 자동 채움
- 입력 데이터: 단어 텍스트
- 출력: 뜻, 예문, 발음(IPA), 품사
- 모델: Google Gemini (사용자 본인 API 키)

**2. AI 단어 생성 (AI word list generation)**
- 사용자가 주제를 입력하면 AI가 단어장을 통째로 생성
- 입력 데이터: 주제 텍스트, 언어쌍, 난이도, 단어 개수
- 출력: 단어·뜻·예문 리스트
- 모델: Google Gemini

**3. AI 사진 OCR (Photo scan)**
- 사용자가 단어 목록이 적힌 사진을 촬영/선택하면 AI가 단어를 추출
- 입력 데이터: 사진 이미지
- 출력: 추출된 단어 텍스트 리스트
- 모델: Google Gemini Vision

**4. AI 번역 (Translation)**
- 단어 입력 시 다른 언어로 자동 번역
- 입력 데이터: 단어 텍스트, 입력 언어, 출력 언어
- 출력: 번역된 텍스트
- 모델: Google Gemini

### Q. AI 기능에 안전장치(safeguards)가 있나요?
**Yes — 다음과 같은 안전장치 적용**:
- AI 호출은 사용자의 명시적 액션(버튼 탭)으로만 트리거
- 사용자 본인의 API 키를 사용하므로 사용량과 비용을 본인이 직접 모니터링
- Google Gemini API의 자체 콘텐츠 안전 필터링 적용 (성인·폭력 콘텐츠 차단)
- AI 생성 결과는 사용자가 검토·수정·삭제 가능 (자동 저장되지 않음, 미리보기에서 선택해야 저장)

### Q. 사용자가 부적절한 AI 출력을 신고할 수 있나요?
**No (현재 미구현)** — 출시 후 추가 고려 사항

### Q. AI가 사용자 데이터로 학습되나요?
**No** — Google Gemini API는 기본적으로 사용자 입력을 모델 학습에 사용하지 않음 (사용자가 자신의 API 키 설정에서 별도로 설정 가능)

### Q. AI 출력이 사실로 신뢰될 수 있나요?
- 어휘 학습 보조용으로만 사용, 사용자가 결과를 검토하고 선택해서 저장
- 앱 내 이용약관 5번(`i18n/locales/ko.json:terms.sections[3]`)에 "AI 생성 결과의 정확성을 보증하지 않음" 명시

## 추가 텍스트 (있는 그대로 붙여넣기)

설문 마지막의 자유 입력란이 있으면:

```
아보카도의 AI 기능은 사용자가 본인의 Google Gemini API 키를 입력해 사용합니다.
앱 개발자 서버를 경유하지 않고 사용자 기기에서 Google API로 직접 호출되며,
입력 데이터(단어·사진)와 출력 결과는 우리 시스템에 저장되지 않습니다.
사용자가 명시적으로 AI 기능 버튼을 탭한 경우에만 작동합니다.

AI 기능은 다음 4가지입니다:
1. AI 자동 보강: 단어만 입력하면 뜻·예문·발음 채움
2. AI 단어 생성: 주제 입력 시 단어장 생성
3. AI 사진 OCR: 사진에서 단어 추출
4. AI 번역: 입력 단어를 다른 언어로 번역

Google Gemini 모델의 자체 안전 필터가 적용되며,
사용자는 AI 결과를 검토·수정·거부할 수 있습니다.
```

# AI asset declaration (스토어 등록정보 자산)

위 "생성형 AI" 신고와 **다른 항목이다.** 그쪽은 *앱이 AI를 쓰는가*를 묻고,
이쪽은 *스토어에 올리는 이미지를 AI로 만들었는가*를 묻는다.
Play Console에서 자산 업로드 시 뜨는 **AI asset declaration** 화면 답변이다.

## 답: "Label assets as created or edited using AI"

그다음 단계에서 **아래 자산만** 개별 표시한다.

| 자산 | 라벨 | 근거 |
|---|---|---|
| `00-hero-a` · `00-hero-b` | ✅ | 배경 일러스트 `screenshots/hero/hero.png`가 **Gemini 생성** |
| 앱 아이콘 (`icons/icon-512.png` 등) | ✅ | 3D 아보카도 씬이 AI 생성 |
| 기능 그래픽 (`feature-graphic/feature-{ko,en}.png`) | ✅ | 좌측 3D 아보카도(`assets/images/Avocado-3D-clean.png`)가 AI 생성 |
| `01-generate` `02-photo` `03-study` `04-stats` `06-autocomplete` `07-curation` `08-theme` | ❌ | 실제 앱 화면 캡처 + 직접 작성한 카피 + CSS 폰 목업 |

→ App Store 9장 중 2장 · Play 8장 중 2장 (+ 아이콘 · 기능 그래픽)

## 헷갈리는 자리 — 앱 화면 속 아보카도는 AI가 아니다

`04-stats`(연속 학습 카드) · `07-curation`(헤더) · `08-theme`·`00-hero-b`의 폰 안(홈 헤더)에도
아보카도가 보이지만, **이건 SVG 캐릭터**라 라벨 대상이 아니다. AI로 만든 것은
**3D 렌더 계열**(`Avocado-3D*.png`, `hero.png`)뿐이다. 파일 형식으로 갈린다고 기억하면 쉽다:

- **3D png = AI** → 아이콘 · 기능 그래픽 · 히어로 배경
- **SVG = 라벨 불필요** → 앱 UI 안에 그려지는 캐릭터

`00-hero-b`는 폰 안 캐릭터가 SVG여도 **배경판이 `hero.png`**라서 라벨 대상이다.

## 라벨을 붙이는 쪽이 안전한 이유

라벨 자체에는 불이익이 없다(노출·심사에 영향을 주지 않는다). 해당되는데 빠뜨렸을 때만
정책 위반이 된다. 경계가 애매하면 붙이는 쪽으로.

⚠️ **원본 그림을 교체하면 이 표도 갱신할 것.** `hero.png`는 README에 "교체 대상"으로 적혀 있다.
