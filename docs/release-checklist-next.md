| 항목 | 지금(임시) | 전환 후(목표) |
|---|---|---|

### 왜 되돌렸나

`20260813000000`이 새 정책을 서버에만 적용했는데, 그 정책과 짝이 되는 앱이 아직
심사·배포 전이었다. 특히 `grant_rewarded_bonus`의 시그니처가
`(uuid,integer,integer)` → `(uuid)`로 바뀌며 **옛 시그니처를 drop**해서, 출시된 앱의
`RewardedAdModal`이 "함수 없음"으로 실패했다 — **광고를 끝까지 봐도 단어가 0개.**
8/13부터 8/14까지 그 상태였다.

### 전환 절차 (순서 중요)

1. **앱을 먼저 배포한다.** 서버가 먼저면 아직 업데이트하지 않은 사용자의 한도가 갑자기
   줄고 리워드가 깨진다.
2. `supabase/migrations/20260813020000_pro_3000_monthly_pool.sql`을 push한다.
   **이미 작성돼 있고 미적용 상태로 대기 중**이다(되돌리지 않았으므로 그대로 쓸 수 있다).
3. `4f76395`를 revert하고 `enrich-word`를 재배포한다.
4. 🔴 **3인자 `grant_rewarded_bonus`를 지우지 말 것.** 앱 업데이트에는 시차가 있어
   구버전이 한동안 남는다. 새 1인자 함수와 나란히 두면 이번 사고가 재발하지 않는다.

### 참고

- `db push`는 미적용 마이그레이션을 **전부** 올린다. 특정 파일만 적용하려면
  `db query --file <migration>` 으로 실행하고 `migration repair --status applied <version>`
  으로 이력만 등록한다(8/14에 이 방법을 썼다).
- CLAUDE.md의 티어 표는 **목표 정책**이며 현재 서버와 다르다는 주석이 달려 있다.

## 2. 단어 언어쌍 오염 — 로컬 SQLite 마이그레이션

### 무엇이 잘못돼 있나

`features/vocab/db.ts`의 `createCuratedList`가 단어 언어를 리스트 언어가 아니라
`'en'/'ko'` 하드코딩으로 스탬프하고 있었다. **원인은 PR #43(2026-07-09 머지)에서 이미
고쳤고 신규 저장은 정상**이다. 남은 것은 그 이전에 저장된 데이터다.

클라우드 실측(2026-08-14): **8,275행 · 21개 리스트 · 사용자 11명.**

| 리스트 실제 언어 | 단어에 찍힌 값 | 행 |
|---|---|---|
| ko>en | en>ko | 6,065 |
| zh>ko | en>ko | 1,491 |
| ja>ko | en>ko | 497 |
| es>ko | en>ko | 122 |
| ko>ko | en>ko | 99 |

찍힌 값이 예외 없이 `en>ko`라 하드코딩 흔적과 정확히 일치한다.

### 고치는 법

**로컬 SQLite 마이그레이션 하나면 된다.** 조건:

```
isCurated = true 인 리스트에 속하고,
단어의 (sourceLang, targetLang) ≠ 리스트의 (sourceLanguage, targetLanguage)
→ 리스트 값으로 덮는다
```

- 로컬을 고치면 dirty로 표시되어 **push로 서버까지 맞춰진다.**
- **게스트도 고쳐진다** (서버 UPDATE는 게스트에 닿지 않는다).
- `cloud_words.updated_at`을 인위로 올리지 않으므로 **운영 지표가 왜곡되지 않는다**
  (`docs/ops-analytics-queries.md` Q1이 그 컬럼으로 "오늘 활동한 사람"을 판정한다).

### 건드리지 말 것

사용자가 직접 만든 리스트(`isCurated = false`) 284행에도 일본어·한자가 들어 있지만,
리스트 자체가 `en>ko`라 무엇이 맞는지 기계적으로 알 수 없다. 사용자가 리스트 언어를
잘못 고른 것일 수도 있다.

### 기대 효과는 크지 않다 (2026-08-14 실측으로 확인)

처음에는 "AI 보강이 올바른 언어로 동작한다"를 근거로 들었으나 **성립하지 않는다.**
대상 8,275행이 **전부 이미 뜻·예문·발음을 갖고 있다**(큐레이션 덱 원본). AI 보강을
부를 일이 없고, 예문 자동 보강도 `!w.exampleEn`일 때만 작동해 타지 않는다. 해당 11명
중 AI를 쓴 사람은 1명뿐이다.

실제로 남는 효과는 이것뿐이다:

- **단어장 카드의 언어쌍 표시가 맞아진다** — `deriveDisplayLanguages`가 단어 최빈 언어를
  우선하므로 지금은 중국어 덱이 `EN → KO`로 보인다. 원래 신고된 증상이 이것이다.
- 단어 편집 화면, 네이버 사전 링크(지금은 영어 사전으로 간다)
- 나중에 그 단어로 AI를 부를 때

TTS는 `list.sourceLanguage`를 쓰므로 오염과 무관하게 정상이다.
