# 내 단어 검색 · 골라서 학습

## 개요

내가 저장한 단어를 찾고, 찾은 그대로 학습으로 넘어가는 화면이다. 예전에는 검색 화면과
맞춤학습 팝업이 따로 있었고 각자 필터를 가졌다 — 검색으로 단어를 걸러놔도 학습으로 갈
길이 없는 막다른 길이었다. 지금은 화면 하나를 **진입점 둘이 서로 다른 자세로** 연다.

| 진입 | 여는 곳 | 자세 |
|------|---------|------|
| A (검색) | 단어장 탭의 `내 단어 검색` 트리거 | 입력창 자동 포커스. 질의도 필터도 없으면 목록 대신 안내와 **지난번 조건** |
| B (고르기) | 홈의 `골라서 학습` 카드 (`?mode=pick`) | 입력창 자리에 제목. 텍스트 검색 없음. 필터가 없으면 A와 같이 목록 대신 안내와 **지난번 조건** |

**목록은 질의나 필터가 있을 때만 나온다** — 두 자세가 같다(`app/search-modal.tsx`의 `browse`).
아무것도 걸리지 않은 첫 화면은 "무엇으로 좁힐까"를 묻는 자리이고, 그 자리에 지난번 조건이
놓인다. 칩·목록·학습 바는 두 자세가 완전히 같다. **홈에는 검색창이 없다** — 검색 대상이 사는
곳은 단어장 탭이고, 홈은 "무엇을 할까"를 묻는 자리다.

## 관련 파일

- `app/search-modal.tsx` — 화면(전체화면 모달, `presentation: fullScreenModal`)
- `features/study/pick/filter.ts` — 조건 → 단어 집합. 화면은 그리기만 한다
- `features/study/pick/labels.ts` — 범위 칩·지난번 조건 문구 조립
- `features/study/pick/store.ts` — 필터(비영속) + 지난번 조건(영속)
- `lib/search.ts` — 텍스트 질의 매칭과 관련도 정렬
- `components/ListDayPicker.tsx` — 범위 칩이 여는 피커

## 주요 개념

| 개념 | 설명 |
|------|------|
| 검색 범위 | `isVisible`인 단어장만. 숨긴 단어장의 단어는 검색되지 않는다 |
| 검색 대상 필드 | `term`, `meaningKr`, `definition`, `tags[]` (대소문자 무관) |
| 칩 4줄 | 상태(+별표+프리셋) · 품사 · 범위 · 태그. 품사와 태그는 있을 때만 나온다 |
| 프리셋 | `많이 틀린 50` · `최근 추가 50`. 거르는 게 아니라 **정렬 후 앞에서 50개를 끊는다** |
| 범위 칩 | 유일한 드롭다운. 단어장과 Day를 함께 고르므로 칩 하나로 접히지 않는다 |
| 필터 개수 | 기본값이 아닌 값의 수. 결과 줄이 `137개 · 필터 2개`로 알려준다 |
| 지난번 조건 | 학습을 시작한 순간의 조합 3개. 저장은 하되 **자동으로 걸지 않는다** |

## 상태 수명

| 값 | 어디까지 남나 | 왜 |
|----|--------------|-----|
| 범위·상태·품사·태그 | 앱을 켜면 초기화 | 실행 중에는 유지된다(화면을 닫았다 열어도 남는다). 앱을 껐다 켠 뒤에는 문맥이 없어 사흘 전 조건이 수수께끼가 된다 |
| 학습 모드(카드/퀴즈) | 계속 남는다 | 필터가 아니라 취향이고, 학습 바에 늘 보인다 |
| 지난번 조건 3개 | 계속 남는다 | 눌러야 적용된다. 계정이 바뀌면 지운다(단어장 id를 담으므로) |

## 동작 시나리오

### 시나리오 1: 검색해서 찾기 (진입 A)

1. 단어장 탭의 `내 단어 검색`을 탭한다 → 화면이 아래에서 올라오고 입력창에 포커스.
2. 아직 아무것도 입력하지 않았고 필터도 기본값이면 목록을 띄우지 않는다. 대신 안내
   두 줄과 **지난번 조건 3개**를 보여준다.
3. 타이핑하면 결과가 좁혀진다. 정렬은 관련도순(`lib/search.ts:getRelevanceScore` —
   완전 일치 → 앞부분 일치 → 부분 포함 → 뜻 → 태그 → 영어 정의).
4. 결과 카드를 탭하면 `add-word`가 `mode: 'read'`로 열려 단어 상세를 본다.
5. 그대로 학습으로 갈 수 있다 — 하단 학습 바에서 카드/퀴즈를 고르고 `3개 학습`.

### 시나리오 2: 조건으로 고르기 (진입 B)

1. 홈의 `골라서 학습` 카드를 탭한다.
2. 아직 아무 칩도 누르지 않았으면 목록 대신 안내와 **지난번 조건 3개**가 보인다.
   입력창이 없는 자세라 안내 문구와 아이콘이 A와 다르다(`search.pickEmpty*`).
3. 칩으로 좁힌다 — 하나라도 걸면 그때부터 목록과 개수가 나온다. 범위 칩은
   `ListDayPicker`를 열어 단어장과 Day를 고른다.
4. 학습 바에서 시작. 이때의 조합이 **지난번 조건**에 저장된다.

### 시나리오 3: 범위 고르기

칩 라벨이 고른 결과를 그대로 읽어준다. 칩이 접힌 채로 화면에 남아 목록 개수를 설명하는
유일한 자리이므로 Day까지 말한다(`features/study/pick/labels.ts:scopeLabel`).

| 고른 것 | 칩 라벨 |
|---------|---------|
| 전부(기본값) | `전체 단어장` |
| 하나, Day 전부 | `토익 900 필수` |
| 하나, Day 연속 | `토익 900 필수 · Day 3–5` |
| 하나, Day 띄엄띄엄 | `토익 900 필수 · Day 3개` |
| 여러 개 | `토익 900 외 2개` |
| 여러 개 + Day 일부 | `토익 900 외 2개 · 일부 Day` |
| 아무것도 안 고름 | `단어장 선택 안 됨` (학습 버튼 비활성) |

피커 안에서: 단어장 행을 누르면 통째로 켜지고 Day는 자동 전체 선택. Day를 하나씩 끄다
전부 끄면 그 단어장이 해제된다. `적용`을 눌러야 반영되고, ✕는 편집을 버린다. 전부 선택 +
모든 Day 전체가 되면 자동으로 "전체 단어장"으로 되돌아간다(나중에 만든 단어장도 포함되게).

### 시나리오 4: 지난번 조건 되돌리기

빈 화면에서는 3개, 목록이 있을 때는 맨 위 하나만 목록 위에 얹는다. 누르면 그 조합이
적용된다. 필터를 걸기 시작하면 사라진다 — 조건을 만들고 있는 사람에게 지난 조건은 방해다.

## 예외 / 엣지 케이스

- **결과를 자르지 않는다.** 1,240개도 그대로 학습으로 넘긴다. 세션을 끊는 일은 배치
  설정(`studyBatchSize`)이 하고, 결과 줄이 배치 크기를 알려준다. 유일한 예외가 프리셋 둘.
- **결과 0개**: 학습 버튼이 비활성 회색 + `학습할 단어 없음`. 결과 줄은 그대로 남아
  초기화 버튼을 제공한다.
- **숨긴 단어장은 검색되지 않는다.** `visibleLists`만 뒤진다.
- **선택했던 품사·태그가 사라지면** 자동으로 해제된다(범위를 좁혀 그 품사가 없어진 경우).
- **단어장이 삭제되면** 그 id는 필터에서 자동 정리되고, 그 단어장만 가리키던 지난번
  조건 줄은 표시되지 않는다 — 눌렀더니 0개가 나오는 일이 없어야 한다.
- **학습을 시작하면 이 화면은 닫힌다**(`router.replace`). 학습 화면이 결과로 갈 때 스스로
  replace하므로, 이 화면을 남기면 결과에서 뒤로 눌렀을 때 방금 외운 단어가 빠진 목록으로
  돌아오고 홈까지 두 번 눌러야 한다. 조건이 날아가는 문제는 지난번 조건이 받아낸다.
